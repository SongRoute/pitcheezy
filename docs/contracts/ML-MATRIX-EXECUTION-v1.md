# ML 매트릭스 실행 등록 v1

2026-09-24. 사용자가 전체 매트릭스의 단계별 실행과 결과 보고서를 요청했고 하위 에이전트·재귀 호출·난도별 모델 배정을 허용했다. 이전 설계 전용 상태에서 실행 단계로 전환한다. 실행 근거는 [매트릭스](../ML_EXPERIMENT_MATRIX.md), 첫 등록 config는 [EXP-P2-001](../../configs/EXP-P2-001.yaml)이다. 후속 조건부 실험도 평가하되 선행 조건이 충족되지 않은 행을 무조건 실행하지 않는다.

## 1. 입력 감사와 보존

- 독립 저장 산출물 감사는 `temporal-blend-20260921T050400Z`의 2024/2025 두 fold에서 통과했다. 이 결과는 이미 노출된 DEV 재계산이며 새로운 일반화 결과가 아니다.
- 허용된 가공 자료는 2,145,111행이며 2023/2024/2025 정규시즌만 포함한다. 현재 바이트 해시는 config에 고정했다. 물리 sidecar도 기존 identity와 해시를 확인한다.
- 원래 raw_root의 Statcast 파일은 현재 존재하지 않는다. `_dryrun`의 작은 파일은 원본과 크기/해시가 다르므로 사용하지 않는다. **이번 입력 모드는 `verified_processed_cache`**다. 원본 파일의 당시 해시는 과거 기록으로 남기며 이번에 원자료 바이트를 재검증했다고 하지 않는다.
- 준비/profile 후 정정(새 학습 결과 공개 전): 원래 raw_root는 클라우드 디렉터리로 연결된 symlink다. 후속 실제 읽기에서 2023/2024 원본 해시는 일치했으나 2025 원본은 읽기 시간초과로 검증하지 못했다. 앞선 ‘경로 부재’ 판단은 철회하며 **원자료 세 파일 전체의 현재 바이트 검증 미완료**가 정확한 제한이다. prepare의 `raw_available=true`는 파일 경로 존재 여부만 뜻한다. 동결된 입력 모드/가공·캐시 해시/실험 표본은 변경하지 않는다. 추가 확인은 별도 audit 산출물에 보존한다.
- 기존 엄격한 raw loader·원자료·가공 자료·캐시·동결 모델·runtime_src·서버/DB는 변경하지 않는다. 별도 새 loader에서 현재 가공/캐시 바이트, 허용 연도, 행 수와 정확한 투구 키 join을 검사한다. 원자료 수집/가공 자체의 재현은 미확인이다.
- 2026/최종셋의 열람·개발·튜닝은 금지한다. 새 미개봉 비2026 자료는 아직 확인되지 않았다. MX-T5의 독립 확인은 가용성이 확인될 때만 실행한다.

## 2. 첫 등록 묶음

`EXP-P2-001`은 MX-R0/R1/R2 및 MX-D1의 비교 family다. 후보별 cell/seed/hash를 분리 저장하고 결과표에서 각각 기록한다.

1. R2는 기존 2025의 MLP·Transformer, 원래 sampling·seeds 42~46을 재학습한다. 기존 checkpoint 재검증을 새 학습으로 세지 않는다.
2. D1은 같은 MLP와 원래 Fref를 사용해 eligible TRAIN 경기의 중첩 25/50/100%를 비교한다. 새 seeds 0~2이며 최대 9회 full fit이다.
3. Fref의 과거 5구는 물리 정보만 포함한다. 과거 구종/결과를 포함한 새 H5는 MX-A0에서 별도 공통 기준선을 설정한다.
4. 정규시즌 필터를 명시한다. 현재 가공 자료가 모두 R이므로 이번 legacy/regular 모집단 차이가 없다는 것을 manifest로 재확인한다.
5. normalizer는 해당 모집단의 모든 TRAIN 행, context·빈도·delivery는 eligible full TRAIN을 쓴다. D1에서 이 보조 모듈을 고정한다. 원래 설계의 ‘D100 공통 보조 자료’ 표현을 이 정확한 범위로 구체화했다.
6. TRAIN 종료 2025-04-30, early-stop 5/1~15, temperature 5/16~31, blend 6월, C6 DEV 7~9월을 유지한다. 경기/타석 경계를 확인하고 DEV 0건 선수를 교체하지 않는다.
7. TRAIN 내부의 월·선발 투구 비중으로 경기 sampling을 층화한다. 이 비중은 **과거 TRAIN 경기 전체 구성**이며 투구 전에 알 수 있는 상태 변수라고 주장하지 않는다. 모든 seed가 같은 nested manifest를 사용한다.
8. 현재 물리는 TRAIN 조건부 outcome 학습에 사용하되 pre-pitch CAL/DEV에서는 같은 TRAIN joint draw 400개로 대체한다. tier와 fallback을 기록한다. 일별 선수 성향은 현재 날짜 전체를 제외한 누적 정보이며 앞선 DEV 날짜의 관측 이력 갱신을 허용한다.

전체 eligible 자체가 `supported_pa` 및 실제 위치 관측 조건을 사용하므로 결과는 사후 적격 모집단에 한정된다. 투구 전 전체 요청 지원률과 제외 사유를 따로 보고하고 MLB 전체 강건성으로 확대 해석하지 않는다.

## 3. 평가·판정의 고정

- 기존 10-class 순서와 NLL/Brier 합 정의를 유지한다. 확률 합 검사는 atol=1e-6, rtol=0이다.
- per-seed TRAIN draw logits의 temperature를 별도 CAL에서 고른 뒤 확률을 평균하고, 3-seed 확률 평균에 6월 CAL로 고른 빈도 혼합 계수를 적용한다. raw integrated, 보정 후, 앙상블, 혼합 예측을 구분 저장한다.
- seed 방향 검사는 seed별로 독립적으로 6월에 혼합 계수를 맞춘 예측끼리 비교한다. 앙상블 계수를 각 seed에 임의 적용하지 않는다.
- 주 비교는 D50−D25, D100−D25 두 개다. 10,000회 같은 경기 resample을 사용해 투구 수로 가중한 평균 차이와 CI를 계산한다. 한쪽 null-centered bootstrap p-value에 Holm α=.05를 적용한다.
- NLL 차이 ≤−.003, paired 95% CI 상한 <0, Holm 통과, Brier 차이 95% CI 상한 ≤+.001, 3 seed 중 2개 이상 개선 방향이면 해당 C6 예측 개선으로 분류한다.
- raw archive 지표 재계산 허용 오차 1e-8, 재학습의 seed별 NLL 차이 허용폭 .001을 유지한다. 이를 넘으면 데이터·환경·모형 차이를 조사한다. 불일치를 성능 개선으로 해석하지 않는다.
- C6에서 불펜·새 선수·저표본 집단은 측정되지 않으면 미확인이다. 정책 효과는 null이며 구종 일치나 모델 내부 Q로 채우지 않는다.

## 4. 실행 예산과 진행

첫 묶음은 최대 19회 full neural fit, HPO 0회다. 먼저 준비·작은 profile을 실행하고 후보 DEV 점수 공개 전에 profile 결과와 예산을 기록한다. 초기 묶음 실행 상한은 4시간, 단일 member 2시간으로 등록한다. 예산은 정확도 문턱과 별개이며 초과 예상 시 실행안을 다시 구체화하고 기록한다. 기록 없이 seed·draw·자료량을 줄이지 않는다.

무거운 실행은 공통 파일 잠금으로 한 번에 하나다. 준비·학습·보정·적분 추론·저장 시간을 분리하며, 실패와 중단도 보존한다. 작은 CPU/MPS profile은 최종 학습 횟수에 합치지 않는다. 임의 서비스 모델 교체·서버 재시작·유료 외부 실행은 이 묶음에 포함하지 않는다.

후속은 공통 enriched H5의 구조 비교, TRAIN 선정 역할/표본량 패널의 선수 공유·긴 이력, 그 결과에 따른 조건부 F/L/결합/정책 비교로 이어간다. 각 후속 family는 후보 결과 전에 사양/예산을 고정한다. 실제 의도 자료가 필요한 E0/E1/P6 및 미개봉 확인 T5는 필요한 자료가 없으면 보고서에 `외부 자료 필요`로 남긴다.
