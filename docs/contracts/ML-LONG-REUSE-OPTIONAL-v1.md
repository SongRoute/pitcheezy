# Optional F4 long-encoding inference reuse

2026-09-24. **Isolated source-only optimization, not registered for execution.** The original registered F4 resource profiles must run against their frozen sources. This branch must not replace sources within an existing preparation or member. Adoption, if justified by the original resource gate, requires a fresh source identity, preparation and actual resource profile before DEV. No data, fitted model, actual profile, training or real inference was used to develop this change.

## Computation

The long stream depends only on the query's fixed legal 0/32/128 history and mask. It does not depend on the current candidate pitch type, generated current physical draw or context. `DualStreamNetwork.encode_long` exposes the existing long-token MLP, position codes and masked mean. `forward_with_pooled` combines that representation with the unchanged current-draw H5 encoding and context. Parameters, module names, initialization, state-dictionary format and the training computation remain unchanged. `LazyMatrixModel.logits` retains the ordinary full forward route.

Within each existing `LazyJointDelivery` pitch chunk, compute the pooled long representation once per query. The original query-major sample ordering maps flattened draw index `j` to pooled row `j // draws`, including model batches that split a query or span multiple candidate actions. Each draw still gathers the original H5/current physical override/candidate type/context and runs the original H5 path and head. No completed query, model or candidate action shares a persistent cache. The local pooled tensor is discarded when the query chunk completes. `reuse_long=False` explicitly selects the original `model.logits` reference path.

For `Q` query rows, 400 delivery draws and max capacity 128, long-token encoder work falls from `Q * 400 * 128` token rows to `Q * 128`; H5/head work remains `Q * 400`. Long-history expansion and transfer is likewise once per query instead of per draw. Accelerator pooled storage is bounded by `pitch_chunk * width`; draw-side work remains bounded by `model_batch_size`. This is a reduction in one component's repeated work, **not a measured 400-fold end-to-end speedup**. No delivery draw, feature, model member or probability term is removed.

Calibration remains the original float32 conditional-logit temperature objective followed by float64 final per-draw softmax and mean. No reuse is performed across parameter updates; training and ordinary early-stop logits use the full model forward.

## Evidence and limits

Eleven synthetic CPU tests use randomly initialized networks, including registered width 128. They cover history lengths 0/32/128, actual full 128-token histories, padded values, candidate actions on duplicate query rows, nonmonotonic query order, exact 400 draws, pitch chunks 1/3/8 and draw batches 37/256/513 (plus 257 at width 128), empty input and feature-contract rejection. The long encoder hook confirms exactly one long encoding per query. Logits, calibrated/raw integrated probabilities and fixed-temperature float32 objective probabilities agree with the reference within an absolute `1e-6` tolerance. A separate width-128 synthetic comparison across all three history lengths measured maximum absolute logit and calibrated-probability differences of 0 on this CPU runtime. The literal original forward and parameter gradients match exactly on the padded CPU fixture; parameter names remain identical.

Real fitted weights, MPS kernels, calibration optimizer output and elapsed/RSS gains are untested. Different matrix batch shapes may cause floating-point roundoff, so mathematical equivalence does not establish bitwise equality on every device. A fresh optimized attempt must check representative frozen-weight MPS logits/probabilities against the reference before using it and record actual resource cost. It must preserve the original failed/unaffordable profile and distinguish the optimized source identity. This change does not alter G or policy/P3 sources.
