## 투구 전 지표 후보 — 현행 이용 통계와 별도, 아직 미측정

`E`는 결과 열람 전에 정한 G/경기구간/정상 공식투구/지원범위 조건에 맞는 **전체 적격 투구 집합**이다. 지원 불명·정정·철회·보류의 분류 규칙과 최종 공식키 선택 규칙은 아래 결정칸에서 고정한다. 추천이 없거나 표시/시각이 누락됐다는 이유만으로 E에서 제외하지 않는다. 원자료 범위 자체가 불완전하면 `|E|=미확인`으로 두며 관측한 부분집합을 전체 분모라 하지 않는다.

| 후보·단계 | 정의 후보 | 현재 가능 여부·한계 |
|---|---|---|
| P0 `첫 수신 전 추천 기록 비율`(proxy) | E 중 입력·키 대조가 유효하고 결정 store_seq/decided가 해당 투구 최초 수신보다 이른 집합을 `B0`; `|B0|/|E|`와 대조가능률 별도 | 기존 rec_pairing 규칙 재사용 후보. 결정 기록만 입증; 파일발행·물리투구 전·팬 표시를 입증하지 않음 |
| P1 `provider 기록시각 기준 투구 전 첫 파일발행 비율` | E 중 아래 분류로 판정가능한 `M1`, first local publish가 provider startTime보다 확실히 앞선 `B1`. 키·시계/시각 의미 검증 또는 추천 부재 확인 필요 | 현행 published_at은 upload 큐 이전 로컬 시각. 현재 파일 하나만으로 과거 첫발행 이력을 복원하지 않음. 이력/정정·시계오차·provider시각 의미 검증 전 **미측정** |
| P2 `provider 기록시각 기준 투구 전 화면표시 비율` | 사전에 정의한 관측단위(예: 적격투구×동의한 활성세션) 집합 `E2`, 아래 분류로 판정가능한 `M2`, decision/pitch ID·표시/visible·clock 증거로 확실히 선행한 `B2` | 현재 emit/저장 필드 없음. E2의 활성세션 자격·분모도 정해야 함. 파일 read/seenAt·health·원격PUT 성공을 표시로 대체하지 않음. **미측정** |

P1/P2의 배타 분류안은 다음 순서다: 관측구간의 원장이 완전하고 추천 부재가 확인되면 `no_recommendation`; 나머지에서 필수 기록이 없으면 `unknown`; 기록은 있으나 키·provider시각 의미·정정·시계오차 구간 때문에 순서를 판정할 수 없으면 `ambiguous`; 확실히 앞서면 `before`, 같거나 뒤면 `late`. 누락된 추천 기록만으로 no_recommendation이라 하지 않는다. 물리적 실제 투구 시각을 검증하지 않은 provider startTime은 **provider 기록시각**으로만 부른다.
각 후보는 `전체 적격수 |E|`, `측정가능수 |M|`, `확실히 선행수 |B|`, `late/ambiguous/unknown/no_recommendation`을 함께 보고한다(P2는 E2/M2/B2). `|M|/|E|`는 coverage, `|B|/|M|`는 **측정가능 부분집합의 조건부 비율**이다. 결측을 뺀 조건부 비율만 헤드라인으로 쓰지 않는다. `|B|/|E|`는 **전체 적격 중 선행 확인 비율**이며 미확인을 실패로 확정하는 성능 추정치가 아니다. 분모0은 해당없음, 분모 미확인은 비율 미측정이다.
제안하는 M은 `before ∪ late ∪ no_recommendation`이며 B는 before다. 즉 부재가 확인된 추천도 조건부 비율의 분모에 남긴다. ambiguous/unknown을 포함한 다섯 분류의 합계는 E와 같아야 한다. 같은 공식 투구의 정정·재전송은 사전 고정한 대표키/버전으로 한 번만 세고, 해소되지 않은 충돌은 ambiguous다. 이 분류안을 실행 등록에서 채택·고정하기 전 계산하지 않는다.

## 팬 이해와 신뢰 — 채택 전 질문 후보

- **주관적 이해 도움:** “이 화면이 다음 공을 이해하는 데 도움이 되었나요?” 선택 예: `도움이 됨 / 일부 도움이 됨 / 도움이 안 됨 / 판단 어려움`. 이는 이해 시험의 전후 향상 점수가 아니다.
- **추천에 대한 신뢰:** “이 추천을 관전할 때 얼마나 믿고 참고할 수 있었나요?” 선택 예: `믿고 참고 / 일부만 참고 / 믿기 어려움 / 판단 어려움`. 이는 추천의 실제 정확도·정책효과가 아니다.
- 둘 중1문항만 택하면 측정하지 않은 다른 개념은 미측정으로 둔다. 현재 helpful/unclear/problem 응답을 이 신규 질문에 대한 답으로 소급 재해석하지 않는다. 새 질문 채택 시 문구·선택지·버전·미응답/판단어려움 분모 포함 규칙을 고정하고 현 feedback strict schema와의 변경을 계약 담당자가 검토한다. 질문 응답 분포의 분모는 유효 응답수이며 전체 팬 응답률은 여전히 별개다.

## 취득·보관·공개 절차 초안

1. Song·팀원 운영자가 telemetry/feedback 각각의 활성화 여부, 안내·선택 UI, retainDays와 접근 gate 값을 결정한다. 서버/클라이언트 동일값을 고정하며 예시30일을 확정값으로 자동 채택하지 않는다. DNT/GPC와 동의 해제를 보존한다.
2. 계정 담당자가 승인된 범위에서 D1 사본을 취득한다. 이 초안은 원격 DB 읽기 권한이 아니다. 원본 ID/쿠키/IP/개인 로그를 공개 문서나 이슈에 붙이지 않는다. 새 개인 식별자는 추가하지 않는다.
3. 원본 스냅샷을 보존한 채 기존 export→report를 사용한다. `source_sha256, coverage=unverified, aggregation=utc_day, generated_at` 포장을 유지한다. DB 취득자/시각·명령·핀·집계일·누락상태를 함께 남긴다.
4. 만료행은 집계 제외하고 cron의 실제 삭제 실행과 백업/Time Travel 범위를 따로 확인한다. 집계 결과 보관기간·접근자·포스터 공개 범위는 원자료와 별도로 결정한다. 피드백/통계 OFF 또는 동의철회는 과거행의 즉시삭제로 설명하지 않는다.
5. 사람이 초안을 읽고 수치·범위·비밀 제외를 검토한 뒤 승인된 범위에서만 공유한다. 보고서 생성 자체를 외부 발신 권한으로 보지 않는다.
