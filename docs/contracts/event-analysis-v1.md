# Event analysis result v1 (C1)

`schema_version="event-analysis-v1"`. All values are final-game win probability for the team defending at the **initial** state. `*_pp` is a signed percentage-point difference (`100 × ΔW`); positive favors that defender. The only supported horizon is `current_pa`. A replacement through `inning_end` is a separate, currently unavailable comparison.

The JSON object has stable top-level keys `schema_version`, `analysis_id`, `revision`, `status`, `reason`, `linkage`, `identity`, `scope`, `values`, `components`, `interactions`, `shares`, `evidence`, `provenance`, and `replacement`. See `examples/event-analysis-v1.json`. `linkage` contains immutable `session_id`, `pitch_id`, `recommendation_id`, `recommendation_created_at`, `recommendation_sha256`, and `event_input_revision`. Corrections create a new `(analysis_id, revision)` result; they never alter the saved pre-pitch recommendation. `identity` carries frozen `model_version`, `model_sha256`, `value_spec_version="defense-we-pa-v1"`, and `baseline_policy_id`. A number may be compared or summed only if all identity fields, `scope.horizon`, and `scope.initial_defender` agree. No RE24 conversion is permitted.

`values.reference`, `plan`, `execution`, `observed` are probabilities in [0,1] from one compatible frozen WE/value evaluator. Reference is the stated pre-pitch policy baseline at the same state. Plan is the hypothetical intended action, with subsequent policy fixed. Execution is the hypothetical delivered action, with the same subsequent policy. Observed is the post-PA state valued for the **initial defender** with the same WE. `values.total_pp = 100 × (observed-reference)` when both exist. A post-PA actual alone can be shown separately, but it is not an intent or a command estimate. The adapter must document how each action maps to the frozen model; an unsupported/off-support action yields null with a reason.

When all four values exist, the ordered telescope is `strategy_contrast_pp = 100(plan-reference)`, `execution_contrast_pp = 100(execution-plan)`, `outcome_residual_pp = 100(observed-execution)`; these sum to `total_pp` within numeric tolerance. The third field is a descriptive **batter-associated outcome residual** and does not identify batter skill or responsibility. Interactions/order dependence have `value_pp=null`, `status="unallocated"`; a single ordering does not identify a separate interaction. `components.unallocated_residual_pp` is the unassigned remainder of the total after available contrasts. Thus missing intent leaves strategy/execution null, and their joint remainder is not given to any player. `shares.denominator_pp` is `sum(abs(assigned signed components))`, and component `abs_share` is `abs(component_pp)/denominator_pp` only for a complete, stable decomposition with denominator > `1e-6` pp. Shares are null for missing or tiny denominators; they are descriptive magnitudes, not responsibility percentages.

`status` is `complete` only when the compatible four-value model calculation is complete, even then it is not causal identification. `partial` retains measurable total and any supported contrast with explicit null reasons. `unavailable` means no compatible total can be evaluated (including unsupported model inputs). `failed` records an unexpected calculation failure with no invented numeric output. `reason` is null only for complete. Evidence records source refs, intent validation and uncertainty, mapping mode, and whether labels are synthetic/developmental. `provenance` records input timestamps and revisions. A late or corrected intent makes a new analysis revision; pre-pitch recommendation identity stays identical.

Python integration is `observer_app.event_analysis.analyze_event(linkage=..., identity=..., initial_defender=..., values=..., evidence=..., provenance=..., stored_recommendation=..., intent_estimate=..., release_frame_time=..., clip_pitch_id=...)`. Each non-null `values` entry must be created with `value_point(value, identity=..., initial_defender=..., source=...)`; mixed model hash, horizon, or defender is rejected. `recommendation_sha256(stored_recommendation)` and its ID must match `linkage`. The production reference source is the **saved same-pitch recommendation** `baseline_value`, not raw pre-state WE. The frozen observed adapter `frozen_observed_value(engine=..., initial_state=..., post_state=..., identity=...)` checks the loaded bundle manifest hash and calls its `engine.we.predict_defense` on the recorded post-PA state. Missing or ambiguous post state, including a game end without a valid terminal state, leaves observed value unavailable. `failed_event(...)` records a calculation error with null values.

A non-null plan also requires `evidence.plan_action={pitch_type,zone_id,source}` with the linked intent zone and a `source` of `pre_release_signal` or `synthetic_fixture`. A non-null execution requires `evidence.execution_action={pitch_type,zone_id,source:"recorded_delivery"}`. Recorded location or type cannot be silently used as the intended action. If only location proxy is known and planned pitch type is unknown, keep plan/execution null. The actual delivery remains evidence, never proof of the plan. Production analysis additionally requires `stored_recommendation` and checks that the reference value equals its saved baseline.

Intent consumption requires the existing `validate_intent_estimate`, exact `pitch_id`, clip-to-pitch evidence, and `evidence.frame_time < release_frame_time` in the same clip clock. `received_at`/`generated_at` are UTC/wall times, never compared to frame seconds. An estimate stopping before `plate_feet`/`zone9` cannot give a model plan action. Even a complete setup estimate is an unreviewed proxy and does not establish true pitcher/catcher intent. Real Statcast has no intent, so ordinary HR/K cases will generally be `partial` and must not show execution or player credit.

`replacement` holds `status="unavailable"`, `horizon="inning_end"`, and missing reasons until an actual contemporaneous candidate roster, eligibility, decision time, workload/rest context, and a separate inning-end evaluator/continuation are supplied. It is not included in PA totals or shares.

The C3 request boundary is `unavailable_replacement(keep_pitcher_id=..., substitute_pitcher_ids=..., decision_at=..., roster_as_of=..., candidates=..., workload_evidence=..., inning_evaluator=...)`. Substitutes must be distinct from the kept pitcher and must exactly match a roster snapshot of eligible candidates whose timestamp does not follow the decision. Seeing a pitcher enter later is not proof they were available at decision time. Even with these inputs, the function returns `unavailable` until a separately validated `inning_end` evaluator exists; it never adds its value to this PA decomposition.

The example is synthetic and marked `development_only`; it is a schema/calculation fixture, not video evidence, performance measurement, or an actual player attribution.
