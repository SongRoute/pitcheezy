# 실시간 관전 서비스 — 필요한 정보·계획·체크포인트

2026-10-02 시작 (D134). 사용자가 프로젝트의 두 축을 **예측 모델**과 **실시간 서비스**로 정하고, 실시간 쪽을 아래 순서로 진행하라고 했다. 구현·실험은 Claude 판단으로 끝까지 진행하고, 주요 판단은 이 문서의 체크포인트에 남긴다.

1. **과거 경기 데이터를 실제 경기 시간에 맞게 실행** (데모 버전)
2. **데이터를 실시간으로 받아와 실행** (초기 버전)
3. **실제 경기 관람에 불편이 없는 처리 속도**

코드는 브랜치 `demo/live-sync`(`demo/ws-2026`에서 분기, 작업 폴더 `../pitcheezy-worktrees/live-sync`). 추천 모델은 동결 ≤2025 ARM-B 그대로이며 이 작업은 모델·정책을 바꾸지 않는다. 화면의 "검증 전 실험 버전" 표시와 D131(정책 채택 없음)은 그대로다.

## 1. 실시간 서비스에 필요한 정보

야구 비유로 말하면, 이 서비스는 중계 옆에 놓는 "두 번째 전광판"이다. 전광판이 쓸모 있으려면 ① 공이 던져지기 **전에** 추천이 떠야 하고 ② 공 결과가 내 중계 화면보다 **먼저** 뜨면 안 된다(스포일러). 그래서 필요한 정보는 대부분 "시간"에 관한 것이다.

## 2. 단계별 계획과 상태

### 1단계 — 과거 경기를 실제 시간대로 재생 (완료, `fda4436`)

- 끝난 경기의 최종 피드를 **실시간과 똑같은 경로**(피드 → 상황 해석 → 동결 모델 → 화면)에 흘려보낸다. 각 공은 기록된 시각 간격 그대로 나온다.
- 화면: 경기 목록의 "실제 속도로 다시 보기" → `/live?game=N&replay=0`. 회 버튼으로 그 회 첫 공 15초 전부터 시작, ±1·±5초 버튼으로 영상과 맞춘다. 시작 시각이 주소에 들어가서 새로 고침·다른 기기에서도 같은 시계를 본다.
- 확인: 849843 재생에서 공이 기록 시각대로 도착, 추천은 다음 공 전에 표시. 폰 폭 브라우저 검사 통과. 백엔드 229개·재생 스크립트 9개 검사 통과(동결 정책 50개 상황이 사전 계산과 동일한지 보는 검사 포함).
- **한 경기 전체 확인(8배속, 2026-10-02):** 849843의 262개 투구 상황을 실시간 경로로 끝까지 흘렸다. 조회 2,248회 중 오류 0, 추천 가능 246·불가 16(사전 계산 246/262와 같음), "계산 중"으로 보인 조회 0회, 계산 시간 중앙값 0.14초·95% 0.18초, 모델 재준비 1회(5.8초, 849843:44:1). 응답 시간 중앙값 9ms·95% 204ms. 요약은 브랜치 `demo/live-sync`의 `results/checks/LIVE-replay-849843-x8.json`.
- 이후 추가(같은 브랜치): 추천이 없는 투수에도 보이는 "이 투수 오늘"(그 경기 구종 비율·평균 구속), 이닝을 끝낸 공을 교대 중에도 표시, 공이 미트에 들어오는 순간 눌러 지연을 재는 미세 조정.

### 2단계 — 실시간 수신 초기 버전 (진행 중)

- 지연 중계 경로(`/live?game=N`)는 D117에서 만들었지만 **실제 진행 중 경기로는 검증된 적이 없다.** 2026-10-02 09:00 KST 849844로 처음 검증한다(기록기 2개: 운영 8766, 새 코드 8769).
- 완료 기준: 한 경기 전체에서 서버 오류 없이 상황판이 따라가고, 추천 가능/불가가 공마다 표시되며, 끝난 뒤 보고서(§4)가 나온다.
- 경기 뒤 드러난 문제를 고치고, 다음 실제 경기(디비전시리즈, 10/4 02:00 KST부터)로 다시 확인한다.

### 3단계 — 관전에 지장 없는 속도 (진행 중)

"지장 없다"의 기준: **다음 공이 던져지기 5초 전까지 추천이 화면에 있고, 공 결과는 내 중계보다 먼저 뜨지 않는다.**

- 한 일: 시청자별 중계 지연 맞추기(사건 시각 기준), 화면 갱신 5초→2초, 새 상황의 추천을 요청 안에서 최대 1초 기다려 "계산 중" 깜빡임 제거, 두 경기 동시 준비(실시간+재생이 서로 모델을 다시 준비시키지 않음).
- 남은 일: §4 측정값으로 피드 조회 간격 결정(CP4), 재생에 실측 지연 반영, 투수 교체·주자 이동 때 모델 재준비(약 5초) 빈도 확인, 운영 인스턴스(8766) 교체.

### 그다음 (1~3단계 뒤, 순서는 측정 결과를 보고 정함)

- 추천이 없는 투수의 화면 채우기(그 경기에서 지금까지 던진 구종 비율·구속 같은 사실 정보).
- 경기 단위 "추천과 실제" 요약, 팬이 다음 공을 맞혀 보는 놀이.
- 예측 축과 연결: 다음 공의 볼·스트라이크·인플레이 확률(현재 화면 자료에 없음, 미측정).
- 자동 시작(launchd)·T7 의존·공개 범위는 사용자 결정 뒤.
