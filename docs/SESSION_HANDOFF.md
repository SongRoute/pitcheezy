## 시작 순서 (아래는 반복 가능한 절차; 이번 첫 묶음은 3번까지 완료)

1. **A 먼저:** 공통 준비 C0의 첫 산출물을 고정한다. C0는 C 세션이 아니라 A~D 공통 준비다.
2. **A의 전체 연구 완료를 기다리지 않고 B·C·D 시작:** 최소 계약·작은 데이터 목록·평가 사양을 공유한 시점에 갈라진다.
3. **B·C·D의 첫 산출물을 D에서 통합:** 추천은 기존 모델, 의도는 개발 샘플이어도 된다. 데이터/계산 검증은 A가 담당한다.
4. **실제 CV 합류:** 계약/시점/좌표 검사를 통과한 실제 출력으로 제구·기여도 품질을 확인한다.
5. **확장:** A의 평가를 통과한 B의 개선 모델을 적용하고 C·D를 재검증한다.

## 각 세션의 첫 완료 목표

| 작업 | 첫 목표 | 먼저 받을 것 | 다음에 넘길 것 |

| B | 기존 모델로 대표 구종·목표 추천 재현, 제구 모형 교체 경계 | A의 계약·데이터·평가 사양 | 추천 어댑터·실행 명령·모델 버전·출력 예시 |
| C | 홈런·삼진 기여 계산과 근거 참조, 교체 분석 입력/범위 | A의 가치 사양·현재 고정 모델 | 분석 결과 형식을 먼저 제공, 이후 계산 모듈·검증 결과 |
| D | 추천→실제 비교→사건 카드의 관전 흐름 | 기존 API, A의 계약, C의 결과 형식 | 통합 실행 경로·화면 검증·남은 실제 입력 의존성 |

A는 공통 계약 **문서와 평가 사양**을 관리한다. B는 모형 어댑터, C는 사건 분석, D는 서비스/API·웹을 구현한다. 공통 타입·DB 스키마의 실제 반영은 D에서 통합하고 규격 변경은 A와 동기화한다. C의 결과 형식은 계산 구현보다 먼저 넘겨 D의 대기를 줄인다.

A의 가치 사양은 현 서비스 WE를 유지하는 실행 계획의 작업안을 기준으로 확정·기록한다. RE24 동결 연구는 별도이며 가치 단위·관점·평가 범위를 섞지 않는다. 네 작업이 각자 새 가치 모형을 만들지 않는다.

## 기다리지 않고 진행할 수 있는 일

- A의 계약이 작성 중이면 B는 기존 추천 재현과 변경 지점을 조사하고, C는 사건 분해 기준을 정리하며, D는 기존 화면/API의 세 단계 흐름을 점검할 수 있다. 미확정 규격의 별도 구현은 피한다.
- C는 B의 새 학습 완료를 기다리지 않고 기존 모델로 계산한다.
- D는 C의 분석 완료를 기다리지 않고 합의한 결과 형식의 샘플로 화면을 만든다.
- CV 실제 표본이 없을 때 B4/C4의 실데이터 검증만 대기한다. 일반 추천 개선·평가·사건 로직·UI는 계속 진행한다.
- 한 작업이 막히면 필요한 입력과 이유를 남기고 독립적인 남은 일을 진행한다. 다른 작업의 완료를 가정해 성능 결과를 채우지 않는다.

## 매 세션의 종료 기록

각 작업은 자기 `docs/handoffs/{A|B|C|D}.md`만 관리한다. 공통 plan/roadmap을 네 작업이 동시에 갱신하지 않는다. 종료 기록은 다음 여섯 항목으로 통일한다.

1. 기준 커밋·작업 브랜치·최종 커밋과 계약/데이터/모델 버전.
2. 실제 완료한 것과 남은 것.
3. 변경 파일·출력 경로·재현 명령.
4. 수행한 검사와 결과; 실제 자료와 개발 샘플 구분.
5. 다른 작업에 넘길 입력/출력과 받아야 할 것.
6. 실행 중인 학습/서버의 작업 ID·로그 경로·자원 사용 여부, 다음 한 가지.

첫 합류 성공은 **한 타석의 세 단계가 연결되고 입력/계산/화면 검증을 통과하는 것**이다. 연구 성능 우위·실제 기여도 품질 통과는 별도 항목으로 남긴다.
