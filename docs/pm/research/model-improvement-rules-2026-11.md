## 2. 규칙 재검토: 지킬 것과 바꿀 제안

‘바꿀 제안’은 아직 효력이 없다. 현행 등록에 사후 적용하거나 이 문서만으로 게이트를 제거하지 않는다.

| 항목 | 지킬 것 | 바꿀 제안 / 추천 | 이유·결정 전 동작 |
|---|---|---|---|
| 2026 자료 | 학습·튜닝·모델 선택 금지, 봉인/OPE 접근 경계 | **이번 3주에는 유지 추천**. 완화안은 별도 미래 연구 계약에서만 논의 | 전시 자료 노출과 평가 오염을 확대하지 않음. 현재 금지 그대로 |
| 예측 후보와 서비스 정책 | N/G/R/C 증거와 정책 P·S2→S6 재인증을 구분 | 예측 연구 후보 동결과 서비스 승격을 단계표로 명시하는 문서 개선 | 이미 매트릭스가 구분한 원칙을 유지. e2e OPE를 예측 NLL 주장에 요구하지 않되 정책 효과·서비스 교체에는 생략하지 않음. D155 재개 없음 |
| ΔNLL −0.003 | 현재·기존 등록의 문턱과 판정 | 현행 유지 추천. 새 목적이 저비용이면 사전에 C 기준을 주 기준으로 선택하는 별도 등록 가능 | 관찰한 −0.002 등을 통과시키려고 문턱을 낮추지 않음. 문턱 변경을 원하면 후보 결과 전 비용·손실 근거와 새 결정 필요 |
| 반복 DEV의 ‘확인’ 표현 | 원본 JSON의 등록 라벨 보존 | 보고서에는 ‘반복 DEV 내 N 통과’와 ‘독립 확인 미완’을 함께 표시 | seed 추가·같은 DEV bootstrap은 새로운 독립 자료가 아님 |
| CAL 재사용 | 기존 실험의 temperature→blend 순서 불변 | B3의 새 등록에서 평균 뒤 보정에 별도 시간 구간 또는 시간 교차적합을 지정 | 같은 6월로 혼합비·후보·보정기를 모두 고르는 선택 편향을 숨기지 않음. 새 CAL 분할이 바뀌면 기준선도 같은 절차로 재산출 |
| 강건성 R | 집단·최소 보고량·분모·CI·기권/fallback 확인 | P48에 빠진 R을 별도 **사후 기술 감사**로 우선 보완 | 본 결과를 소급하여 사전 지정 R 통과로 만들지 않음. 새 확인 등록에는 집단을 사전 고정 |
| 탐색 폭 | 비교군·seed·데이터·실패 보존 | 한 묶음 최대 후보 2개, 한 변경 축, 사전 fit/시간/저장 예산 | 거대한 조합 탐색보다 기존 P48 계열 재사용. 결과 보고 다음 후보를 추가하면 새 묶음·새 노출 기록 |
| GPU 사용 | 타 작업·기록기·메모리·장치 lock 보호 | 가용 A5000 최대 5장으로 seed 작업 병렬화하는 일정 | 허가는 예약이 아님. 실행 직전 `gpu st`, 실행은 `gpu run`; 기본 장치당 1fit. 가용 장치가 적으면 순연, 다른 작업 종료 금지 |
| 기존 코드·실험 | baseline·ablation·고정 source·실패 기록 보존 | 삭제/통합 정리 없음 | 결과 재현과 비교 의미를 잃지 않음 |
