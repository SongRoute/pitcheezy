# CLI MVP 후속2–4단계 최소 설계

2026-09-21. Astra 설계·코드, Sol 실행·저장. 기존 신경망과 완료 소스/번들은 동결한다. 승인된2023–2025, 기존 가상환경, T7 Shield만 사용한다. 신규 신경망 학습, 군집/윈도우 탐색, 추천 안정성은 제외한다.

## 2. 학습 경기를 분리한 정책 평가

원 정책의 TRAIN은2025-04-30까지, 온도·혼합 보정은5–6월이다. 별도 평가기의 결과 확률, WE, 주자 진루는 **2025-07-01~07-31의 경기만** 사용해 적합한다. 결과 평가기는 July 빈도 계층: 카운트·좌우→구종→주자아웃→고정 contact/ISO 유형→투수, 고정 축소강도50/100. 기존 모델의 학습된 확률·가치·빈도표를 가져오지 않는다. 타자 성향은 당시 이전 날짜의 누적 통계이며 그 원천은 과거 기간과 공유된다. 평가기는 신경망과 다른 단순한 근사이며 인과적 평가가 아니다.

- **8월1–7일:** 약점 진단. **8월8–15일:** 개선안 채택 판단. **8월16일–9월30일:** 최종 정책 비교. 경기 집합의 비중첩을 검사한다.
- 기존 실험에서 관측한 기간을 재사용하는 탐색적 검증이다. 완전히 미관측인 확증 데이터라고 주장하지 않는다.
- 비교 정책: TRAIN 구종 빈도, WE 첫 구 개입 후 빈도 복귀, WE 전체 타석, RE 전체 타석. 원 정책이 선택한 행동을 별도 평가기로 채점하며 평가기로 행동을 다시 선택하지 않는다.
- 지원된 선정 투수의 적격0–0 첫 구 중 경기·투수당 시간순 처음5타석. 주자/점수 결과를 보고 사례를 선택하지 않는다. 기존 사후 적격 타석 필터에 따른 제한은 남는다.
- 주요 비교는 WE 전체 타석−빈도 및 WE 전체 타석−첫 구. 경기bootstrap2,000회, 두 비교에 대한 Bonferroni97.5%구간을 제공한다. RE 비교와 개선안 차이는 보조적95%구간이다. 동일 경기의 타석들을 함께 재표집한다.
- 별도 결과 평가기의 로그손실을 July 카운트 기준선과, WE Brier를 July 상수 기준과 진단/검증 구간에서 비교한다. 주자 진루의 실제 다음 상태 확률0 비율·진루 득점 오차도 공개한다. 결과 평가기의 모든 전이가 신뢰 가능하다고 간주하지 않는다.

## 3. 시점별 정보 갱신

새 immutable sidecar를 만든다. 입력 날짜 이전의 모든 승인 기록으로 타자 성향과 신뢰도를 갱신한다. 같은 날짜의 정보는 제외한다. 투수는 기존6명만, 행동은 기존 모델의 구종과 최근90일20구 이상 구종의 교집합만 허용한다. 지원 행동이 없으면 추천하지 않는다. 타자 부족 표본과 기본 프로필은 명시한다. 날짜·번들 해시·참조 데이터·코드 해시를 저장한다. CLI로 실제 사례 및 잘못된 날짜·미지원 투수를 확인한다.

## 4. 확인된 약점 한 가지만 개선

진단 기간의 원 정책 예측에서 클래스별 평균 확률과 실제 비율의 최대 차이가1%p 이상이고100구 이상이면 **L2강도0.05의 클래스별 절편 보정 한 개**를 시험한다. 원본 로그확률에10개 절편을 더하며 주자·아웃·타자 등 입력을 제거하지 않는다. 진단 기간으로만 적합하고, 8월8–15일에 로그손실이 감소하며 Brier가 증가하지 않을 때만 채택한다. 조건을 만족하지 않으면 원본을 유지하고 실패 결과도 보존한다. 다른 설정을 탐색하지 않는다. 다음 정책 비교에서는 원본과 채택 모델을 같은 평가기로 확인한다.

이 보정은 관측 예측 오차를 줄이는 작은 후보일 뿐 반사실 구종의 보정이나 승률 개선을 보장하지 않는다. 진루 평가에서 미지원 전이가 많이 발견되면 이를 다음 병목으로 기록하며, 본 회차의 정책 점수 해석을 제한한다. 부정적 결과를 이유로 평가 기간·표본·분할을 다시 선택하지 않는다.
