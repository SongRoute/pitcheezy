# 넓은 자료를 유지하는 대상 선수 적응 비교안

상태: **설계 후보, 최적 가중치나 성능 우위 미확정**. 새로운 모델 이름을 늘리기보다 기존 동결 구조·동일 사건 정의에서 자료 가중치의 효과를 먼저 분리한다. 과거 특정 물리 커널이 개선하지 못한 결과는 보존한다.

## 첫 유한 비교

공통 적격 자료 풀은 품질·시점 규칙을 통과한 모든 투구이며 대상 선수의 과거 다른 팀 기록과 상대 선수 기록도 포함한다. 대상4팀 기록만 남기는 학습을 주안으로 삼지 않는다.

| arm | FIT 가중치 차이 | 분리하는 질문 |
|---|---|---|
| A | 넓은 풀의 기본 가중치 | 현재까지 유용한 전체 자료를 쓰는 공통 기준 |
| B | A + 사전 고정 대상 선수 강조 | 대상 선수에 학습량을 더 쓰는 효과 |
| C | B + 비대상 유사 자료 강조 | 대상 강조 이후 유사 자료의 추가 효과 |

같은 전체 FIT 행·동결 이력·입력·구조·예산·시드·FIT/SELECT/CAL/TEST·보정 절차를 쓴다. 행 복제로 가중치를 대신하지 않는다. B의 대상조건은 투수/타자 중 무엇인지와 양쪽 중복 처리까지 등록한다. C의 유사도는 구종·손잡이·역사적 구질과 타자 표현을 사용하되 현재 실현 투구 특징은 금지한다. outcome 기반 표현을 학습하면 FIT 내부에서도 순방향 시간 fold의 교차적합을 사용해 자기 라벨 누출을 막고, 학습 query마다 strictly prior/당시가용 donor결과만 허용한다. 무작위 교차적합만으로 미래행 누출이 해결됐다고 보지 않는다. SELECT/CAL/TEST는 표현학습에 쓰지 않는다. 그 구현 부담이 크면 첫 C는 과거 구질의 고정 거리만 비교하며 학습 유사도는 별도 후속안으로 둔다.

가중치 후보식은 `wA=1`, `wB=1+alpha*target`, `wC=1+alpha*target+beta*(1-target)*similarity`다. alpha/beta·거리 척도·similarity범위·결측/기권 규칙은 아직 미고정이다. 같은 alpha로 B/C를 묶어 유사도 효과를 분리한다. 가중치의 상한, 상대 최대/최소 비율, 선수·구종별 질량 집중 한도와 `ESS=(Σw)^2/Σw²` 최소 수준을 점수 전에 고정한다. 최종 평균1정규화 후에도 상한이 보장되는 결정적 투영/정규화 절차를 검증한다. clipping 전후/최종 가중치와 ESS를 기록하며 무제한 가중 탐색을 하지 않는다.

첫 실행안은 **한 사전 대표 temporal fold·한 고정 seed·A/B/C 각1개 패키지**다. 여러 head를 쓰면 패키지 수가 아닌 실제 classifier/CAL fit 횟수를 별도로 계산해 상한에 넣는다. 첫 단계에서 실제비용·결측·가중치 집중·누출/재현을 확인한 다음, 등록된 확장 조건을 만족할 때만 추가fold/seed 및 전체 자료로 확대한다. 이 문서는 fit 수치·시간/GPU를 승인한 실행 등록부가 아니다.

## 비교 지표와 다음 방법

전체 비가중과 사전 대상 cohort 내부 비가중 사건별 NLL/Brier, 보정 고정구간·지지, 최악 지원 선수/구종, 확률 포함 관계·합, 후보 제공률/기권, 시간/메모리를 함께 기록한다. 전체 투구가중 평균과 선수동일가중 평균을 구분하고 별도 가중 평가를 한다면 다른 추정대상임을 명시하고 가중치를 결과 전에 고정한다. SELECT 선택목적은 모든 arm에 동일하게 고정하며, CAL cohort/규칙도 동일하고 평가 라벨을 재사용하지 않는다. target/non-target의 최종 질량도 함께 기록한다. 게임 단위 paired 차이·구간과 모든 실패를 남긴다. 작은 차이·개발표본 개선을 정책 우위로 해석하지 않는다.

계층/멀티태스크 방식은 **공통 모델 + 선수/구종/타자 상호작용의 축소된 보정**을 공유해 희소 선수를 넓은 자료에 묶는 후속 후보가 될 수 있다. 처음부터 팀별 독립 모델·대형 새 백본·표현학습·가중치를 한꺼번에 바꾸지 않는다. 첫 A/B/C가 자료집중 효과를 분리한 뒤 필요성과 예산으로 한 축씩 추가한다. C가 불리하면 유사도 가정을 바꾸기 전에 A/B 유지와 지원 부족 구간을 확인한다.

모델 선택 기준은 사전 SELECT 점수·품질/보정/가용성 기준으로 정하고 TEST/LCS/WS 성적을 보고 역으로 가중치를 고르지 않는다. 실서비스 추천에는 별도 상태 전이·가치 계약이 필요하며 사건확률 성능 개선만으로 최적 구종을 주장하지 않는다.
