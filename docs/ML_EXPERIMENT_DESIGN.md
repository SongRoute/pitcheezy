# MLB 구종·목표 위치 확률 정책을 위한 전체 실험 설계

작성: 2026-09-24. 이 문서는 **실행 전 작성한 설계안**이며 현재 실행 상태는 [실행 보고서](reports/ML-matrix-execution-2026-09-24.md)를 따른다. 사용자는 먼저 전체 실험을 설계하고, 첫 검증 범위를 **MLB 정규시즌 선발·불펜 전체**로 정했다(D53). 이 문서는 실험 축·대조군·평가·진행 조건을 정의한다. 수치 예산·표본 목록은 ML0 감사 후 후보 결과를 보기 전에 고정한다.

목표와 우선순위의 출처는 [로드맵](roadmap.md), 첫 실행 절차는 [ML 인수인계](handoffs/ML-experiments-next-session.md), 기존 15편의 원문 검토는 [문헌 검토](reports/ML-literature-review-2026-09-24.md)다. 본 설계는 ML0→ML5를 구체화하고 그 뒤의 정책 실험을 추가한다. 기존 서비스·동결 연구의 사양을 소급 변경하지 않는다.

후속 구체화: [실험 매트릭스](ML_EXPERIMENT_MATRIX.md)에 각 비교의 대조군·변경/고정 조건·평가·판정 수치 초안·진행 조건과 첫 실행 묶음을 정리했다. 매트릭스 ID는 계획 식별자이며 실행 기록은 아니다. 전체 설계의 개념/범위는 이 문서, 행별 비교 규칙은 매트릭스를 함께 따른다.

## 1. 무엇을 만드는가

투구 직전 상황 `s`가 들어오면 **구종 k와 목표 위치 z의 결합 확률 정책**을 출력한다.

`π(k,z | s) = π(k | s) × π(z | k,s)`

- 구종 확률: `π(k|s) = Σ_z π(k,z|s)`.
- 구종별 위치 확률: `π(z|k,s)`. 구종 확률이 0이면 조건부 위치는 unavailable로 표시한다.
- 전체 위치 확률: `π(z|s) = Σ_k π(k,z|s)`도 계산하되, 실제 추천 조합은 결합 확률로 선택한다.
- 예: 슬라이더 선택 40%, 슬라이더 선택 시 낮은 바깥쪽 70%이면 그 **조합의 추천 비율은 28%**다. 이는 성공 확률이나 정답일 확률이 아니다.
- 지원하지 않는 구종·위치는 확률 0, 지원 행동 전체 합은 1. 지원 행동이 없으면 억지로 정규화하지 않고 unavailable과 사유를 반환한다.
- 행동별 예상 가치, 결과 분포, 지원량, 불확실성, 모델/좌표 버전은 확률 정책과 별도 필드다. 이번에는 기존 API를 변경하지 않는다.

최적화 목표는 기존 `defense-we-pa-v1`을 유지한다. 현재 타석 종료까지의 선택을 계획하고, 이후는 동결된 WE continuation으로 평가한다.

`J(π|s₀) = Eπ[W_def(g_T) − W_def(g₀)]`

`W_def`는 시작 시점 수비 팀의 최종 승리 확률이며, 이닝이 바뀌어도 같은 팀 관점을 유지한다. 표시 단위는 `100 × ΔW` %p다. γ=1에서 종료 시점 보상 또는 telescoping 가치 변화 중 하나를 사용하고 중복 합산하지 않는다. full-game 정책, 투수 교체, RE24 최적화는 별도 과제다. 근거: [연구 헌장](../experiments/pitchmdp/RESEARCH_CHARTER.md), [현재 추천 계약](contracts/B-recommendation-v1.md).

**확률 정책에도 최적화 원리가 필요하다.** 상대 반응을 고정하고 기대 가치만 최대화하면 보통 한 행동을 고르는 결정적 정책이 최적이다. 따라서 아래를 분리 비교한다.

1. 결정적 `argmax Q`: 반드시 포함할 기준선.
2. 관측 행동 정책 `b`에서 지나치게 벗어나지 않는 KL 제약/정규화 정책: 고정 Q에 대해 `maxπ Eπ[Q] − τ KL(π||b)`이면 지원 행동에서 `π(a) ∝ b(a) exp(Q(a)/τ)`. 순차 문제에서는 이에 맞는 regularized value backup을 사용한다. τ는 정책 개발 자료에서 고정한다.
3. 타자의 대응을 명시한 게임 모형의 혼합 전략: 타자의 정보·행동 공간·효용 가정을 밝히고 균형을 계산한다.

이들은 서로 다른 제약 아래의 최선이다. Q 점수의 임의 softmax를 전역적으로 최적인 확률이라고 부르지 않는다. 앙상블의 1위 투표 비율도 정책 확률이나 통계적 신뢰도로 대체하지 않는다.

## 2. 세 과제를 구분하는 공통 비교 체계

| 과제 | 입력과 출력 | 판단할 수 있는 것 |
|---|---|---|
| 행동 예측 / behavior cloning | 과거 정보 → 실제 선택 구종; 목표 라벨이 있을 때만 목표 위치 | 기존 선수의 선택을 얼마나 잘 모방하는가. 추천의 정답은 아님 |
| 결과 확률 예측 — ML 주 과제 | 과거 정보 + 후보 행동 → 다음 공 10개 결과 확률 | 확률 예측 품질. 정책 계산의 재료 |
| 추천 정책 — POL 주 과제 | 과거 정보 → 구종×목표 위치 확률 | 공통 목표·지원·평가 조건 아래 예상 수비 가치와 강건성 |

공통 결과는 `ball / strike / foul / out / single / double / triple / home_run / hbp / double_play`다. 볼넷·삼진의 마지막 공도 각각 ball/strike이고, 종료는 규칙 전이에서 처리한다. 타격 결과 4종이나 타석 결과 9종의 논문 점수를 이 10종 점수와 직접 순위 비교하지 않는다.

논문마다 세 칸을 만든다: **원문 보고값**, **원문 과제 재현 또는 생략 사유**, **우리 공통 과제로 적응한 비교값**. 데이터·입력 시점·클래스·모형을 바꾸면 adaptation으로 표기한다. 서로 다른 과제를 모두 backbone으로 억지 편입하지 않고, 해당 논문이 제안한 모듈을 끄고 켜는 절제 실험도 정식 비교로 인정한다.

현재 공의 실제 구속·회전·도달 위치는 투구 전 입력이 아니다. 물리 조건부 모델은 같은 TRAIN delivery 표본으로 적분한 **pre-pitch 점수**를 주 비교로 쓴다. 실제 물리를 넣은 점수는 별도 진단이다. 직접 pre-pitch 모델은 별도 정보 경로 실험으로 비교한다.

현재 `ObservedDeliveryKernel`은 TRAIN의 400개 joint draw를 목표 주변에 재가중하는 **관측 근사**다. `p(실제 도달 | 의도 목표, 상황)`의 인과적 실행 분포를 검증한 것이 아니다. ML 단계의 결과 예측 개선과 목표 위치 개입 효과의 입증을 분리한다.

## 3. 전체 실험 지도

아래 D/G/F/A/L/P 표기는 설계 축이며 실제 실행 ID가 아니다. 실행 때 기존 `EXP-P{phase}-{seq}` 규칙으로 등록한다. 한 실험의 주 변경 축은 하나다.

| 축 | 핵심 질문 | 공통 대조군과 후보 | 주 평가 |
|---|---|---|---|
| D: 데이터 | 양·최근성·다양성 중 무엇이 도움 되는가? | 중첩 25/50/100%; 같은 N의 최근/장기; 같은 N의 선수 구성 | 학습 곡선, 신규/저표본 선수 성능, 비용 |
| G: 선수 정보 공유 | 비슷한 선수끼리 공유하면 적은 개인 자료를 보완하는가? | 전체 공유 / 개인별 / 군집 / 계층적 부분 공유 / soft mixture | 전체 및 저표본·새 선수 NLL, 음의 전이 |
| F: 입력 정보 | 어떤 시점 이전 정보가 독립적으로 유용한가? | 기본 상황 + 선수 성향 / 짧은 이력 / 긴 이력 / 경기 내 변화 / 환경 | 블록별 추가·제거, 시간 누수, 가용성 |
| A: 구조 | 같은 정보를 어떤 구조가 가장 잘 사용하는가? | 빈도·선형·MLP·GBDT·LSTM·GRU·Melville recurrent·Transformer | NLL/Brier, 보정, 학습·추천 비용 |
| L: 학습 방식 | 보조 과제·표현 학습·강건 학습이 도움 되는가? | 단일 과제 / 계층적 결과 / multitask / 사전학습 / Group DRO | 공통 주 과제, worst-group, calibration |
| P: 정책 | 확률 예측 개선을 실제 선택 가치로 연결할 수 있는가? | behavior cloning / 한 공 greedy / 타석 계획 / KL 혼합 / offline RL | 공통 ΔWE, 지원률, OPE 가정·불확실성 |
| E: 실행·목표 위치 | 목표를 얼마나 실행할 수 있고 어디까지 추천 가능한가? | 관측 kernel / 검증된 intent→delivery; 내부 9존 / 바깥쪽 포함 | 실제 실행 분포의 정확도, 좌표 오차, 정책 민감도 |
| R: 일반화 | 어떤 선수·상황에서도 결과가 유지되는가? | 미래 시점·불펜·저표본·새 선수·결측·분포 변화 | 평균+그룹 성능, 지원률, fallback 성능 |

먼저 한 축씩 검증하고, 효과가 확인된 구성만 결합한다. 다만 상호작용을 놓치지 않도록 **데이터량×모델 구조**, **정보 공유×저표본 선수** 두 조합은 작은 2×2 비교를 사전 계획한다. 모든 데이터×피처×모델×손실의 전수 조합은 실행하지 않는다.

## 4. 데이터와 검증 범위

### 4.1 범위와 세 평가판

| 평가판 | 용도 | 원칙 |
|---|---|---|
| 기존 6명 코호트 | ML0 재현, ML1 첫 비교, 기존 연구와 연결 | TRAIN 선정 명단 그대로; DEV 0건인 선수도 성능을 보고 대체하지 않음 |
| MLB 전체 개발 benchmark | 선발·불펜, 저표본 선수, 여러 상황에 대한 개발 | ML0에서 선정 규칙·기간·역할 정의를 예약. 필요한 그룹 실험에는 사전 고정한 소규모 대표 패널을 사용하고, ML5에서 동결 후보를 전체 범위로 평가 |
| 미개봉 확인 benchmark | 후보 선택에 쓰지 않은 최종 일반화 확인 | 모든 구성·보정·지원 규칙 동결 후 한 번 확인. 없으면 없다고 명시하고 별도 확보 전에는 최종 우위 미확인 |

6명에서 좋은 결과만으로 MLB 전체의 강건성을 선언하지 않는다. MLB 전체는 평가 모집단의 목표이며, 모든 선수·행동에 처음부터 개인화 추천을 보장한다는 뜻이 아니다. 지원하지 못하는 상황도 전체 분모에 포함하고 fallback/기권을 보고한다. 포스트시즌과 KBO 등 타 리그는 이후 외부 검증으로 남긴다.

군집/부분 공유·강건 학습을 고를 때 기존 6명만으로 저표본·불펜 효과를 판단하지 않는다. 필요한 그룹이 없으면 해당 비교 **전에** 전체 개발 모집단의 대표 패널을 고정하고 모든 후보에 동일 적용한다. 이는 개발용 범위 확대이며 최종 검증이 아니다. ML5에서 실패한 뒤 수정하면 새 DEV 단계로 등록하고 별도 미개봉 확인 자료를 보존한다.

### 4.2 분할과 노출 통제

`TRAIN → 시간순 내부 튜닝/early-stop → CAL → DEV → 미개봉 FINAL`

- 경기·타석을 분할 경계에서 쪼개지 않는다. 날짜 경계에 걸린 경기는 한쪽에 배정한다. CAL은 temperature와 혼합 계수 등의 구획을 구분하며 같은 CAL을 반복 탐색에 소모하지 않는다.
- 기존 2024/2025 결과와 2025년 7월 563구 진단은 이미 노출된 DEV다. 2025 TRAIN에 이전 DEV가 포함되므로 독립된 두 최종 검증이라고 부르지 않는다.
- **2026 경기 데이터와 기존 최종셋은 개발·튜닝에 사용하지 않는다.** 이전 학습/평가 노출 이력에 따라 미개봉 여부를 판단한다. 이미 사용한 자료를 새로 무작위 분할해 미개봉이라고 부르지 않는다.
- 가능하면 개발 가능한 과거 기간에서 3개 시간 anchor로 forward evaluation을 구성한다. 정확한 날짜·독립성은 ML0 manifest 감사 후 확정하며, 자료가 없으면 가용한 수와 한계를 보고한다.
- 선수 통계, 군집, 표준화, embedding, 구종 사전, delivery, WE 및 전이 추정의 학습 출처를 각각 기록한다. TRAIN 결과를 이용한 target encoding도 시간순 out-of-fold 방식으로 자기 결과가 자기 입력에 들어가지 않게 한다.
- DEV에서 이전에 끝난 투구를 다음 공의 이력으로 사용하는 전향적 갱신은 가능하되 사전에 선언한다. 모델 가중치나 군집을 DEV 결과로 재학습하는 것과 구분한다. 현재/미래 투구와 시즌 종료 집계는 금지한다.
- 최종 정책 확인 자료는 정책 후보·보상·propensity·평가기 선택에도 사용하지 않는다. 예측과 정책 확인에 같은 holdout을 재사용하면 먼저 공개한 시점부터 미개봉 상태가 끝난다.

### 4.3 분모와 결측

기존 결과 모델은 `supported_pa` 및 실제 위치 존재 등의 적격성 조건을 가진다. 이를 그대로 재현하되 **관측 후 적격 표본 성능**과 **투구 전 실제 요청 모집단에서의 지원률**을 따로 보고한다. 결과를 본 뒤 어려운 투구를 제외해 일반 경기 성능으로 제시하지 않는다.

도루·폭투·보크·희생번트·고의볼넷·자동 볼/스트라이크·주자 진루 등 주 과제 라벨/전이 밖 사건은 종류와 빈도를 감사한다. 행동 공간·외생 사건 전이를 확장하거나 미지원 범위를 명시한다. 불리한 결과가 발생한 뒤만 제거하지 않는다. 좌표 결측은 모델별 삭제 대신 공통 적격 집합과 결측 처리 비교를 사용한다.

## 5. 데이터량과 선수 정보 공유

### D1. 학습량 — 첫 ML1

기존 NN의 2025 TRAIN은 276,821행, 전체 eligible TRAIN은 1,252,824행이다. 기존 runner는 무작위 250,000행에 대상 투수 자료를 합치는 방식이므로 **기존 NN 100%와 전체 TRAIN 100%를 혼용하지 않는다**. ML0는 원래 sampling을 재현하고, ML1는 새로운 공통 sampling으로 100% 대조군도 다시 학습한다.

1. 가용 TRAIN의 고정 기간·선수 구성 안에서 경기 단위 중첩 subset을 만든다: `D25 ⊂ D50 ⊂ D100`. 월·선발/불펜 구성의 차이를 작게 유지하고 실제 투구 수·선수 수·경기 수를 기록한다. 비율은 경기 기준이므로 정확히 25%의 투구 수일 필요는 없다.
2. backbone은 기존 MLP, 입력·optimizer·보정·DEV·평가 draw는 고정한다. 각 규모에서 early-stop은 허용하되 최대 epoch와 update 예산을 기록한다. equal-epoch와 equal-compute 질문을 혼동하지 않는다.
3. 첫 비교는 **결과 모델의 학습량 효과**다. delivery·빈도 대조군·공통 as-of 특징은 고정 TRAIN 출처로 유지하고 그 사실을 명시한다.
4. 후속으로 모든 학습 보조 모듈도 해당 subset으로 제한하는 **전체 학습 자료량 효과**를 분리한다. 선수 이력 context도 별도 외부 자료라면 출처·허용량을 기록한다.
5. Transformer의 데이터 요구량은 D1 이후 같은 두 규모로 MLP와 2×2 확인한다. 데이터 확대와 backbone 변경을 한 점수 차이로 설명하지 않는다.

### D2/D3. 최근성과 다양성

- 같은 N에서 최근 기간 대 긴 기간을 비교한다. 최근 가중의 유효 표본 수를 함께 기록하고 half-life는 TRAIN 내부에서만 고른다.
- 같은 N·기간에서 기존 투수 중심 대 더 다양한 선수/역할의 자료 구성을 비교한다. 표본 수 증가와 선수 다양성 증가를 분리한다.
- 전체 eligible TRAIN 이후의 연도 확대는 승인된 가용 과거 자료를 감사해 별도 묶음으로 등록한다. 학습 곡선이 항상 단조롭다고 가정하지 않는다.

### G1~G5. 선수 유형으로 정보를 공유

현재 실행 주석: 실제 G0는 타자 성향6·신뢰도6·soft membership5와 정적 TRAIN 투수 표현을 포함한다. 아래는 일반 설계 가설이며 현재 G0를 순수 연속 성향만의 모델로 해석하지 않는다. 현재 모집단의 타자 표현 효과는 [F1 bridge](contracts/ML-BATTER-BRIDGE-v1.md)에서17개 입력을 함께 제거해 검증한다.

군집화는 새로운 독립 관측을 만드는 증강이 아니라 **다른 선수의 실제 관측을 공유**하는 방법이다. 다음을 같은 원자료·평가 집합에서 비교한다.

| 후보 | 구현 가설 | 필수 대조 |
|---|---|---|
| G0 전체 공유 | 하나의 모델 + 연속 선수 성향 | 기본 대조군 |
| G1 개인별 | 선수마다 별도 모델 | 학습 가능한 선수 수와 league fallback 포함; 많은 자료 선수만 남기지 않음 |
| G2 hard cluster | 유형별 모델 또는 공통 모델에 cluster feature | 두 방법은 별개 실험. K=1은 전체 공유, 후보 K={4,8}은 TRAIN 표본량 조건 충족 시만 |
| G3 계층적 부분 공유 | league→역할/유형→개인 효과를 shrinkage로 결합 | 개인 자료가 적을 때 전체 정보로 수축; 단순 연속 성향/ID와 비교 |
| G4 soft mixture | 여러 유형에 대한 소속 확률로 전문가 결합 | 전문가 수·파라미터 증가 효과와 군집 의미를 분리 |

투수 유형은 과거 구종 구성·구속/무브먼트·릴리스·좌우 등, 타자 유형은 과거 swing/contact/chase·존 반응 등으로 각각 구성한다. 이번 공 실제 물리는 넣지 않는다. **투수 유형과 타자 유형은 처음부터 동시에 바꾸지 않는다.** 우선순위는 전체 공유→투수 군집→계층적 공유이며 soft mixture는 개선 근거가 있을 때 진행한다.

군집기·정규화는 TRAIN만으로 적합한다. 새 선수는 사전 관측 성향으로 배정하거나 unknown/league fallback을 쓴다. 무이력 cold-start와 몇 경기 관측 후 적응을 별도 평가한다. 군집별 최소 선수·경기 수와 small-cluster fallback은 후보 결과 전 고정한다. 크기를 맞춘 무작위 군집을 제한된 placebo 대조로 넣으면 의미 있는 유형 정보와 단순 모델 분할 효과를 구분할 수 있다.

기존 타자 군집의 추가 이득은 일관되게 확인되지 않았다. 따라서 같은 실험의 무제한 반복 대신 **저표본/신규 선수에서의 부분 공유**, **투수 유형**이라는 새 가설로 비교한다. 좋은 전체 평균과 함께 특정 선수에 생기는 음의 전이도 보고한다.

## 6. 입력 특성, 이력, 모델 구조

### F: 투구 시점 이전에 실제로 알 수 있는 정보

| 블록 | 예시 | 비교 방법 |
|---|---|---|
| F0 기본 | 카운트·아웃·주자·이닝·점수 차·홈/원정·좌우·후보 구종 | 공통 최소 입력 |
| F1 선수 성향 | 과거 구종별 능력, 타자 swing/contact/chase, 추정 표본 수·불확실성 | F0+F1; ID embedding 추가 효과 별도 |
| F2 같은 타석 | 직전 구종·관측 물리·결과, 경과 공 번호 | 기존 0/5구 근거 재사용; 새로운 구조에서 필요할 때만 재확인 |
| F3 타석 간 장기 이력 | 타자 최근 32/128/400구, 투수 최근 이력, 시간 간격·상대 정보 | 처음은 32/128만 screen, 400은 이득/비용 확인 후. 타자/투수 stream 별도 절제 |
| F4 경기 내 변화 | 투구 수, 휴식일, 이전 공 대비 구속 변화, 같은 타순 회차 | 관측 workload와 잠재 피로를 구분; 이번 공 이후 측정 사용 금지 |
| F5 환경 | 포수·심판·구장·날씨·수비 정보 | 당시 가용성이 검증되는 항목만 추가; 미래 확정 명단/사후 집계 금지 |

긴 이력은 서로 다른 투수·타석·경기를 표시하고 timestamp·경과 시간을 넣는다. 없는 이력은 mask와 유효 길이로 처리하며 미래 padding을 하지 않는다. 다음 투구 예측 시 현재 결과를 넣지 않는다. Melville cell의 결과 갱신도 다음 시점부터 적용한다.

### A: 동일 정보에서 구조 비교

- 빈도/조건부 빈도 → 다항 선형 → 기존 MLP를 강한 대조군으로 유지한다.
- GBDT 계열 1종을 주 비교로 고른다. CatBoost/LightGBM 등 구현 선택·라이선스·CPU 비용은 ML0에서 정하고 결과를 본 뒤 유리한 계열만 추가하지 않는다.
- 일반 LSTM, GRU, **Melville 논문 자체 recurrent cell**, Transformer를 구분한다. Melville 모델을 LSTM 재현이라고 쓰지 않는다.
- 첫 구조 비교는 동일한 짧은 이력과 동일 원시 변수로 한다. tabular 모델에는 순서가 보존된 flatten+mask를 제공한다. 시퀀스 모델만 더 많은 과거를 보는 비교는 F3 실험으로 분류한다.
- 긴 이력에서는 MLP/GBDT 요약 통계 기준선도 두되, 요약 때문에 정보가 달라졌음을 표시한다. 순서 제거/섞기 대조는 TRAIN 안에서 사전 정의한 규칙으로 만들어 순서 자체의 기여를 검사한다.
- 같은 파라미터 수만으로 공정성을 주장하지 않는다. 정보·분할·탐색 횟수·실제 계산량·early-stop·앙상블 수를 공개하고 정확도–비용 관계를 비교한다.

### L: 논문에서 가져오는 추가 학습 가설

1. **계층적 결과 모형:** swing/contact/타구 결과 등으로 분해하되, HBP·called strike·foul·double play 등을 빠짐없이 공통 10-class 합 1로 복원한다. 단일 softmax와 비교한다. Douglas/Mott의 다른 결과 정의를 그대로 섞지 않는다.
2. **다중 과제:** 결과 NLL + 타구 방향/속도 등 관측 가능한 보조 목표. 보조 타깃은 입력이 아니며, 관측된 경우만 loss를 계산한다. 타구 자료가 있는 공만 주 과제에서 남기는 선택 편향을 피한다. Kneita식 긴 이력과 보조 loss는 각각 절제한다.
3. **선수 표현 사전학습:** 과거 이력의 contrastive/masked prediction 뒤 주 과제 fine-tuning. 같은 이력·파라미터의 무작위 초기화와 비교한다. 추가 TRAIN 자료를 사용하면 데이터 효과도 별도 대조한다.
4. **강건 학습:** ERM, 그룹 균형 sampling/weighting, 정규화를 동반한 Group DRO를 비교한다. 역할·표본량 등 그룹은 사전 정의한다. 가중 학습 후 원래 경기 분포에서 NLL·보정을 다시 평가한다.
5. **확률 품질:** 온도 보정·빈도 혼합·seed 앙상블. 이미 쓰는 5-seed 앙상블을 새 방법의 이득으로 중복 계산하지 않는다. 희귀 결과를 늘리는 sampling이나 focal loss는 원래 확률을 왜곡할 수 있어 보정 없는 기본 선택으로 두지 않는다.
6. **직접 pre-pitch vs 물리 적분:** 전자는 잠재 물리를 암묵적으로 평균내고 후자는 명시적으로 적분한다. 같은 후보·입력 시점·행동 지원을 맞춘 뒤 비교한다. 목표 라벨 없이 direct head에 실제 도달 위치를 목표로 주입하지 않는다.

이 목록을 한 번에 실행하지 않는다. ML3는 문헌 가설과 TRAIN/DEV 오차 분석에 근거해 **묶음당 최대 2축**을 등록하고, 사용한 DEV는 탐색 자료로 기록한다.

## 7. 확률 정책과 강화학습

### POL0~POL4

| 단계 | 비교 | 선행 조건과 해석 |
|---|---|---|
| POL0 사양 | 행동 사전·지원·보상·전이·확률 출력 정의 | ML0부터 문서화 가능. 물리적 가능성과 관측 support를 구분 |
| POL1 계획 기준선 | 관측 선택 모방, 한 공 greedy, 타석 단위 계획, KL 제약 확률 정책 | 같은 결과 모델·delivery·WE·상태·action grid에서 정책 규칙만 비교 |
| POL2 offline RL | 이산 행동 IQL, CQL | 관측 행동과 보상이 있는 trajectory. 먼저 구종만의 축소 과제에서 경로 검증 |
| POL3 확장 | 상대 반응을 넣은 혼합 전략; 필요하면 MOPO식 불확실성 패널티 | 기본 모델·OPE·지원 감사 통과 후 최대 2후보. 상대 모형에 따른 민감도 공개 |
| POL4 확인 | 동결 정책의 별도 평가·이후 전향적 검증 | 예측 우위·시뮬레이터 우위·관측 OPE·실제 적용 효과를 구분해 기록 |

SmartPitch의 MDP나 타석 내 동적 계획만으로도 강한 정책 기준선을 만들 수 있다. MDP를 사용한다는 이유만으로 이미 RL을 학습한 것은 아니다. 복잡한 sequence state에서 정확한 DP가 불가능하면 근사 탐색/rollout의 깊이·오차·계산비를 공개한다. 타석 길이 상한을 두면 잘린 질량과 continuation 민감도를 보고한다.

분기마다 카운트·주자·아웃·이력·모델 hidden state를 생성 결과로 갱신한다. 반사실 첫 공을 바꾼 뒤 실제 경기의 후속 공을 그대로 붙이지 않는다. 같은 PA 시작점과 공통 난수를 이용해 후보 간 Monte Carlo 비교 분산을 줄인다.

**offline RL 자료:** `(s_t, a_t, r_t, s_{t+1}, done)`의 게임/타석 경계를 보존한다. IQL은 관측 행동 중심 가치 학습과 advantage-weighted 정책 추출, CQL은 미관측 행동의 과대 가치 억제를 비교한다. 기존 연속 행동 구현을 복사하면 이산 구종/존 정책과 맞지 않을 수 있어 adaptation을 기록한다. 알고리즘 이름만으로 안전한 개선을 보장하지 않는다. [IQL](https://arxiv.org/abs/2110.06169), [CQL](https://proceedings.neurips.cc/paper/2020/hash/0d2b2061826a5df3221116a5085a6052-Abstract.html).

실제 목표 위치 라벨이 없으면 **구종×목표 위치의 행동 로그도 없다**. 실제 도달 위치를 목표 행동으로 바꿔 RL/OPE를 수행하지 않는다. 첫 구종-only 과제는 그 구종 아래의 관측 위치/실행 혼합을 유지하는 축소 과제다. 잠재 목표·배터리 판단 등에 의한 교란이 남으므로 이것도 조건부 관측 근거로 해석한다. joint policy의 확인은 검토된 intent 자료와 측정 오차 모형을 갖춘 뒤 진행한다.

모델이 생성한 trajectory에서 RL을 학습하는 실험은 가능하지만, 같은 모델에서 얻은 높은 보상을 현실 개선 증거로 쓰지 않는다. MOPO식 불확실성 패널티와 서로 다른 평가 모델을 쓰는 민감도 검사는 보조 근거다. PPO 등 온라인 알고리즘은 추후 시뮬레이션 sanity check 후보이며 첫 실제 로그 실험의 우선순위가 아니다. [MOPO](https://proceedings.neurips.cc/paper/2020/hash/a322852ce0df73e204b7e67cbbef0d0a-Abstract.html).

### 위치와 실행 분포의 별도 축

현재 3×3은 **스트라이크 존 내부 9구역**이다. 낮게 떨어지는 유인구·바깥으로 빼는 공을 고려하려면 정책 행동 공간 확장이 필요하다. baseline 9존은 보존하고, 다음 묶음에서 내부 3×3을 포함한 5×5와 같이 바깥 영역을 갖는 공통 grid를 제안한다. 물리적 범위·정규화·희귀 행동 지원은 TRAIN만으로 정한다. grid 변경을 모델 변경과 동시에 하지 않는다.

새 grid는 별도 행동/좌표 버전을 부여한다. 기존 `zone9` 계약에 25개 위치를 조용히 넣거나 기존 관측 기록의 좌표 의미를 바꾸지 않는다.

연속 위치 분포는 후속 후보이며 공통 셀로 적분해 이산 정책과 비교한다. 좌표 단위가 다른 density NLL을 직접 비교하지 않는다. 좌우 좌표는 기존 catcher-view 계약을 유지하고 타자 기준 mirror 표현은 역변환을 명시한다.

검토된 의도 자료가 생기면 목표→도달의 편향·분산·다봉성·선수별 수축·상황 의존을 비교한다. CV의 포수 세팅은 의도의 관측 proxy이므로 검토·좌표 오차와 실제 제구 변동을 분리한다. 개발용 가상 라벨을 실제 평가에 넣지 않는다. 이 축은 [의도 계약](intent-spec.md)을 소비하며 팀원의 CV 알고리즘 개발을 대신하지 않는다.

## 8. 강건성·통계·선정 기준

### 예측 평가

- 주 지표: 투구별 10-class NLL. multiclass Brier는 **클래스별 제곱 오차 합**, 범위 [0,2]로 통일한다. 보정 전/후·단일 seed/앙상블을 나눠 기록한다.
- 보조: accuracy, macro-F1, 클래스별 precision/recall, classwise calibration/reliability, ECE. ECE bin 정의를 고정하고 NLL/Brier의 대체 주 지표로 쓰지 않는다. 해당 클래스가 없으면 undefined를 0으로 채우지 않는다.
- 주 전체 평균과 함께 선수별 macro 평균, 역할별·시점별 성능을 보고한다. 홈런·HBP·병살 같은 드문 고가치 사건의 확률 오차를 따로 본다.
- 동일 경기/투구에서 짝지은 경기 bootstrap 95% CI를 계산하고, 여러 후보의 선정 비교는 Holm 보정이나 사전 분리된 확인 자료로 다중 비교를 통제한다. 선수 단위 의존성에 대한 민감도도 보고한다.
- 고정 예측 bootstrap은 학습·보정·모델 선택의 불확실성 전체를 포괄하지 않는다. seed별 결과와 시간 anchor별 변동을 함께 제시한다.

| 일반화 축 | 확인할 실패 |
|---|---|
| 선발/불펜·좌우·구종 | 다수 집단 개선에 가려진 특정 역할 악화 |
| 표본량 | 고표본 선수에서만 이득; 신인/저표본 모델 붕괴 |
| 새 선수/새 대진 | 본 선수끼리 처음 만난 대진, 완전히 못 본 투수, 못 본 타자를 구분 |
| 상황 | 카운트·주자·아웃·접전·긴 타석에서의 오보정 |
| 시점 | 다음 기간·레퍼토리 변화·경기 내 workload 변화에서 악화 |
| 입력 품질 | 이력 부족, 물리 센서 결측/잡음, 환경 정보 없음에 대한 민감도 |
| 지원·실행 | 평균이 좋아져도 지원 가능한 행동/상황이 줄어드는 현상 |

새 선수 검증은 해당 선수의 학습·튜닝·CAL 라벨을 모두 제외한다. 무이력 zero-shot과 사전 관측 자료를 허용한 few-shot을 구분한다. 노이즈·결측 실험의 패턴/강도는 TRAIN 관측 또는 명시한 시나리오에서 정하며 실제 현장 분포를 검증했다고 부르지 않는다. 모든 그룹의 교차 조합을 무제한 검사하지 않고 주요 그룹을 사전 등록한다.

**선정 규칙 초안:** NLL 실용 개선폭 0.003 nats/구, Brier 악화 허용 상한 0.001을 출발 후보로 제안한다. NLL 차이(후보−기준)의 점추정이 `≤−δ`이고 짝지은 95% CI 상한이 0 미만이며, 사전 등록한 다중 비교 검정과 guardrail을 통과해야 개선으로 분류한다. 이 숫자는 아직 확정/검증된 제품 기준이 아니다. ML0에서 기존 기준선 변동·가능한 표본·비용을 확인해 δ, Brier 판정에 사용할 CI, 모든 guardrail 수치를 후보 결과 열람 전에 고정한다. 결과가 나온 뒤 문턱을 낮추지 않는다.

그룹별로는 최소 경기/사건 수, NLL·Brier 허용 악화폭, 지원률, 추론 지연·메모리 상한을 사전 고정한다. 작은 그룹은 넓은 구간/판정 불가로 남기고 ‘악화 검출 없음’을 통과로 바꾸지 않는다. 부족한 통계력에는 표본 확대 또는 한계 명시로 대응한다. 차이가 실용적으로 작거나 불확실하면 더 단순하고 빠른 모델을 운영 후보로 선택할 수 있지만 성능 우위라고 주장하지 않는다.

### 정책 평가

1. 공통 action set·상태 분포·WE·보상 범위에서 PA 시작당 평균 ΔWE와 그룹별 값을 비교한다. 중간 투구들을 독립된 타석처럼 중복 집계하지 않는다. 시뮬레이션 내부 개선과 실제 관측 평가 표를 나눈다.
2. 별도 자료/교차 적합으로 propensity와 value nuisance model을 학습하고 sequential doubly robust 등 OPE를 검토한다. 단일 공 IPS와 타석 전체 정책 가치는 다른 estimand다. 경기 단위 fold와 시간 순서를 보존한다. [Jiang & Li, 2016](https://proceedings.mlr.press/v48/jiang16.html).
3. OPE에는 행동 관측, 충분한 overlap, consistency, 관측 상태를 조건으로 한 교란 통제 등의 가정이 필요하다. 추정된 propensity나 DR가 숨은 intent를 복원하지 않는다. ESS·극단 가중치·잘림 전후 민감도·미지원 질량을 함께 보고하고 clipping/정책 제약은 사전 고정한다.
4. 정책을 만든 모델과 같은 모델로만 평가하지 않는다. 동결된 다른 모델/seed에서의 민감도와 가능할 때 관측 OPE를 사용한다. 같은 데이터로 만든 평가기끼리 동의하는 것도 독립적인 인과 검증은 아니다.
5. 효과 최소폭·CI·support·그룹별 손실 한도는 정책 단계 시작 전에 고정한다. WE 차이를 시즌 승수로 단순 환산하지 않는다. 식별/표본 조건이 안 되면 효과는 null/미확인이다.

기존 ESS≥20·kernel mass≥0.01 같은 지원 기준은 실행 가능성의 한 규칙이며 인과 식별이나 안전성의 증명은 아니다. 모델 불확실성이 크거나 support가 없으면 전체/유형 모델로 수축하거나 기권하는 정책도 같은 분모에서 평가한다. 정책이 특정 상황을 피해서 얻은 점수와 전체 요청에 대한 성능을 구분한다.

기존 실험의 정확 재현은 원래 seeds `{42,43,44,45,46}`를 유지한다. 새 탐색은 `{0,1,2}`, 최종 후보는 `{0,1,2,3,4}`이며 이 둘을 혼동하지 않는다. 첫 screen은 모델별 대표 설정 1개, 후속은 유망 최대 2계열에 각 최대 8설정으로 제한하는 안이다. HPO는 TRAIN 내부 시간 분할에서 하고 CAL/DEV의 역할을 유지한다. 실제 총 accelerator 예산은 ML0 profile 뒤 결과 전에 기록한다.

M4 24 GiB 로컬에서 작은 profile부터 시작하고 무거운 실행은 전체 작업에서 한 건씩 수행한다. 전처리·피처 생성·보정·물리 적분·정책 탐색까지 시간/메모리를 재며 순수 fit 시간만 비용이라고 쓰지 않는다. 예상 단일 실행 2시간 초과 또는 메모리/연산 제약이 확인되면 외부 실행 비용안을 별도로 만든다. 대형 LLM·무제한 탐색·전체 조합 실행을 기본값으로 두지 않는다.

사전 계획한 두 연속 묶음에서 실용적 개선 근거가 없으면 현재 최선과 한계를 정리하고 추가 가설의 정보 가치에 따라 다음 축/확대 여부를 판단한다. 실패·중단·OOM·seed 누락도 기록하며 좋은 실행만 보고하지 않는다.

## 11. ML0에서 고정할 미결 항목과 첫 실행 완료 조건

전체 설계에 필요한 선택과 실제 자료를 감사해야 정할 수 있는 숫자를 구분한다. 다음은 사용자에게 반복 승인받을 목록이 아니라 **실행 전 측정·기록할 항목**이다.

1. 승인된 가용 과거 기간, 학습/노출 manifest, 미개봉 확인 자료의 존재 여부.
2. D100 모집단과 nested game 목록, 기존 sampling과의 차이, CAL/DEV 날짜·MLB 전체 평가 선정 규칙.
3. 이벤트/결측/제외 분모, 구종 사전, 신규 선수·불펜·적은 표본의 정의, as-of feature 명세.
4. NLL 실용 개선폭과 Brier/그룹/지원/비용 guardrail, 검정·bootstrap·다중 비교 방법, 표본 부족 판정 규칙.
5. 모델별 대표 config, 총 탐색 예산, 내부 튜닝 경계, seed, 전처리/보정/적분의 공통 출처.
6. 실행 commit과 config hash를 후보 결과 전에 고정. 코드·원문/라이선스 차이와 재현 생략 사유도 남김.

첫 실행의 완료 범위는 **ML0 재현·사전 등록 + ML1 MLP 데이터량 첫 비교**다. 결과가 유의하지 않아도 고정한 비교를 마치고 기록하면 이 묶음은 완료다. 이 시점에 MLB 전체의 최적 정책이나 RL 성공을 요구하지 않는다.

각 실험 번들은 `가설 → 한 축의 변경 → 비교군 → 표본/시점/seed → 예측·정책 지표 → 그룹·지원·비용 → 판정 → 다음 조건`을 포함한다. config, 코드 commit, 데이터 manifest hash, 모델/보정 hash, 투구별 예측, 정책 확률/지원, 실패 로그를 연결한다. `docs/experiments.md`와 기존 결과 저장 규칙을 재사용한다.

이번 문서 작성에서는 학습·ML0 profile·ML1 비교를 실행하지 않았고, 실제 의도 자료 확보나 추천 효과를 확인하지 않았다. 원자료·동결 모델·runtime_src·서버·사용자 기록은 변경하지 않았다.
