상태: 사용자가 승인한 계획에 따라 로컬 첫 MVP 구현·검증 완료. 아래 시간표는 착수 전 예상이며 실제로는 일정을 앞당겼다. [구현·검증 결과](../apps/observer/RESULTS.md)와 [체크포인트](../apps/observer/CHECKPOINTS.md)를 따른다.

- 동작 순서: **다음 구종·위치 추천 → 실제 도달 위치 비교 → 타석 종료 후 선택한 투구만 의도/실행/결과 해석**.
- 마감: **2026-09-22 06:00 KST**. 계획 시각은21시대이며 남은 약8시간반을 기준으로 한다.
- 로컬 브라우저 동작이면 충분하다. 외부 배포·공개·유료 서비스 구매는 이번 범위가 아니다.
- 준비된 영상은 없다. CV 호출 계약·작업 처리·대체 입력·사후 해석까지 구현하고, 실영상 검출·정확도 검증은 완료했다고 표시하지 않는다.
- 별도 개발 환경의 프런트엔드/API/CV 패키지 설치를 허용했다. 기존 `.venv`, 완료 실험 소스, 모델 번들·해시를 보존한다.
- 승인된2023–2025 데이터와 T7 Shield 아티팩트를 사용한다.2026 신규 수집·모델 재학습 범위는 확대하지 않는다.
- 개발 중 추가 질문 대신 체크포인트를 기록하고, 의존하지 않는 일을 계속한다. 확정되지 않은 외부 권한이나 비용 승인을 가정하지 않는다.

## 06시의 완료 기준

1. 한 명령으로 로컬 앱을 실행하고 브라우저에서 경기·타석을 고를 수 있다.
2. 실제 과거 투구를 순서대로 재생하며, 결과 공개 전에 구종·목표 구역 추천을 저장한다.
3. 추천 목표와 실제 도달 위치를 같은 존 그림에서 구분해 보여준다. 카운트·주자·아웃·점수가 갱신된다.
4. 타석 종료 후 분석할 투구를 기본1개 고르고, 비동기 작업 상태를 표시한다. 영상이 없으면 그 사실을 표시한다.
5. 목표 구역을 수동 입력하면 입력 출처를 명시하고 선택·실행·결과의 비교 설명을 생성한다. 의도가 없을 때는 관측 가능한 부분만 설명한다.
6. 재실행 후 기록·작업 상태가 유지된다. 미지원 선수·구종, 잘못된 입력, 자료/모델 부재를 정상 처리한다.
7. 의미 있는 계약/통합 테스트와 실제 브라우저 흐름을 확인한다. 실행 방법, 테스트 결과, 한계·체크포인트를 남긴다.

성공 기준에 논문 수준 정책 개선, 실시간 MLB 연결, 실제 영상 인식 정확도, 정밀 제구 분포 추정을 넣지 않는다. 이들은 이후 개선 대상이다. 대신 모든 계산/출처의 상태를 정직하게 보여준다.

## 선택적 CV 규칙

- 기본은 타석 마지막 공1개. 고정한 중요도 규칙을 구현할 수 있으면 더 중요한 공으로 **대체**한다. 추가 구수를 자동 누적하지 않는다.
- 키는 `pitch_id + cv_version`; 여러 관전자·재생·재시도에서도 같은 분석을 재사용한다.
- 작업 예산과 재시도 횟수를 제한한다. CV 상태는 `queued / running / complete / unavailable / failed`로 표현한다.
- 영상이 없으면 `unavailable:no_media`. 사용자가 목표를 넣으면 `manual` 근거로 별도 분석 버전을 만든다.
- CV가 나중에 연결돼도 투구 **전** 셋업 프레임을 근거로 사용한다. 작업 시점과 의도 추정 근거 시점을 구분한다.
- 추천과 실제 위치 화면은 CV 실패/지연과 독립적으로 동작한다.

## 아키텍처·환경

- React/TypeScript 웹, Python API, 같은 도메인 코드를 쓰는 CLI. CV/무거운 작업은 별도 워커로 분리한다.
- PostgreSQL 기반 운영 구조를 유지한다. 로컬 DB 실행이 환경 문제로 오래 막히면 저장소 인터페이스를 보존한 SQLite 대체 구현으로 통합을 계속하고 체크포인트에 차이를 기록한다.
- 새 서비스 코드/테스트/환경을 분리한다. 기존 연구 디렉터리의 동결 파일을 수정해 서비스에 맞추지 않는다. 구종 매핑·결과10/11분류·RE/WE 차이는 어댑터와 테스트로 처리한다.
- 별도 환경은 작업 전용 경로를 사용하고 버전/의존성을 기록한다. 기존 실험 가상환경을 재설치·업그레이드하지 않는다.
- 같은 경기 상태·프로필·모델·위치 가정의 추천을 재사용한다. 재생 위치는 사용자 세션에 분리한다.
- 실제 자료·모델·생성 아티팩트는 승인된 SSD에 보존하며 Git에 대용량 산출물을 넣지 않는다. 기존 사용자 변경을 유지한다.

## Astra·Sol 분담과 사용량 관리

- **Astra:** 전체 설계·공통 계약, 추천/좌표/정보시점 등 핵심 코드, 통합과 중요한 오류 판단. 단순 모듈 코딩은 낮은 추론 수준으로 제한된 작업 단위를 맡긴다.
- **Sol:** 환경 구성 실행, 테스트·브라우저 검증, 데이터/평가 실행, 로그·결과 저장, 재현 확인. 설계 변경이나 모델 선택은 Astra의 작은 검토 지점으로 되돌린다.
- 동시에 진행하는 코딩 작업은 소수로 제한하고 파일 소유권을 나눈다. 같은 환경 설치나 모델 실행을 중복하지 않는다.
- 긴 대화 전체를 하위 작업에 반복 전달하지 않는다. 입력 계약·담당 파일·완료 기준만 전달한다.
- 전체 로그 대신 실패 요약, 관련 오류, 변경 파일, 테스트 수·산출물 경로를 보고한다. 테스트는 수정 영향 범위 위주로 실행하고 마지막에 통합 검증한다.
- 시간 여유는 실제 데이터 재생·자동 테스트·지연/메모리 측정처럼 로컬 계산에 쓴다. 추가 모델 탐색이나 반복적인 장문 분석으로 채우지 않는다.
- Pro 잔여 사용량20%를 이 세션에서 정확한 토큰 수로 환산하거나 실시간 잔량을 보장할 수 없다. 기능 연결을 먼저 확보하고, 설계 재검토를 제한하며, 마지막 검증·정리에 여유를 남긴다.

## 체크포인트 처리

기록 파일에는 `문제 / 영향 / 임시 선택 / 나중에 필요한 결정 / 관련 파일`을 남긴다. 다음 항목은 개발을 멈추지 않고 기록한다.

- 영상 확보·카메라 보정·실제 CV 모델 선택 → 대체 입력과 unavailable 경로를 완성.
- 라이브 데이터 공급·영상 사용 범위·외부 배포 → 기록 재생·로컬 실행 유지.
- 지원 자료가 부족한 선수·위치 → 추천 후보 축소 또는 추천 불가 표시, 실제 경기 화면은 유지.
- 제구 가정·중요 투구 선정 규칙의 야구적 판단 → 명시한 단순 기준과 설정 파일로 구현.
- UI 세부 선호 → 관전 흐름을 방해하지 않는 기본값 채택.
- 인프라 장애 → 기존 자료를 훼손하지 않는 로컬 대체 경로 사용.

외부 비용·권한이 필요한 작업, 기존 자료 파괴·동결 변경은 임시 선택으로 진행하지 않는다. 해당 부분만 보류하고 나머지 기능을 계속 만든다.

## 빨리 끝났을 때의 순서

1. 실제 타석을 더 재생해 상태·표시·지원 범위 오류 수정.
2. 추천 캐시·계산 재사용으로 응답 지연과 메모리 개선.
3. CV 작업/수동 입력의 실패·재시작·중복 처리 강화.
4. 존 화면·설명 문구·좁은 화면 사용성 개선.
5. 재현 가능한 측정과 실행 문서 보강.

안정적인 결과가 있으면 보존하고 마지막 검증까지 유지한다. 사용 시간을 채우기 위한 설정 탐색이나 대규모 신경망 재학습은 시작하지 않는다.
