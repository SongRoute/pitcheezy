# Pitcheezy 설계 (2026-09-07 확정, 2026-09-15 개인 개발 전환)

이 문서가 설계의 유일한 출처다 (D5). 결정·비교 축·가정은 확정이며, 바꾸려면 `docs/decisions.md`에 한 줄을 먼저 추가한다 (D1).
뒤집힌 항목: §1-b "2026 검증셋 NLL" → 학습 창 내 홀드아웃 (D3). §3 트랙 구조 → 개인 개발 (D5). §0-f·⑤·⑥ 분해 → Phase 2 후순위 (D7). 비교 대상 추가 (D6, §3-b).

**쉬운 말 요약.** 투구 하나하나를 "지금 상황에서 이 공을 던지면 평균적으로 점수가 얼마나 오르내리나"로 값을 매긴다(RE24). 그 값을 가장 좋게 만드는 공을 고르는 규칙(정책)을 과거 데이터(2023–25)로 배우고, 배우는 데 쓰지 않은 2026 시즌에서 "이 규칙대로 던졌다면 실제로 몇 점을 아꼈을까"를 추정한다(OPE). 기존 연구 두 편을 같은 방식으로 다시 만들어 같은 표에 놓고 비교한다.

## 0. 코어 질문과 end-to-end 지표

### 0-a. 코어 질문

- 주어진 상황에서 기대 득점 손실을 최소화하는 투구는 무엇이고, 실제 결과와의 차이는 타자·투수·벤치·전략 중 어디서 왔는가?
- 추천과 해석은 하나의 가치함수 V를 공유 → 해석 모듈은 추천 모듈 위에 얹힘
- 전략 책임 = V(추천) − V(의도)

### 0-b. end-to-end 지표

- 목적: 모듈별 지표(군집 품질, NLL 등)로는 조합 비교 불가 → 최종 산출물(추천, 해석)을 각각 숫자 하나로. 모든 실험은 이 저울 위에서 비교
- 득점가치 단위: RE24
    - 주자·아웃 24개 상태별 기대득점, 플레이 전후 차이 = 그 플레이의 득점가치
    - 투구 단위: Statcast `delta_run_exp`
- 추천 지표: "정책 π_e를 실제로 썼다면 타석당 기대 득점가치"의 추정치
    - 선택 편향(투수가 이유 있어 던진 공) → Off-policy evaluation: 행동 정책 π_b 추정 후 IPS 또는 Doubly Robust
    - VI = argmax(결정론적) → π_b와 겹침 적어 분산 폭발 → 평가 시 softmax / top-k 완화 (방식은 실험에서 결정)
- 해석 지표
    - ① 정합성: 성분 합 = 실제 득점가치 변화 (망원경식 분해면 자동 성립 → 프록시 품질은 못 잡음, 0-f 참고)
    - ② 안정성: 시드·시즌 간 분해 비율 일관성
    - 정성 평가 후순위
- 검증 분할: 시즌 단위 (랜덤 분할은 같은 투타 매치업 누수)
- 평가 저울 고정: e2e는 실제 RE24, xRE24는 보조 지표

### 0-c. 확정 사항

- 보상 R = 리그 공통 RE24 (모든 투수 같은 저울 → 투수 간 비교·4자 분해 가능)
- 투수 특성은 전이 모델 P(다음 상태 | 상태, 투구, 투수)에. 같은 보상 + 투수별 동역학 → 최적 정책이 자동으로 투수별
- 투수별 RE24는 기각 (공통 화폐 깨짐, 상태당 표본 부족)

### 0-d. 보상 정교화 — RE24가 못 잡는 것

- A. 운: 실제 결과엔 BABIP·수비·구장 섞임 → 삼진·볼넷 편향 위험
    - xRE24 = 타구 특성(EV/LA/방향) 기반 결과 분포 × ΔRE24. `estimated_woba_using_speedangle` 출발점
    - 학습 보상의 실험 축. 현 단계 실익 최대
- B. 레버리지: RE24는 점수차·이닝 무시. 진짜 목적함수는 WE(승리확률)
    - WE 상태 수천 개 → 투수별 모델에서 희소, OPE 분산 증가
    - 정책 학습 보상은 RE 계열 / LI 가중은 보조 지표 / WE는 벤치 성분에만
- C. 투구 비용(투구수·피로·시퀀싱·타순 회차): 보상 페널티가 아니라 상태 피처. ④ 컨디션 모듈 연결 지점
- RE24 테이블은 학습 시즌 창으로 재계산 (룰 변경으로 득점 환경 변화)
- 구장 효과: 공변량 하나로

### 0-e. 문제 1 — 순환 평가

- ②전이 모델 P̂가 ③정책의 시뮬레이터. P̂ 안에서 최적인 정책을 P̂로 평가하면 VI가 방금 최대화한 값을 재확인하는 것 → 무의미
- model exploitation: 정책은 모델이 낙관적으로 틀린 곳을 골라 파고듦 → 시뮬레이션 가치는 상향 편향, 모델이 가장 틀린 곳에서 편향 최대
- 설계 반영
    - ②: 홀드아웃 NLL + 캘리브레이션 (희귀·고가치 결과: 홈런·헛스윙 / reliability diagram, ECE)
    - ③: 실데이터 OPE. 전이 모델 간 비교도 각자 시뮬레이터가 아니라 같은 OPE 위에서
    - 검증 시즌(2026)은 ②를 건드리지 않음: ② 학습 → ③ VI → 2026 OPE
    - 완화(③ 축 후보): 전이 모델 앙상블 비관적 가치 / π_b KL 제약 (OPE 분산도 감소)
- OPE도 π_b·결과 회귀 모델을 쓰지만 보상이 실데이터이고 π_b가 ②와 독립 → 순환 끊김

### 0-f. 문제 2 — 투수 실책의 기준점(의도) [Phase 2 후순위, D7]

- 분해 사슬 (망원경식, 합 = V(추천) − 실제 결과 → 정합성 자동)
    - 전략 = V(추천) − V(의도)
    - 투수 실책 = V(의도) − V(실제 투구)
    - 타자 = V(실제 투구) − 실제 결과
        - xRE24로 분리 가능: 타자 역량 = V(투구) − xRE(타구 질) / 운 = xRE(타구 질) − 실제 결과. 5번째 성분으로 분리 권장
    - 벤치 = 다른 층(누가 던지나, 교체 타이밍), WE
- Statcast에 의도 없음 → 기준점 없이는 전략·실책이 뭉개짐 (계획 오류 vs 실행 오류 구분 불가)
- 0/1(빗나감) 라벨만으로 부족한 이유
    - 착지점의 비용 크기는 보상(V(실제))이 잼 → 여기엔 의도 불필요
    - 비용의 주인(계획 vs 실행)은 V(의도)가 결정. 같은 착지점·같은 보상이어도 셋업 위치에 따라 전략/실책이 정반대
    - "빗나감 → 전부 실책" 지름길은 V(의도) ≈ V(추천)일 때만 성립 → 추천 모듈의 전제(실제 계획이 추천과 자주 다름)와 충돌
    - 라벨 1(맞춤)에서는 의도 = 실제 → 실책 0, 손실 전부 전략. 라벨 0에서만 기준점 필요
    - 결과를 보고 거꾸로 책임 정하기 = 사후 편향. 실책은 결과와 무관하게 같은 크기여야 함
- 결론: 기준점 = 교체 가능한 부품. 실책 = V(기준점) − V(실제)
    - 후보 (⑥ 축): ⓑ 단일 중심 / ⓒ 혼합분포 / CV-학습 프록시
    - ⓑ: 투수×구종(×카운트×좌우) 로케이션 평균. 구종 하나에 목표 여러 개면 평균이 사이에 놓여 판정 뒤집힘(백도어 = 실책). 노이즈가 아니라 편향
    - ⓒ: 투수×구종×카운트 구간×타자 좌우별 GMM(2~3 성분), 실제 로케이션이 속한 성분 중심 = 의도. 메인
    - 단봉/다봉 여부는 경험적으로 확인 → ⓑ는 베이스라인으로 유지
    - 소프트 배정: 실책 = Σ pₖ [V(cₖ) − V(실제)] → 애매한 투구는 실책도 흐릿하게
    - 조건에 카운트 구간·타자 좌우 필수 (구종만은 너무 거침). "많이 벗어나면" 임계값 불필요 (연속값)
- CV 역할 재정의: 후순위 모듈 → ⑥의 검증·보정 파일럿 (라벨러)
    - 셋업 시점 미트 위치 = 의도, 셋업→포구 변위 = 실행 오차(연속). 0/1은 임계값으로 파생
    - "편하게 잡음" 주관 라벨은 프레이밍에 속음 → 변위 기반
    - 커버리지: 클립 2,008개 vs 시즌 70만 구 → per-pitch 피처 불가. 소수 투구에 정답을 붙이는 라벨러로
        - (1) 프록시 검증·보정: 성분 배정 vs 셋업 위치 일치도, 변위 vs 프록시 오차 상관
        - (2) 학습된 프록시: 클립 라벨로 "Statcast 피처 → 의도 위치" 학습 → 전체 투구 적용
    - 라벨 1 투구만으로 의도 분포 학습(빗나간 공 오염 없음), 라벨 0은 최근접 목표 배정
    - 파일럿: 1인, 1~2주, 새 라벨링 없음. 기존 글러브 검출기 + 개폐 크롭으로 변위 추출 → go/no-go
        - Go: CV를 라벨러로 편입, 클립 확장은 레귤러 선발 60~70명 × 투수당 시즌 ~200구
        - No-go: 프록시 단독, 검증 숫자는 문서에 유지
    - 미트 위치도 의도의 근사 (포수 셋업 ≠ 투수 목표일 수 있음)
- 문서화할 가정: "투수 실책의 기준점은 해당 투수·구종·상황의 로케이션 혼합분포에서 실제 로케이션이 속한 성분의 중심이며, 포수 셋업 위치가 있는 서브셋에서 검증된다. 셋업 위치도 진짜 의도의 근사다."

## 1. 데이터 범위와 state 정의

### 1-a. 데이터

- MLB Statcast만 (pybaseball)

### 1-b. 시즌 범위

- 동일성 경계: 2020 Hawk-Eye 전환(측정값) / 2023 피치클락·시프트 금지·베이스 확대(결과 분포) / 2026 ABS 챌린지(경계 판정). 2020 단축 시즌 제외
- 후보: 2023–26 (엄격) vs 2021–26 (데이터 1.5배, 룰 변경 전후 혼재)
- 결정 방식: 실험. 2023–25 학습 vs 2021–25 학습 → 학습 창 내 홀드아웃 NLL·ECE로 스크리닝, 채택은 OPE (ADR-3으로 갱신. 원문: "같은 2026 검증셋 NLL"). 나빠지면 2021–22 제외, 좋아지면 시즌 피처 검토

### 1-c. 투수 범위

- 시즌당 일정 이닝 이상 레귤러 선발 (예: 100이닝 → 시즌 60~70명, 투수당 2,500~3,000구, 4시즌 8천~1만 구)
- 특화 성공 후 일반화(불펜·신인)로 확장

### 1-d. 타자 표현

- 개인 ID는 데이터 부족 → 군집 또는 임베딩. ①전처리 군집화 실험과 연결

### 1-e. 에피소드·상태 설계

- 에피소드 = 타석, 스텝 = 투구, γ = 1
- 상태 = (카운트, 주자·아웃, 타자 군집, 투수, 맥락 피처)
    - 주자·아웃: 매 투구 시점 실제값 (Statcast 기록). VI는 타석 내 불변 가정 (무시 ≠ 제외)
    - 맥락 피처 후보: 투구수, 타순 회차, 직전 N구 구종 이력, 점수차·이닝
- 전이 = 다음 카운트 또는 종결 결과 (+ 투구 이벤트). 주자 진루는 학습하지 않음
- 종결 보상 = ΔRE24(주자·아웃, 결과)
    - 축: ⓐ 맥락 없는 고정 가중치(대조군) / ⓑ ΔRE24 (메인) / ⓒ 풀 이닝 MDP (다음 타자까지 상태, 라인업 인식 전략. RE24는 다음 타자를 리그 평균으로 가정. 후순위)
- 중간 보상 = `delta_run_exp` (카운트 조건화 기대득점 변화. potential-based shaping → 최적 정책 불변, 학습만 가속)
- 결과 공간
    - 거침(K/BB/HBP/인플레이 결과)으로는 병살 유도 불가 (전이 모델이 병살과 단순 아웃 구분 못 함)
    - 세분화: 타구 유형(땅볼/뜬공/라이너) × 방향 × 강도 + 주자·아웃 조건 조회표 P(ΔRE24 | 타구 특성, 주자·아웃) (병살·희생플라이). 종결 시점 한 번, 리그 평균 매핑이면 충분. xRE24와 통합
- 타석 중 주자·아웃 변화
    - 데이터 제외 없음. 비율 문서화 (전체 타석 ~3~5%, 주자 있는 타석 ~10% 추정 → 실제로 셀 것)
    - 반응(변화 후 정책 재계산)은 per-pitch 상태로 공짜. 예측(변화 전 가능성 반영)만 모델링 대상
    - 기준 = 빈도 × 투구 의존성 × 가치 변동
    - 폭투/포일: 투구 의존성 최고, 3루 주자면 1점 → 투구 단위 이벤트로 전이에 추가 (로케이션·구종·투수 조건). 베이스라인 직후
    - 도루/도루 실패: 시도는 외생(주자 속도 군집, 투수, 포수, 카운트, 점수차), 성공은 구종 조건부(변화구 → 성공률↑). 도루 가능성 높으면 병살 유도 투구 가치 하향 필요 → 폭투 다음
        - 트리거: 주자 1루 + 빠른 주자 서브셋 OPE가 전체보다 유의하게 나쁘면 편입
    - 견제사·보크·주루사: 투구 의존성 없음 → 무시
    - 히트앤런 등 타자의 사전 접근 변화: 벤치 결정 → 전이 노이즈, 벤치 성분
- 점수차·이닝: 상태 피처(타자 접근 변화)로는 지금, 보상(WE)으로는 후순위

## 2. 모듈별 비교 축

### ① 데이터·전처리

- 시즌 창: 2023–25 vs 2021–25
- 타자 표현: 군집화 방식 (미정 — 성향 기반 군집 vs 임베딩)

### ② 전이 모델

- 투수별 구조: ⓐ 투수별 완전 별도 / ⓑ 공유 + 투수 임베딩 / ⓒ 공유 사전학습 + 투수별 파인튜닝 (ⓐ = 특화, ⓑⓒ = 일반화 경로)
- 결과 공간: 거침 vs 타구 특성 기반 + 조회표
- 투구 이벤트: 폭투/포일 포함 여부 → 도루
- 지표: 홀드아웃 NLL + 캘리브레이션 (학습 창 내 홀드아웃, ADR-3)

### ③ 정책·보상

- 종결 보상: ⓐ 맥락 없음 / ⓑ ΔRE24 / ⓒ 풀 이닝
- 인플레이 보상: 실제 RE24 vs xRE24
- 평가 시 완화: softmax 온도 / top-k
- 보수화: 앙상블 비관적 가치 / π_b KL 제약
- 상태 피처: 투구수, 타순 회차, 구종 이력, 점수차·이닝 포함 여부

### ④ 투수 컨디션

- 상태 피처로 연결 (미설계)

### ⑤ CV [Phase 2 후순위, D7]

- 파일럿 go/no-go (0-f)

### ⑥ 책임 분해 [Phase 2 후순위, D7]

- 기준점: ⓑ 단일 중심 / ⓒ 혼합분포 / CV-학습 프록시 (평가 = 클립 서브셋 셋업 위치 일치도)
- 운 성분 분리 여부
- 벤치: WE (후순위)

### ⑦ LLM 해석, ⑧ 프론트엔드

- 후순위

## 3. 실험 매트릭스와 우선순위

- 방식: 전조합 불가 → 베이스라인 고정, 축 하나씩 ablation, OPE 오르면 채택 후 다음 축. 검증셋·e2e 지표는 끝까지 고정
- Phase 0 — 베이스라인 end-to-end (D6·D7로 갱신)
    - 우리 모델: 2023–25 / 거친 결과 공간 / 투수별 별도 모델 ⓐ / ΔRE24 실제 결과 / softmax 평가
    - 외부 베이스라인 B1 (SmartPitch류, 카운트만) + 내부 기준선 (π_b 자체 OPE, 랜덤 정책 OPE)
    - 목표: 네 정책이 한 표에 놓인 OPE 숫자. 이후 모든 실험의 비교 대상
- Phase 1 — 기대 개선 큰 축 (순서는 D8 → D24 로 변경)
    - 투수별 구조 ⓑⓒ (D24: P0 위약 검사에서 투수별 정보 부재 확인)
    - 직전 N구 시퀀스 맥락 (B2 Takamido류 재구현과 함께. context 축 삽입)
    - xRE24 + 결과 공간 세분화 (얽혀 있어 함께)
    - 폭투/포일
- Phase 2 — 나머지
    - 4자 분해 + 혼합분포 기준점 + CV 파일럿 (D7)
    - 시즌 창, 도루, 보수화, 상태 피처 추가, 운 성분, WE 벤치, 풀 이닝
- 상호작용 묶음 (탐욕적 순서 의존 주의)
    - 결과 공간 세분화 × xRE24 (조회표 없이는 효과 없음)
    - 모델 구조 ⓑⓒ × 데이터 적은 투수 (차이가 거기서만 남)
- 모듈 경계 (구 트랙 A/B/C, D5로 라벨만 제거)
    - data·transition (①②) → policy·ope (③) → decomp·cv (⑥⑤)
    - 인터페이스: 전이 확률 텐서 / 가치함수 Q (+ 공통 자산 RE24 테이블). 스펙은 docs/interface-spec.md

### 3-b. 비교 대상 (D6)

- 원칙: 논문 보고 수치를 옮기지 않는다. 우리 데이터 버전·같은 2025 홀드아웃·같은 2026 OPE에서 재구현해 같은 표에 넣는다
- B1 SmartPitch (Otremba 2022): 카운트 상태 MDP + 지도학습 전이 + 동적계획법. 우리 Phase 0의 축소판. 우리 텐서에서 K=1, 주자·아웃 축 붕괴로 재현. 보상·행동 공간은 원문 미확인 (docs/baselines.md)
- B2 Takamido & Nakamoto: Transformer로 2스트라이크 결정구의 인플레이 확률 예측, 반사실 argmin으로 구종·로케이션 선택. MDP·OPE 없음. 모듈 층(전이 모델 NLL·ECE)과 정책 층(2스트라이크 제한 OPE) 두 층에서 비교
- 우리 기여: (1) 카운트 MDP를 주자·아웃·타자 군집·투수별로 확장하고 RE24로 보상 통일, (2) 세 방식을 실데이터 OPE 한 저울에서 비교. 두 논문 모두 (2)를 하지 않았다
