# P1 첫 축 ⓑ — 공유 전이 모델 + 투수 임베딩 (설계 초안, 2026-09-20)

D24 로 P1 첫 축이 됐다. 이 문서는 초안이며 확정되면 decisions.md 에 한 줄(D28) 적고 design.md §2 ② 에서 링크한다.

## 왜
P0 위약 검사: 다른 투수의 Q 로 기울여도 진짜 Q 와 거의 같은 이득 (001: +0.031 / +0.031). 현재 전이 모델은 "리그 공통 지도"이고 투수별 정보가 없다. 원인은 투수당 자료(5천 구)가 (상태 288~1,728 × 행동 225) 칸을 못 채워 평활이 리그 평균으로 덮는 것. 투수 층 해상도를 올린 006/009 에서 처음 갈렸다(+0.040 / +0.035).
야구로 치면: 투수 219명에게 같은 볼배합 책을 주고 있다. 투수마다 책을 따로 쓰기엔 자료가 부족하니, **한 권의 책에 "구속 95 이상 싱커 투수는 이 페이지"** 처럼 투수 특징으로 갈래를 두는 것이 ⓑ 다. 비슷한 투수끼리 자료를 나눠 쓴다.

## 무엇이 바뀌고 무엇이 안 바뀌나
- 바뀜: 전이 모델 학습 방식만 (`transition/count.py` 집계+평활 → `transition/shared.py` 신경망). config `transition.model_arch: shared_embedding`
- 안 바뀜: 텐서 스키마·저장 포맷(interface-spec v1 그대로), VI·완화·π_b·OPE·판정(D19~D23), 풀·RE24·군집. 베이스라인 = **EXP-P0-009** (K=6, 투수층 구종×구역, 주자·아웃 보상)
- 실험 ID: EXP-P1-001 (ⓑ 본체) + 같은 코드로 대조군 두 개 (아래)

## 모델
입력 (한 투구) → 결과 11-way 확률. 모두 임베딩을 이어 붙여 작은 MLP 에 넣는다.

| 입력 | 표현 | 차원 |
|---|---|---|
| 카운트 (12) | 임베딩 | 8 |
| 주자·아웃 (24) | 임베딩 | 8 |
| 타자 군집 (K=6) | 임베딩 | 4 |
| 구종 (9) | 임베딩 | 8 |
| 위치 행·열 (5, 5) | 임베딩 각각 | 4 + 4 |
| 투수 id (219) | **학습 임베딩** | 16 |
| 투수 측정 특징 | 구종별 (구속, 회전수, pfx_x, pfx_z, 릴리스 x·z, 익스텐션, 팔각도) 학습 창 평균 + 구종 사용률 → 9구종 × 9값 = 81, 없는 구종은 0 + 마스크 | 81 → 선형 16 |

MLP: concat(≈84) → 128 → 128 → 11 (ReLU, dropout 0.1). 규칙 마스크(3볼에 볼, 2스트에 스트라이크 등)는 로짓에 −∞. 파라미터 ≈ 4만.
"투수 측정 특징"은 Statcast 열 `release_speed, release_spin_rate, pfx_x, pfx_z, release_pos_x, release_pos_z, release_extension, arm_angle` (결측 0.4~0.8%) 의 (투수, 구종) 평균. 표준화. **학습 창에서만 계산** (2026 값은 안 씀. 2026 신규 구종은 0 + 마스크).

### 왜 임베딩과 측정 특징을 둘 다
- 임베딩만: 자료 많은 투수는 잘 맞지만 적은 투수는 리그 평균으로 수렴 (P0 와 같은 문제가 약하게 남음)
- 측정 특징만: "95마일 싱커" 라는 사실만으로 비슷한 투수의 자료를 빌려온다. 자료 적은 투수에게 유리. 단 같은 구속·무브먼트라도 커맨드·시퀀싱 차이는 못 잡음
- 둘 다: 특징이 사전분포, 임베딩이 잔차. **추천**. 대조군으로 분리 실험 (아래)

## 학습
- 손실: 결과 11-way 교차 엔트로피 (규칙 마스크 적용). 행동 있는 투구만 (P0 와 동일 조건)
- 홀드아웃 텐서: 2023–24 학습 → 2025 NLL·ECE 보고 (P0 와 같은 표에 놓는다). 조기 종료는 2025 가 아니라 **학습 창 안 10% 경기(game_pk % 10 == 0)** 로 → 2025 NLL 은 튜닝에 안 쓰인 숫자로 남는다
- 전체 텐서: 2023–25 학습, 에폭 수는 홀드아웃 학습에서 정해진 값 그대로
- 옵티마이저 AdamW lr 1e-3, weight decay 1e-4, 배치 4096, 최대 20 에폭, 조기 종료 patience 3. 학습 자료 ≈ 105만 구 → 에폭당 ~260 스텝, M4 CPU 로 에폭당 1분 안쪽 예상 (미측정, 첫 실행에서 기록)
- 시드: 이제 진짜 난수(초기화·셔플). 탐색 {0,1,2} 각각 학습. 채택 후보만 {0..4}
- 텐서 생성: 모든 (투수, 상태, 행동) 조합에 forward → K=6 이면 219 × 1,728 × 225 = 8,500만 행. 배치 forward 로 수 분 (미측정). 결과 float32 3.7GB
- valid 마스크: P0 와 같은 규칙 (학습 창 구종 ≥ 100구). n_obs 도 같은 집계로 동봉. meta.model_arch = "shared_embedding", 하이퍼파라미터 전부 meta 에
- 저장: P 는 s0 만 (Drive 용량, D21 과 같은 이유). s1·s2 는 Q·V·policy·홀드아웃 지표만. 스펙에서 벗어나는 부분이라 decisions 한 줄

## 위험과 대비
- **착취**: NN 은 셀 단위 잡음은 덜하지만 외삽 지점에서 자신만만할 수 있다. 모델 내 가치와 OPE 를 같이 본다. 앙상블 비관은 P2
- **과적합 (임베딩)**: weight decay + 조기 종료. 002 (투수 없음) 와 비교로 확인
- **시간**: 첫 실행에서 학습·텐서 생성 시간을 재고 2시간 넘으면 Colab (D10)
- **torch**: pyproject 에 `torch>=2.4` 추가. MPS 는 되면 쓰고 안 되면 CPU. 시드 고정해도 MPS 는 완전 결정론 아님 → run.json 에 장치 기록
