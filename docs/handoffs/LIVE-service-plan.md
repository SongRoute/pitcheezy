## 2. 단계별 상태

### 1단계 — 과거 경기를 실제 시간대로 재생 (완료)

- 끝난 경기의 최종 피드를 **실시간과 똑같은 경로**(피드 → 상황 해석 → 동결 모델 → 화면)에 흘려보낸다. 각 공은 기록된 놓는 시각 간격 그대로 나오고, 결과는 놓고 1초 뒤(타구는 플레이가 끝난 시각)에 보인다.
- 화면: 경기 목록의 "실제 속도로 다시 보기" → `/live?game=N&replay=0`. 회 버튼으로 그 회 첫 공 15초 전부터 시작, ±1·±5초 버튼으로 영상과 맞춘다. 시작 시각이 주소에 들어가서 새로 고침·다른 기기에서도 같은 시계를 본다. `&speed=8`은 배속, `&lag=16`은 실제 피드처럼 기록을 늦게 주는 리허설이다.
- **한 경기 전체 확인(8배속):** 849843의 262개 투구 상황. 조회 2,248회 중 오류 0, 추천 가능 246·불가 16(사전 계산 246/262와 같음), "계산 중"으로 보인 조회 0회, 계산 시간 중앙값 0.14초·95% 0.18초, 모델 재준비 1회(5.8초). 응답 시간 중앙값 9ms·95% 204ms. `results/checks/LIVE-replay-849843-x8.json`(브랜치 `demo/live-sync`).

### 3단계 — 관전에 지장 없는 속도 (기준 충족 범위 확정)

"지장 없다"의 기준: **다음 공이 던져지기 5초 전까지 추천이 화면에 있고, 공 결과는 내 중계보다 먼저 뜨지 않는다.**

- 우리 쪽 처리는 충분히 빠르다(공마다 0.13초, 화면 갱신 2초). **느린 것은 피드 자체다**: 공을 놓은 뒤 약 19초(중앙값) 뒤에야 기록이 올라오는데 다음 공은 약 20초 뒤에 온다.
- 실측(§4): 중계가 **30초 이상 늦는 시청자는 100%**, 20초는 98–99%, 10초는 84–87%, 지연이 없으면 약 42%다. 스트리밍 중계는 보통 수십 초 늦으므로 대상 사용에는 충분하지만, 실제 시청 환경의 지연은 사용자가 화면의 "중계 맞추기"로 재야 안다(미측정).
- 한 일: 시청자별 중계 지연 맞추기(사건 시각 기준, ±버튼과 "미트에 들어오는 순간 누르기"), 화면 갱신 5초→2초, 새 상황의 추천을 요청 안에서 최대 1초 기다려 "계산 중" 깜빡임 제거, 최대 3경기 동시 준비, 지연 25초 미만 시청자가 있을 때만 피드 5초 조회(CP4).

### 그다음 (순서는 사용자 결정)

- 빠른 중계(지연 20초 미만) 시청자용: 지금 공의 결과별(볼이면/스트라이크면) 다음 추천을 미리 계산해 한 공 앞서 보여 주기. 정책 요청 경로를 건드리므로 별도 설계가 필요하다. **보류(D149):** 사용자가 실제 중계 지연을 "중계 맞추기"로 재 보고 20초 미만이면 그때 검토한다.
