# 인계 기록 양식

인계마다 새 ID의 문서를 만든다. 요청 측 작성자가 초안을 쓰고 반환 후 통합 기록 작업자가 상태를 갱신한다. 양쪽이 같은 파일을 동시에 수정하지 않는다.

- ID / 보낸 PM / 받는 PM / 시각(KST)
- 상태: 인계 요청 → 인수 → 적용 검증 → 수용 또는 반려(이유·다음 조치)
- 목적과 완료 기준
- source commit / worktree / config / 데이터·모델·산출물 해시
- 입력·출력·단위·지원 범위와 실패/결측 처리
- 결과, 비교 기준, 노출/해석 한계, 검토 증거
- 실행 비용·자원·지연·메모리
- 기존 서비스/연구에 미치는 영향, 복구 기준점
- 받는 쪽 담당 작업자·모델·인수 시각·예상 다음 조치

검토·인수 기록이 없으면 단순 파일 생성만으로 전달 완료라고 하지 않는다. native message는 보조 통신이며 파일/커밋이 지속 증거다. 별도 앱 채팅으로 자동 전달되는 도구는 현재 구성에 없음.
