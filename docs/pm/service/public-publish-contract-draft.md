# 공개 발행 계약 (초안 v0)

상태: 초안, 2026-10-11. Song 결정 "맥미니가 바깥으로 내보내기만 한다" + "지연은 모두에게 같은 값 하나"를 옮긴 것이다. 팀원 합의 전이며 구현·실행 전이다. 수치 기준(발행 간격, 갱신 지연 판정, 캐시 시간)은 리허설에서 재고 정한다 — 아래 "미정"은 추정하지 않고 비워 둔 것이다.

상위 문서: [협업 헌장 초안](../collaboration-charter-draft.md) 5·9절.

## 1. 구조

```
MLB 공개 피드 ─► 맥미니 발행기 ─(올리기만)─► 공개 호스팅 ◄─(읽기만)─ 팬의 화면
                 (Song 레포)                  (팀원 관리)
```

- 팬의 요청은 맥미니에 닿지 않는다. 맥미니로 들어오는 길은 열지 않는다.
- 맥미니는 경기당 한 번 계산해 파일로 올린다. 접속자가 늘어도 맥미니 부하는 같다.
- 이 문서가 정하는 파일 묶음이 두 레포 사이의 계약이다. Song은 파일 내용, 팀원은 파일을 받아 보여 주고 지키는 일을 맡는다.

## 2. 파일

경로는 공개 호스팅의 한 접두사 아래에 둔다. 본문은 `rc/ws-2026`의 `/api/service/*` 응답과 같은 JSON이다. 필드 정의는 이 문서에 다시 적지 않고, 고정 커밋에서 뽑은 **예제 파일과 JSON Schema**로 넘긴다(스키마가 정본, 문서는 안내).

- `v1/manifest.json` — 계약 버전, Song 커밋, 발행 시각, 발행 간격, 고정 지연 값
- `v1/health.json` — 마지막 발행 시각과 순번. 화면과 감시가 "갱신 지연"을 판정하는 데 쓴다
- `v1/dates.json` — 경기가 있는 날짜 목록 (현재 `GET /api/service/dates`)
- `v1/games/<날짜>.json` — 그날 경기 목록 (현재 `GET /api/service/games?date=`)
- `v1/game/<game_pk>.json` — 경기 한 개의 전체 상태 (현재 `GET /api/service/games/{pk}`)
  - 진행 중: 발행 주기마다 덮어쓴다
  - 종료: 마지막으로 한 번 쓰고 종료 표시를 단다. 이후 바꾸지 않는다(정정은 새 순번으로)
- `v1/setup/<game_pk>.json` — 끝난 경기의 포수 미트 가로 위치. 팀원 영상 모듈 산출물이 Song 검사기(`validate_intent_estimate`, sha256 pin)를 통과한 뒤에만 올린다. 없는 경기는 파일이 없다

## 3. 규칙

- **보여도 되는 것만 담는다.** 진행 중 경기 파일에는 서버가 지금 표시를 허용한 내용만 넣는다. 확인 중인 공의 구종·속도·위치·결과는 비운다. 미래 공은 넣지 않는다. 시연용 재생과 운영자 기능은 발행 대상이 아니다.
- **장부 먼저.** 추천은 발행 전에 추천 장부에 기록한다. 기록에 실패하면 그 추천은 내보내지 않는다.
- **통째로 바꾼다.** 파일은 임시 이름으로 올린 뒤 바꿔치기한다. 반쯤 쓰인 파일이 읽히면 안 된다.
- **순번과 시각.** 모든 파일에 발행 순번과 발행 시각을 넣는다. 화면은 순번이 뒤로 가는 파일을 버린다.
- **고정 지연.** 모든 시청자에게 같은 값 하나를 쓴다. 발행기 설정 값이며 기본은 0초(피드에 뜨는 대로)다. TV·현장 관람과 거의 같은 환경을 전제로 한다(2026-10-11 Song). 값은 리허설에서 조정할 수 있다.
- **멈췄을 때.** 발행이 끊기면 화면은 마지막 상태를 유지하고 "갱신 지연"을 표시한다. 판정 기준은 미정.
- **캐시.** 진행 중 파일은 발행 간격보다 길게 캐시하지 않는다. 종료 파일은 길게 캐시해도 된다. 값은 미정.
- **비밀.** 올리기용 인증 값은 맥미니에만 둔다. 레포·이슈·문서에 적지 않는다.
- **버전.** 필드를 빼거나 뜻을 바꾸면 `v2/`로 올린다. 더하기만 하는 변경은 `v1` 안에서 한다.

## 4. 팬의 화면

- 화면(본체)은 Song 레포의 관전 화면이다. 고정 커밋에서 빌드한 정적 파일을 팀원이 같은 호스팅에 올린다.
- 화면은 읽을 주소만 서버에서 위 파일로 바꾼다. "마지막 공 이후만 받기"는 쓰지 않고 전체 파일을 읽는다(파일 크기는 미측정 — 재 보고 크면 나눈다).
- 접속 기록과 피드백은 팀원 쪽에서 받는다. 맥미니는 팬이 실제로 봤는지 알 수 없다.

## 5. 알려진 한계

- 공식 피드는 실제 투구보다 늦게 온다(849844·849831 한 경기씩 실측: 약 11~20초). 849831에서는 다음 공이 이미 시작된 뒤에 직전 공이 처음 수신된 경우가 256구 중 99구였다. 이런 공은 TV·현장 관람자에게 투구 전 추천이 제때 닿지 못한다. 발행·호스팅 지연이 여기에 더해지며 끝에서 끝까지의 지연은 미측정이다.
- 미트 표시는 경기 뒤 영상 판독으로 만들어지므로 진행 중 경기에는 없다. 모든 값은 검토 전 추정이다.

## 미정

- 발행 간격, 갱신 지연 판정 기준, 캐시 시간
- 호스팅 종류와 올리기 방식(팀원 선택)
- 경기 파일 크기와 분할 여부
- MLB 공개 피드의 공개 서비스 이용 조건
