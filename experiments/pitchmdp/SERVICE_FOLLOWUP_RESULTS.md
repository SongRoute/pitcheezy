# CLI 후속2–4단계 결과 — 2026-09-21

**분리 학습 평가, 날짜별 선수 정보 갱신, 약점 한정 개선 실험을 실행했다.** CLI는 유지했다. 분리 평가에서 전체 타석 계획의 우위는 확인되지 않았고, 원 추천 모델의 확률 보정 후보는 검증 성능이 나빠 채택하지 않았다. 서비스에는 기존 모델과 날짜별 정보 갱신을 사용한다. Astra가 설계·코드, Sol이 실제 실행·결과 저장을 맡았다.

## 2. 정책 평가

원 정책의 신경망 학습은2025년4월까지, 보정은5–6월이다. 평가기의 학습·보정에는7월 경기만 사용했다.8월1–7일은 진단,8–15일은 개선안 채택 판단,8월16일–9월30일은 최종 비교로 분리했다. 경기 집합 비중첩을 검사했다. 이미 앞선 탐색에서 본 역사 기간이므로 완전히 새로운 확증 자료는 아니다.

첫 상황별 빈도 평가기는 검증 로그손실1.513273으로 카운트 기준1.507846보다 나빴다. 이 실패를 `service-validation-v1`에 보존하고, 희소한 셀을 줄이는 **정규화 로지스틱 평가기 한 개**만 시험했다. 타자 연속 성향과 주자·아웃 등 상황은 유지했다.7월1–21일63,528구 적합,7월22–31일34,433구로 혼합 계수만 정했다.8월 데이터로 평가기를 학습하지 않았다.

| 평가기 예측 점검: 로그손실, 낮을수록 좋음 | 동일 자료의 카운트 기준 | 정규화 평가기 |
|---|---:|---:|
| 진단8월1–7일, 전체 리그 | 1.519604 | **1.510853** |
| 검증8월8–15일, 전체 리그 | 1.509107 | **1.499577** |
| 최종8월16일 이후, 대상 투수2,480구 | 1.511039 | **1.502341** |

최종 WE Brier는0.152838이었다. 진루 모델의26,693개 지원 종결 전이 중 실제 다음 상태에 확률0을 준 비율은0.345%, 셀 정보가 없어 대체 전이를 사용한 비율은0.0225%다. 최소 점검은 통과했지만 드문 전이까지 검증된 것은 아니다.

최종 정책 표본은 **30경기·150타석**이다. 각 투수·경기에서 시간순 처음5개 적격 타석을 사용해 초반 상황에 치우친다. 실제로 관측한 이후 결과를 입력에 넣지 않고, 원 정책이 고른 행동을 별도 평가기로 채점했다.

| 비교 | 평균 수비 WE 차이 | 경기 bootstrap 구간 |
|---|---:|---:|
| 전체 타석 계획 − 구종 빈도 정책 | +0.00403%p | **−0.00075 ~ +0.00871%p** |
| 전체 타석 계획 − 첫 구만 개입 | +0.00314%p | **−0.00079 ~ +0.00734%p** |
| WE 전체 타석 − RE 전체 타석 | −0.00024%p | −0.00115 ~ +0.00072%p |

앞의 두 주요 비교는 다중 비교를 반영한97.5% 구간, RE 비교는 보조95% 구간이다. 모두0을 포함한다. **이번 표본에서는 타석 계획이나 WE 목적의 우위를 확인하지 못했다.** 차이가 없다는 동등성 증명도 아니다.

이전51개 후반·근소한 점수차 우선 사례의 내부 평가와는 평가기뿐 아니라 표본도 다르다. 따라서 이전 수치와 이번 수치의 차이를 평가기 변경 효과 하나로 해석하지 않는다. 타자 프로필의 과거 원천, 행동의 관측 편향, 사후 적격 타석 필터, 모델 가정을 공유하므로 현실의 인과적 승률 개선 검증은 아니다. 평가 구종·카운트 셀 지원 표본 중앙값은141구,20구 미만은11.9%였다.

## 3. 날짜별 선수 정보 갱신

**2025-08-16부터 쓸 수 있는 스냅샷**을 만들었다. 자료는8월15일까지이고, 마지막 관측일의 모든 기록을 포함한 타자 성향887명과 신뢰도를 저장했다. 같은 날짜 이후의 정보를 제외하는 합성 검사를 통과했다.

- 후보는 원 모델의 구종 중 이전90일에20구 이상 관측된 구종만 허용한다. 모델이 지원하지 않는 새 구종은 추가하지 않는다.
- 기존6명 중5명은 지원 가능했다. Nola는 해당 시점의 최근 지원 구종 기록이 기준에 못 미쳐 제외했다. 이 판정은 투구 기록 기준이며 실제 로스터·부상 상태 조회가 아니다.
- 미지의 타자는 이전 날짜 리그 비율과 신뢰도0으로 처리하고 경고 필드를 반환한다. 미지원 투수·사용 불가능한 투수·잘못된 날짜는 오류로 처리한다.
- 원 번들은 그대로 보존한다. 새 JSON에는 기준 날짜, 원 자료·모델 메타데이터·계산 코드의 해시와 코드 사본이 연결된다.

[날짜별 CLI 사용법](docs/REFRESH_CLI.md). 이 갱신은 기능 검증을 완료한 별도 변경이다. 위 정책 비교는 매일의 과거 타자 성향과 원 TRAIN 구종 목록을 사용했으므로,8월16일 고정 스냅샷·최근 구종 제한을 합친 CLI 정책 전체의 효과를 검증한 결과는 아니다.

실제 CLI는8월17일 Webb–batter802415 요청에서 프로필을 ID로 조회하고 스위퍼(ST)를 첫 후보로 반환했다. 기각한 보정은 적용되지 않았다. 미지 타자 처리, 미지원 투수, 사용 불가능한 Nola, 너무 이른 요청 날짜, 요청 당일의 명시 프로필에 대한 실제 오류/대체 응답을 확인했다. **전체206개 테스트와11개 subtest 통과**, 저장 결과·소스 해시 감사도 통과했다.

## 4. 관측된 약점에 한정한 개선

진단447구에서 클래스별 평균 확률과 실제 비율의 최대 차이가3.61%p였다. 설계대로 클래스 절편 보정 한 개를 적합하고 별도의 검증432구에서 채택 여부를 판단했다.

| 지표 | 기존 모델 | 보정 후보 |
|---|---:|---:|
| 검증 로그손실 | **1.458590** | 1.468315 |
| 검증 Brier | **0.716775** | 0.720099 |

두 지표가 나빠 **보정은 채택하지 않았다.** 최종 평가를 보기 전에 결정을 저장했고, 추가 설정은 탐색하지 않았다. 원 모델의 최종2,480구 로그손실은1.481775, Brier는0.717763이다. 부가 확인에서도 기각 후보의 로그손실은1.484847로 더 나빴다. 진단의 차이가 안정적인 보정 문제인지, 적은 표본의 변동인지 구분이 필요하다.

이번에 유지한 개선은 **평가기의 정규화**와 **날짜별 정보 갱신 기능**이다. 원 추천 신경망은 재학습하지 않았고 예측이 좋아졌다고 주장하지 않는다.

## 사용과 다음 우선순위

CLI 요청 예제·응답은 SSD `runs/service-followup-cli-v1`, 날짜별 스냅샷은 `runs/pitch-refresh-20250816-v1`, 평가·선택·검증 결과는 `runs/service-validation-v2`에 보존했다. 첫 실패 평가기는 `runs/service-validation-v1`에 남겨두었다.

프로젝트 루트에서 검증한 요청을 다시 실행할 수 있다.

```sh
.venv/bin/python experiments/pitchmdp/scripts/refresh_pitch_service.py recommend \
  --snapshot '/Volumes/T7 Shield/pitcheezy/pitchmdp/runs/pitch-refresh-20250816-v1' \
  --calibration '/Volumes/T7 Shield/pitcheezy/pitchmdp/runs/service-validation-v2/calibration.json' \
  --request '/Volumes/T7 Shield/pitcheezy/pitchmdp/runs/service-followup-cli-v1/request.json'
```

위 보정 파일은 `accepted=false`이므로 기존 모델을 그대로 사용한다.

다음에는 모델 종류나 군집 수를 늘리기보다 **실제 갱신 CLI의 구종 제한·프로필을 그대로 적용한 정책을, 초반/후반과 주자 상황별로 같은 사례에서 비교**하는 것이 우선이다. 그때도 예측 개선과 추천 효과를 분리한다. 현재 CLI는 연구 MVP로 사용하고, 현실 승률을 높이는 모델이라는 결론은 보류한다.
