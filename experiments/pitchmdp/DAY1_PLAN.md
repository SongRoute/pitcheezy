# 24시간 방향 확인 파일럿

**착수 후 업데이트:** 첫 결과는 10분 55초, 사용자 의견을 반영한 MLB 전체·타자 유형
수정 실험은 약 21분에 완료했다. 최신 범위·실험·한계는 [REVISED_PILOT.md](REVISED_PILOT.md).
아래 LAD 선정 규칙은 최초 실행의 계약 기록으로 보존한다.

2026-09-21 사용자 요청 반영. 이번 세션은 초기 세팅, **다음 세션 본격 착수부터 6시간 이내(가능하면 더 빨리) 첫 결과, 24시간 이내 방향 판단**을 목표로 둔다. 장기 목표는 RESEARCH_CHARTER.md를 유지한다.

## 대상

- **투수: LA 다저스 선발 등판 이닝 상위 4명.**
- **타자: 제한 없음.** 해당 투수들이 상대하는 타자를 모두 다룬다. 데모용 타자 4명, 선수 유형별 할당, 타자 개인 최소 표본 같은 별도 선정 기준은 만들지 않는다.
- 선수 선정의 이닝 기준 기간은 사용자 확정에 따라 학습 가중치 기간인 **2023-05-15~2025-04-30**이다. 해당 기간 LAD 선발 등판에서 기록한 아웃 수를 합산해 순위를 정한다. 현재 시즌 로스터 또는 2026 이닝 순위라는 의미가 아니다.
- 다른 팀 소속 등판과 LAD 불펜 등판은 이닝 순위에서 제외한다. 이적/말소 여부 등 현재 로스터 조건은 추가하지 않는다. 동률이면 같은 기간 LAD 선발 등판 수, 그다음 MLBAM ID 순으로 결정한다.
- 실제 명단은 데이터 집계 후 기간·선발 경기 수·아웃 수·이닝과 함께 기록한다. 투구 수를 이닝의 대용으로 쓰지 않는다. 순위 경계의 이닝 복원이 불확실하면 그 사실을 확인한 뒤 명단을 고정한다.
- 평가도 해당 투수들의 LAD 선발 등판을 대상으로 한다. 선수 선정에는 평가 기간 결과를 쓰지 않는다. 후속 기간에 표본이 부족한 선수가 있어도 임의 교체하지 않고 표본 부족으로 보고한다.
- 공유 결과 모델·WE 모델·리그 사전분포에는 더 넓은 리그 학습 데이터를 사용한다. 네 투수와 일부 타자의 직접 맞대결 기록만으로 모델을 학습하지 않는다.
- 타자 개인 이력이 부족하면 리그/좌우 사전분포와 결측·표본 수 표시를 사용한다. 데이터 품질상 제외한 행/타석과 타자 선정 제한을 구분한다.

## 24시간 뒤의 산출물

1. 선수 4명과 학습/평가 표본·제외 내역이 고정된 manifest.
2. 상대 타자·카운트·앞선 공·경기 상황을 받아 구종×목표 위치의 top-k를 출력하는 실행 가능한 경로.
3. 타석 종료 이후 승리 확률을 연결한 간단한 정책과, 같은 모델의 myopic/단순 보상 비교.
4. 실제 평가 타석에서의 예측 지표·추천 요약·대표 히트맵, 속도·메모리 기록.
5. 초기 방향 메모: 어떤 조건에서 추천이 달라지는지, 어떤 가정에 민감한지, 다음 하루에 해결할 병목.

이 단계의 방향 판단은 추천 계산이 작동하고 기초 검증을 통과하는지에 관한 것이다. 기존 논문 대비 현실 정책 개선의 통계적 입증은 후속 단계다.

## 시간 배분

| 경과 시간 | 작업 | 남길 증거 |
|---|---|---|
| 0–2h | 초기 세팅 재점검, LAD 선발 이닝 집계, 네 선수 선정, 원본/분할 고정 | cohort manifest, 데이터 보고서 |
| 2–6h 이내 | 작은 실제 표본의 as-of 피처→경량 결과 모델→종결 상태/WE→타석 MDP→추천/평가 연결 | 첫 추천·예측 평가, 누수/손계산 솔버 검사 |
| 6–14h | 네 투수로 확대, Full/−B/−C 및 같은 모델의 보상·계획 범위 비교 | 실험별 성능·소요 시간·실패 내역 |
| 14–20h | 유망 후보 재학습, 확률 보정·지원 범위·제구 민감도 점검 | 반복성·불확실성·취약 상황 |
| 20–24h | 사례 분석, 재실행 확인, 방향 메모 | DAY1_REPORT 및 재실행 명령 |

시간은 작업 상한을 나누기 위한 계획이다. 중간 목표 미달이면 모델 복잡도·그림 개수를 줄이고, 어떤 항목이 미완료인지 보고한다.

## 6시간 첫 결과의 최소 기준

- 네 선수의 선정 근거를 고정하고, 우선 한 명의 실제 타석에서 실행 경로를 확인한다.
- 작은 실제 학습 자료의 결과 모델과 시간상 분리된 검증 자료의 예측 지표를 제시한다. 평가 기간과 표본 수를 함께 적는다.
- 카운트·타자·앞선 공·경기 상황을 받아 구종/목표 위치 후보와 타석 이후 수비 팀 승률 기준의 가치를 출력한다.
- 단순 기준 정책과 비교하되, 모델 내부 전략 가치와 관측 예측 성능을 별도로 적는다.
- 누수·확률 질량·보상 부호·작은 정답 솔버 검사를 통과한다. 미지원 사건과 제구 가정을 명시한다.
- 예시 입력, 출력, 재실행 명령, 미완료 항목을 기록하고 즉시 검토를 요청한다. 6시간까지 일부 미완료라면 진행 증거와 병목을 보고한다.

## 유지할 것과 줄일 것

- 유지: 승리 확률이라는 목적, 시간 분할/as-of, 타석 종료 전후 상태의 의미, 실제 목표와 도달 위치 구분, 핵심 수학·누수 검사.
- 단순화: 하나의 경량 결과 모델, 짧은 투구 이력, 제한된 격자, 한 학습 시드, 최소한의 타자 개인 피처, 명시적인 제구 근사.
- 연기: 긴 Transformer, 다중 모델 탐색, 모든 논문 재현, 대규모 sequential OPE, 재학습 bootstrap, full 목표 정책의 인과 효과 주장, UI·실시간 API·책임 분해.
- WE 연결이 구현되지 않으면 그 항목을 미완료로 적는다. 상황 중립 보상만 구현한 결과를 승리 확률 목적 달성으로 표시하지 않는다.
- 미지원 주루/특수 사건·경기 종료 규칙은 명시하고 표본 커버리지를 보고한다. 단순화 가정에 따른 결과임을 표시한다.
- 같은 모델이 산출한 정책 이득은 내부 진단이다. 결과 예측의 held-out 검증과 구분한다.

## 실행 환경

- 이번 24시간은 M4 24GB 사용. 9/23부터 가능한 3080 서버를 선행 조건으로 기다리지 않는다.
- 새 코드는 기존 pitcheezy와 분리한다. 설치 변경을 최소화하고 기존 실행 환경을 훼손하지 않는다.
- 첫날은 기존 `.venv`를 재사용하고 설치 버전을 기록한다. 별도 환경/lockfile은 의존성 변경이나 서버 이관 전에 준비한다.
- JSON 결과 파일과 기존 W&B offline 로깅을 우선 사용한다. MLflow 신규 도입은 첫날 이후 검토한다.
- 학습은 한 번에 하나, 짧은 선별 실행 후 후보에 추가 예산을 배정한다. 실행 코드·설정·seed·데이터 분할을 결과와 연결한다.
- 데이터·모델·캐시는 `/Volumes/T7 Shield/pitcheezy/pitchmdp`에 둔다. 내장 공간 부족을 이유로 사용자 파일을 임의 삭제하지 않는다.
- 2023–2025 허용 입력만 사용하며 2026 원본은 열지 않는다.

## 첫날 이후 판단

- 데이터·솔버가 맞고 추천/예측이 해석 가능하면 공통 기준선과 B·C·D 절제로 확대한다.
- 예측이 부족하면 결과 모델·타자 피처부터 개선한다.
- WE/제구 가정에 추천이 지나치게 흔들리면 그 부분을 먼저 보강한다.
- 표본·검증이 부족하면 성능 실패와 구분해 ‘판정 불충분’으로 남긴다.
