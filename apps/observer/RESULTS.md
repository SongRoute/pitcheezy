M4 로컬 CPU4스레드, 동결된5개 모델, 재학습 없음.

- 전체78구 추천 확인 프로세스: 약**2.51초**, 최대 RSS 약**357MiB**.
- 추천 계산/캐시 혼합 지연: 중앙값**0.875ms**,95백분위**73.76ms**, 최대**75.08ms**. 모델 초기 로드 시간은 개별 추천 지연에 포함하지 않는다.
- 준비된 캐시를 사용한 API176요청: 중앙값**8.42ms**,95백분위**10.71ms**, 최대**16.17ms**.

이 수치는 작은 로컬 데모의 측정치다. 다중 사용자 부하나 실제 영상 처리 지연을 측정한 것은 아니다.

## 구현과 검증의 경계

- 위치 추천은 TRAIN joint delivery400개를 구역 주변으로 재가중한 근사다. 실제 목표 위치 개입이나 투수 제구 모형을 검증한 결과가 아니다. 유효 표본 수뿐 아니라 절대 커널 질량으로 먼 구역의 허위 지원도 차단한다.
- 화면의 승률 차이는 모델 내부 비교다. **추천을 따르면 실제 경기 성능이 좋아진다는 결론은 아직 없다.** 기존 예측·정책 연구의 불확실성은 그대로 남긴다.
- CV는 마지막1구를 선택하는 작업 처리·어댑터까지 연결했다. 영상이 없어 자동 미트/의도 인식은 수행하지 않았다. 수동 목표는 사용자의 메모이며 실제 의도 라벨로 간주하지 않는다.
- 타자 이름 대신 MLB ID를 표시한다. 컨디션 모듈은 누적 투구 수를 제공하는 첫 단계다. 구위 변화·타순 회차·불펜 비교는 후속이다.
- 운영 PostgreSQL 대신 SQLite를 사용했다. 신경망·진루·가치 모델과 기존 실험 환경을 보존했다.
