# Codex–Claude 협업

상위: [운영 진입점](pm/overview.md) · 지침 정본: [AGENTS](../AGENTS.md)

두 도구는 같은 AGENTS를 읽는다. CLAUDE는 `@AGENTS.md` import만 유지한다. 도구별 정책 복사본이나 별도 역할 연혁을 이 문서에 두지 않는다. nested instruction의 검색·로딩 방식은 도구마다 다를 수 있으므로 새 범위 지침을 도입하면 실제 세션에서 확인한다.

## 이번 전시 작업

Song의 10/31 작업 지시에 따라 Codex는 검토·구현·검사·문서·PR을 수행한다. Opus 검토·통합 책임은 [관리 세션 안내](handoffs/OPUS-github-manager-prompt-2026-10-31.md)를 따른다. 실제 담당·활성 여부는 [작업큐](pm/work-queue.md)에서 확인한다. PR 생성은 merge·운영 배포 완료가 아니다.

역할 이름만으로 과거 모델 제한이나 GPU 권한을 되살리지 않는다. 작성자·검토자와 실제 사용 도구를 기록하고, 같은 모델의 다른 에이전트 검토와 다른 모델 검토를 구분한다. 위임된 에이전트도 배정된 파일·자료·실행 범위를 넘지 않는다.

## 인계할 증거

[작업 절차](pm/workflow.md)에 따라 고정 커밋·diff, 실제 검사 명령/결과, 생성한 산출물의 위치·해시, 남은 실패·미측정·자원·소유권을 전달한다. 세션의 성공 반환만으로 완료라 하지 않는다. 같은 파일/index의 동시 작성을 피하고 활성 작업의 명시 반환을 확인한다.

CLI 하위 작업이 필요하면 기존 `scripts/run_claude_task.py`의 감독·새 attempt 경로를 재사용한다. 오류·시간 초과·결과 부재를 성공으로 기록하지 않는다. 과거 시도를 덮지 않는다. 요청한 모델 이름만으로 실제 응답 모델을 확인했다고 주장하지 않는다.

과거 D68~D100 역할·COOP 기록 및 오래된 운영 체제는 [고정 원문](maintenance/instruction-history.md)에 보존된다. 연구의 실제 상태는 각 등록·manifest·실행 보고서가 결정하며, 문서 정리가 기존 실험 계약을 변경하지 않는다.
