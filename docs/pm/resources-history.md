# 자원 관측 이력

현행 규칙: [resources](resources.md) · 현재 점유 확인: [작업큐](work-queue.md)

기존 15,496자 자원 문서는 날짜별 승인·PID 관측·실행/검토 근거가 누적된 기록이다. 원문은 [전체 고정 커밋 6e2038fd](https://github.com/SongRoute/pitcheezy/blob/6e2038fd0010657e6f6f2d1e49820490f6195da4/docs/pm/resources.md)에 보존한다. 당시 숫자·주소·로컬 증거 경로를 수정하거나 현재 관측처럼 다시 적지 않는다.

원문의 탐색 순서는 다음과 같다.

| 시점 | 확인할 이력 |
|---|---|
| 10/11 체크포인트 2 | 수집/reader 종료와 당시 보호 운영 PID |
| 10/11 PM 인수 | GPU 5장 허용·기록기 우선·이전 슬롯 제한 종료 |
| 10/11 05:31·04:46·02:13 | post-capture arming, WAITING_CAPTURE, 소형 합성 검사 범위, 메모리 사고와 경계 |
| 10/10 | 유한 GPU 권한 해석·만료 정정, P47 실행·bridge 검토/수용 |
| 10/09 | 조건부 UUID 후보, A/B/C CPU 종료, 별도 CLI 슬롯과 프로세스 관측 |
| 10/06 | 5 GPU 승인·큐 구현 후보, MPS/시연 보호, 포트·DB 경계와 한시 적용 |

[10/31 점검 종료 기록](https://github.com/SongRoute/pitcheezy/issues/37#issuecomment-6536549232)은 그날의 GPU 관측·기존 점유 해제 대조다. 자료/모델 payload·fit 없이 수행됐고 새로운 실험을 실행한 기록이 아니다. 이후 작업에서 현재 점유를 새로 확인해야 한다.

길이 예외는 이 고정 원문과 과거 실행 증거의 보존을 위한 것이다. 현행 자원 안내를 다시 길게 누적하지 않는다. 새로운 관측은 날짜·소스·범위·제한을 갖춘 별도 작업 기록에서 연결한다.
