# D-UI-004 — 모바일 한 화면 틀: 시안과 판단 기록

2026-10-02 (D135). 코드 변경 없음(시안·문서만). 시안: <https://claude.ai/artifact/NdXoDTZzazFgcXscKpbnUx> (비공개 캔버스, 21장).
레퍼런스는 [frontend-references.md](../frontend-references.md), 실시간 서비스의 시간·속도 쪽은 [LIVE-service-plan.md](LIVE-service-plan.md)(다른 세션 작업)를 따른다.

**틀은 확정됐다(D140, §15). 상세 디자인(색·글꼴·아이콘)은 아직 정하지 않았다.** 시안은 지금 데모(`demo/ws-2026`의 `watch-along.css`) 색을 임시로 빌렸다. 이 문서가 정하려는 것은 배치와 화면 전환 규칙이다.

## 1. 사용자가 정한 것 (2026-10-02 대화)

1. 경기 첫 화면은 **스크롤 없이** 모든 정보가 한 화면에 나온다. 야구장이나 TV 앞에서 폰으로 본다. 정보는 최대한 추리고, 추가 정보는 눌러서 본다.
2. 대상은 iPhone 17과 Galaxy S26의 웹 브라우저(사파리, 삼성 인터넷, 크롬).
3. AI 서비스이므로 **상황에 맞게 화면이 전환**된다.
4. **실시간 정보가 주**이고, 지난 순간을 찾아보는 것은 부수 기능이다.
5. 웹페이지는 세 흐름이다: ① 홈(경기 선택) ② 경기 페이지(주, 실시간) ③ 지난 경기 분석(보조).
   - 홈: 실시간 경기를 위에, 최근 끝난 경기를 아래에. 지난 경기 검색.
   - 경기 페이지: 간단한 투타 정보, 경기 기본 정보(박스 스코어 등), 핵심인 추천 구종·위치, 가벼운 설명.
6. 상세 디자인은 나중에. 지금은 배치를 레퍼런스를 참고해 여러 개 뽑고, 추가 판단은 Claude가 하고 기록한다.

## 3. 세 흐름

| 흐름 | 주소(제안) | 지금 데모에서 대응 | 시안 |
|---|---|---|---|
| ① 홈 | `/` | `/watch` 경기 목록 | H1, H2 |
| ② 경기 페이지(주) | `/game/{경기}` | `/live?game=` | A0~A9, B, C, D |

## 4. 경기 페이지 A안 — 존 무대 (추천안)

스트라이크존이 늘 같은 자리에 있고, 그 위·아래 내용만 상황에 따라 바뀐다. 체스 복기 화면에서 판이 고정된 것과 같은 원리다.

```
┌────────────────────────────────┐
│ ←  ● LIVE 중계와 맞추기  실험판 ⋯ │ 44   상단 줄
├────────────────────────────────┤
│   필라델피아 1 : 0 애틀랜타      │
│   2회 초 ●●○ ◇ 0-2 3구째        │ 약 120  점수판 + 투타 한 줄씩
│   투수 Sale 31구째 │ 타자 Sosa   │
├────────────────────────────────┤
│ [다음 공 추천] 모델 추정         │
│ 슬라이더                        │
│ 낮은 오른쪽으로                  │ 남는 높이 전부  무대
│ 평소에도 가장 자주 던진 공 …     │
│        ┌──┬──┬──┐               │
│        ├──┼──┼──┤  존           │
│        └──┴──┴■─┘               │
├────────────────────────────────┤
│ [1 슬라이더][2 슬라이더][3 ?]    │ 48   이 타석 공 순서
├────────────────────────────────┤
│ [자세히] [박스 스코어] [지난 장면]│ 60   눌러서 보는 것
└────────────────────────────────┘
```

402×681에서 무대 높이는 약 409px, 360×620(가정)에서는 약 364px이다. 시안은 실기기에서 렌더 검증하지 않았다.

### 상황 다섯 가지와 전환

손을 대지 않아도 무대가 바뀐다. 지금 `Live.tsx`가 받는 상태값에 그대로 대응한다.

| 상황 | 언제 | 무대에 나오는 것 | 시안 |
|---|---|---|---|
| 투구 전 | 다음 공 추천이 준비됨(`ready`) | 추천 구종, 목표 위치, 한 줄 설명, 존의 목표 칸 | A1 |
| 투구 후 | 공 결과가 도착함 | 실제 구종·구속·결과, 추천과 같음/다름, 존에 목표와 실제 | A2 |
| 중요 사건 | 타석이 끝남(삼진·홈런·볼넷 등) | 결과, 수비 팀 승리확률 변화, 기여 막대 자리 | A3 |
| 대기 | 이닝 교대·준비 중(`between_innings`, `buffering`) | 다음 투타, 지난 이닝 요약 | A4 |
| 추천 없음 | 기록이 부족한 투수(`unsupported`) | 이유, 빈 존. 실제 공은 계속 보여 줌 | A5 |

"투구 후"를 얼마나 보여 줄지: 추천 계산이 0.12~0.17초라 그냥 두면 공 결과가 바로 다음 추천에 덮인다. 그래서 **공 결과를 약 6초 붙잡아 둔 뒤 다음 추천으로 넘긴다**(제안값, 미검증). 공 사이 간격이 짧은 쪽(15.2초)에서도 다음 공 전에 추천이 9초쯤 떠 있게 된다. 결과는 아래 공 순서 줄에 계속 남는다.

## 5. 다른 구성

| 안 | 한 줄 설명 | 좋은 점 | 아쉬운 점 | 바탕 |
|---|---|---|---|---|
| **A 존 무대** | 존 고정, 내용이 상황별로 바뀜 | 추천과 실제를 같은 그림에서 비교. 손 안 대도 됨 | 한 번에 한 가지만 보임. 전환에 익숙해져야 함 | 체스 복기, Savant |
| B 큰 글씨 카드 | 구종 이름을 아주 크게, 존은 구석에 작게 | 팔 뻗은 거리·야외에서 가장 잘 읽힘. 지금 데모와 비슷해 작업량이 적음 | 존이 작아 위치 비교가 약함. 투타 정보가 한 줄로 줄어듦 | 중계 자막 |
| C 위아래 분할 | 다음 공, 방금 공, 경기 흐름을 한꺼번에 | 전환이 거의 없음 | 글자가 작고 빽빽함. S26 높이에서 빠듯함 | Gameday 타석 화면 |
| D 아래 탭 | 추천·투타·박스 스코어·지난 장면을 탭으로 | 박스 스코어가 늘 한 번에 닿음. 익숙한 앱 구조 | 탭 줄이 항상 52px를 차지. 다른 탭에 있으면 자동 전환을 놓침 | 스포츠 앱 경기 화면 |

추천은 A. 사용자가 정한 "한 화면, 상황에 맞게 전환, 실시간이 주"에 가장 곧게 맞고, 로드맵의 세 질문(다음 공, 실제 공, 중요 사건)이 같은 자리에서 차례로 답해진다. B의 큰 글씨는 A의 구종 이름 크기를 키우는 식으로 나중에 섞을 수 있다.

## 6. 홈과 지난 경기 분석

- **H1 목록형**: 지금 경기 → 최근 끝난 경기 → 맨 아래 검색. 가장 단순하다.
- **H2 라이브 크게**: 실시간 경기 카드에 현재 상황과 "실시간 추천 보기" 버튼, 끝난 경기는 날짜 띠로 고른다. 실시간 경기가 하나일 때 좋다.
- **P1 요약과 승부처**: 최종 점수, 이닝별 점수, 추천을 낸 공 수, 승리확률이 가장 크게 움직인 장면 셋. 여기서 그래프나 한 공씩 보기로 간다.
- **P2 승리확률 그래프**: 경기 전체 승리확률 선, 점을 누르면 그 장면의 추천과 실제.
- **P3 한 공씩 다시 보기**: 경기 페이지와 같은 틀. 회 버튼으로 이동. LIVE-service-plan의 "실제 속도로 다시 보기"도 이 화면에 붙인다.

홈은 H1, 분석은 P1을 첫 화면으로 추천했고, 사용자가 H1(가운데 정렬·날짜 묶음·점수 표시로 수정)과 분석 화면을 받아들였다(§12).

## 8. 구현할 때 지킬 틀 규칙 (제안, 미검증)

- 화면 전체 높이는 `100svh`. 주소창이 보이는 상태의 높이라서 넘치지 않는다. 삼성 인터넷에서의 동작은 실기기 확인이 필요하다.
- 본문은 `overflow: hidden`, `overscroll-behavior: none`. 스크롤은 아래에서 올라오는 판 안에서만.
- 세로 배치는 고정 높이 줄(상단 44, 점수판, 공 순서 48, 버튼 60)과 남는 높이를 전부 쓰는 무대 하나. 존은 무대에 맞춰 줄어든다.
- 아이폰 아래 홈 표시 줄은 `env(safe-area-inset-bottom)`만큼 띄운다.
- 누르는 것은 모두 44px 이상.
- 화면이 꺼지지 않게 하는 기능(Wake Lock)과 다크 모드는 상세 디자인 때 정한다.

- **지난 장면**: 이 화면을 연 뒤에 본 공만 돌아볼 수 있다. 그 전의 공은 지난 경기 분석(5단계)에서 다룬다.
- **투타 한 줄**: 타자의 "오늘 몇 번째 타석"은 응답에 없어 좌타·우타만 쓴다.
- **박스 스코어 판**: 현재 점수와 지금 투수의 구수만 있다(3단계).
- **높이 560 이하**: 공 순서 줄과 꼬리표를 숨긴다(F10).

아직 확인하지 않은 것:

- 실기기(iPhone 17, Galaxy S26)와 사파리·삼성 인터넷. 검사는 Chromium뿐이다.
- 실제 서버와 붙인 동작. 오늘 실경기를 측정 중인 8766·8769에 요청을 보내지 않으려고 모의 응답만 썼다.
- 공 결과를 붙잡는 시간(6초, 10초)이 실경기 흐름에 맞는지.

### 같은 날 추가 (실시간 서비스 쪽 변경 반영)

실시간 서비스 세션이 실경기 849844 측정을 마치고 백엔드를 바꿨다. `demo/ui-frame`에 `demo/live-sync` `4452331`을 합치고(`37e3931`) 한 가지를 고쳤다(`5056209`).

- **새 상태 "결과 확인 중"**: 삼진·볼넷·타구 직후 결과가 올라오기 전 약 10초 동안 서버가 `resolving` 상태를 준다. 고치기 전에는 이 상태를 쉬는 시간으로 취급해서, 그 뒤에 와야 할 "타석 끝" 화면이 뜨지 않았다. 이제 "결과 확인 중" → "타석 끝" → 다음 추천 순으로 이어진다. 검사에 이 장면을 넣었다.
- **전환 시간에 관한 실측**(849844, 277구, 실시간 서비스 세션 측정): 공을 놓은 뒤 기록이 뜨기까지 중앙값 19.2초, 공과 공 사이 중앙값 20.5초. 그래서 중계 지연을 짧게 맞춘 시청자에게는, 공 결과를 6초 보여 주는 동안 다음 공이 이미 던져졌을 수 있다. 붙잡는 시간(6초·10초)은 실기기에서 보면서 다시 정해야 한다.
- 서버가 새로 주는 "추천과 같은 구종 수"(`tally`)는 새 화면에 넣지 않았다. 성능처럼 읽힐 수 있어서다(§13 주의).
