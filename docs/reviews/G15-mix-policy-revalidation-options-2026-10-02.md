# 혼합 예측 후보(G15 mix)로 추천 정책을 다시 검증할지 — 설계안 (2026-10-02)

상태: **제안, 미등록, 실행 0.** 사용자 결정을 받기 위한 문서다. 수치는 [results-all.md](../results-all.md)와 [decisions.md](../decisions.md)에서 옮겼고, 새로 잰 것은 없다. "추정"이라고 적은 것은 측정이 아니다.

## 1. 지금 상태

- 예측: 직접 head와 G0를 1/2씩 섞은 후보가 5 seed 확인을 통과했다(D143). G0 대비 ΔNLL은 패널 −0.003442 [−0.005032, −0.001894], 전체 MLB −0.004062 [−0.004383, −0.003752].
- 연구 기준: 이 후보를 예측 연구의 기준으로 올렸다(D145, `configs/G15-MIX-RESEARCH-FROZEN-v1.json`).
- 추천 정책: 그대로다. 정책 식별자 `c13cc989…`(G0 + τ 0.1 P3)이고, 2026 평가는 "개선 근거 없음"이었다(D131, 차이 범위 [−0.00120, +0.00092] 승리확률/타석).

## 2. 정책에서 무엇이 바뀌나

추천 정책은 "이 구종을 던지면 결과가 어떨까"를 예측기에 물어 타석을 미리 굴려 보고 구종을 고른다. 그 예측기를 G0에서 혼합 후보로 바꾸는 것이다.

- 예측기가 바뀌면 정책 식별자가 바뀐다. 그래서 인증 사슬을 다시 돌려야 한다.
- 다시 해야 하는 단계: 부품 연결 확인(S2) → τ 다시 고르기(S3b, 예측기가 바뀌면 필수) → 추정기 자체 검사(S5) → 본 평가(S6).
- 다시 안 해도 되는 단계: 자료 세기(S0), 실제 투수 흉내 정책 저장(S1·S1b), 평가 분모(S4). 예측기와 무관하다(D122 선례).
- 새로 짜야 하는 코드: 혼합 예측기를 정책 런타임과 식별자에 연결하는 부분. 지금 런타임은 G0만 받는다.

## 3. 비용 (앞선 실행의 실측)

- S3b τ 선정: 2,179초
- S5 추정기 검사: 2,900초
- S6 본 평가(2025년 DEV 150경기): 3,776~3,808초
- 합계 약 8,900초(약 2.5시간), 맥미니, 최대 메모리 6.8~8.4GB
- 2026 전체 시즌 평가를 다시 한다면 47,828초(약 13.3시간)
- 새 연결 코드 작성·테스트·검토 시간: 미측정

## 4. 기대치 (추정)

판정이 바뀔 가능성은 낮다고 본다. 근거는 세 가지다.

- 9월 P1 실험에서 예측 NLL이 1.2100 → 1.176으로 크게 좋아졌는데도 추천 평가는 구분되지 않았다. 이번 개선 폭은 그보다 훨씬 작다.
- τ 0.1 정책은 실제 투수의 선택과 매우 가깝다(평균 KL 0.0074). 예측기가 조금 바뀌어도 추천이 거의 같을 수 있다.
- 2026 평가의 차이 범위는 이미 ±0.001 안쪽이다.

다만 이것은 추정이다. "예측기를 바꾸면 추천이 실제로 얼마나 달라지는가"는 아직 잰 적이 없고, 아래 단계 B가 그것을 싸게 잰다.

## 5. 제안: 단계를 나눠 싸게 먼저 확인

**단계 A — 연결** (코드, 실행 약 1분)
- 혼합 예측기를 정책 런타임·식별자에 연결한다. 별도 브랜치에서 작업해 데모가 쓰는 식별자는 건드리지 않는다(D118 선례).
- 합성 테스트와 S2 확인(정책 경로의 예측이 평가 경로와 64행에서 1e-6 안으로 같은지).

**단계 B — 추천 변화 진단** (약 36분, 경기 결과는 보지 않음)
- 6월 150경기(τ 선정 표본, 43,487결정)에서 같은 τ 0.1로 G0 정책과 혼합 정책의 구종 분포를 비교한다.
- 지표: 결정마다 두 분포의 차이(TV 거리) 평균, 1순위 구종이 같은 비율.
- 중단 규칙(결과를 보기 전에 고정): 평균 TV < 0.01 이고 1순위 일치율 ≥ 98%이면 "추천이 사실상 같다"로 기록하고 여기서 끝낸다. 문턱 두 개는 판단값이며 측정 근거가 없다. 승인할 때 바꿀 수 있다.
- 미확인: 기존 G0 τ 실행이 결정별 분포를 저장해 두었는지. 없으면 G0 쪽도 다시 계산해야 해서 약 36분이 더 든다.

**단계 C — 2025년까지 리허설** (약 1.9시간 추가)
- 단계 B에서 추천이 의미 있게 달라질 때만 진행한다.
- τ 확정 → S5 → S6. 판정 규칙·문턱은 기존 등록(D108·D109·D119·D120)을 그대로 쓴다.
- 주의: 혼합 후보는 같은 2025년 7~9월 자료에서 예측 성능으로 골랐다. 리허설이 그 자료 위에서 돌므로 약간 낙관적일 수 있다.

**단계 D — 2026 재평가** (지금은 하지 않음)
- 2026 자료는 이미 한 번 평가에 썼다. 후보를 바꿔 다시 평가하면 "여러 후보 중 좋은 것 고르기"가 되어 한 번만 쓴다는 원칙이 깨진다.
- 단계 C의 리허설 라벨이 "개선"일 때만 별도 결정으로 올린다. 그때는 두 번째 열람이라는 사실과 유의수준 보정(예: 절반)을 사전등록에 넣는다.
- CLAUDE.md의 "이번 ML 개발에서 2026은 추가 열람하지 않는다"를 바꾸는 결정이 따로 필요하다.

## 6. 검토 게이트

- 정책 런타임 코드가 바뀌므로 기존과 같은 두 게이트(코드 검토, 독립 검토)가 필요하다.
- 지금까지 독립 검토는 Fable 5.1이 맡았다. 이번 코드는 Fable 5.1 세션이 쓰게 되므로, 같은 모델의 검토는 독립 검토가 아니다. 누가 독립 검토를 할지는 사용자가 정한다.

## 7. 선택지

1. **단계 A·B까지 승인하고, 진단 결과를 본 뒤 C를 정한다(추천).** 가장 싼 방법으로 "추천이 달라지기는 하는가"부터 확인한다. 달라지지 않으면 2.5시간짜리 사슬과 검토를 아낀다.
2. 단계 A~C를 한 번에 승인한다. 결과는 빨리 나오지만, 추천이 거의 같을 경우 리허설이 같은 답을 다시 내는 데 시간을 쓴다.
3. 정책 재검증은 보류한다. 포수 셋업(의도) 자료가 와서 목표 위치까지 추천하는 ARM-A를 설계할 때 예측기 교체를 함께 넣는다.
