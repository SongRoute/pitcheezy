# P47 execution wiring — prepared, not run

This packet is code for a later reviewed attempt. It does not register P47, read real data, query a GPU, run a fit, or score DEV. The fixed undated DRAFT remains `configs/DRAFT-CUDA-BATTER-DROPOUT-20261006.json` (SHA256 `b2ca6336…`). `run_cuda_direct.py --smoke` explicitly refuses P47 because that legacy path reads DEV payloads.

1. Stage a reviewed source commit and the pinned export plus its sibling batter sidecar on newsrv. Obtain the research PM's source/protocol acceptance and the recorder's current ID/seed check. Do not treat the older DRAFT phrase “P44 reserves 75–79” as a global ledger claim: P44's actual DRAFT uses 49–53. P47 seeds 80–83 still require a fresh global reservation before registration.
2. On the staged checkout, use `make_p47_probe_spec.py` to write a **new** spec with its DRAFT config, export path, Python path, new output path, independent-review evidence path and ledger-review evidence path. Review the exact spec and its source/config/data hashes. It declares 16 two-epoch subset tasks (all arms × seeds) and one two-epoch full-TRAIN zero-UNK arm task. The spec names GPU3 only, one slot, the common exclusive lock, and registration/run paths that must still be absent.
3. After separate authorization, run `scripts/p47_probe.py SPEC OUT` on newsrv. The supervisor binds each child to `CUDA_VISIBLE_DEVICES=GPU-c334d905-8ec9-0029-b206-46ce3ac49cd9`, uses the shared lock, and queries that UUID only. The child verifies manifest/sidecar metadata, hashes and loads **only TRAIN and earlystop arrays**, fits without calibration or prediction, and records source/data/input/model hashes, modes, exact-zero rows, timing and peak memory. `OUT/check.json` must say `valid: true`; abort/refusal consumes that attempt path.
4. After PM review of the probe, use `p47_launch.py date DAY HH:MM CHECK NEW_DATED_DRAFT` to set a same-day window allowing measured probe wall time + 4,894 seconds fit projection + 900 seconds stop grace + 1,200 seconds scorer/report reserve. Recheck source/config/export/sidecar pins, GPU ownership, budget and current global ledger. The recorder must issue a fresh `ledger_review` JSON with `experiment_id=EXP-P47-001`, `seeds=[80,81,82,83]`, `reserved=true`, and timezone-aware `checked_kst` within 15 minutes of registration; this packet creates no such reservation. `p47_launch.py register DATED_DRAFT CHECK HH:MM SOURCE_COMMIT GO_REFERENCE LEDGER_REVIEW NEW_REGISTERED_CONFIG` requires the exact current checkout HEAD and the PM go file. It writes only a new registered config and preserves the inherited 3,600-second task cap, 36,000-second family cap and two attempts.
5. After registration and a distinct review of this wiring, stage the registered config and run `run_p47_pipeline.py` with its required named arguments. Its first payload stage hashes the full frozen <=2025 export/sidecar **after registration**, recorded as a separate exposure stage. It checks GPU3 compute apps with `--id=<GPU3 UUID>`, then launches the existing durable serial `cuda_direct_queue.py` with exactly one GPU and the common lock. The wrapper refuses a second start; the queue persists task states and bounded retries. The scorer starts only after the queue reports `{'done': 16}` and every expected arm/seed output passes `verify_task` seal checks. A partial family, missed deadline, interruption or preexisting artifact is not scored. A failed wrapper or queue needs manual owner review before any new attempt or queue restart; it never silently restarts/scorers beside an uncertain child.

The P47 DEV analysis remains exploratory after repeated exposure. No automatic scientific verdict, model promotion, service policy change or 2026 training/model-selection use is created by this packet.
