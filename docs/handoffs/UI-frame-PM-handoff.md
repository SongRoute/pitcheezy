# 화면(프론트엔드) 인수인계 — 새 PM용

2026-10-02 작성. 이 문서 하나로 화면 작업의 현재 상태를 파악할 수 있게 썼다.
결정이 나온 순서와 배경은 [D-UI-004-frame.md](D-UI-004-frame.md), 참고한 서비스는 [frontend-references.md](../frontend-references.md), 결정 한 줄 기록은 [decisions.md](../decisions.md)의 D135~D142에 있다.

## 1. 한눈에

- **무엇**: 야구 중계를 보면서 폰으로 여는 화면. 다음 공의 추천 구종과 위치를 먼저 보여 주고, 공이 들어오면 실제와 비교한다.
- **어디까지**: 화면 틀(배치와 전환 규칙)은 사용자가 확정했다. 세 화면 가운데 **경기 페이지만 구현**됐고(1·2단계), 홈과 지난 경기 분석은 시안만 있다.
- **지금 볼 수 있는 것**: 구현된 경기 페이지는 `http://100.108.252.111:8770/game?game=849844&replay=0` (Tailscale에 연결된 기기에서만). 시안은 <https://claude.ai/artifact/NdXoDTZzazFgcXscKpbnUx> (사용자 계정의 비공개 캔버스. 다른 사람이 보려면 사용자가 공유해야 한다).
- **멈춘 지점**: 사용자가 실제 폰(iPhone 17, Galaxy S26)에서 경기 페이지를 보고 의견을 주기로 한 상태에서 세션을 닫았다. 그 의견이 다음 일의 출발점이다.
- **색·글꼴은 미정**: 사용자가 "상세 디자인은 나중에"라고 했다. 지금 색은 기존 데모 것을 임시로 쓴 것이다.

## 3. 화면별 현재 상태

| 화면 | 확정된 틀 | 시안 | 구현 |
|---|---|---|---|
| ① 홈 | 목록형. 가운데 정렬. 위에 지금 경기, 아래에 지난 경기 | H1 | 없음 |
| ② 경기 페이지 | 존 무대 + 아래 버튼 셋 | A0~A10 | **1·2단계 완료** (`/game`) |
| ③ 지난 경기 분석 | 요약과 승부처 → 승리확률 그래프 → 한 공씩 다시 보기 | P1~P3 | 없음 |

시안 캔버스는 두 쪽이다. "확정 틀"에 위 15장, "검토 기록"에 고르지 않은 안(H2, B, C, D)과 추가 제안(E)이 있다. 검토 기록 쪽은 참고용이며 E의 타자 그림은 머리가 잘려 보인다.

## 4. 경기 페이지 명세 (구현된 대로)

### 배치

위에서 아래로 다섯 줄이고, 화면 높이에 딱 맞는다. 가운데 "무대"가 남는 높이를 모두 쓴다.

| 줄 | 내용 |
|---|---|
| 상단 | 뒤로, LIVE(누르면 중계 맞추기), "실험판" 표시, 더 보기 |
| 점수판 | 두 팀 점수, 회, B·S·O 불빛, 주자, 투수 이름과 구수, 타자 이름과 좌·우타 |
| 무대 | 상황에 따라 바뀌는 내용 + 스트라이크존 그림(옆에 타자 그림) |
| 공 순서 | 이 타석에서 던진 공을 번호 점으로. 누르면 그 공을 본다 |
| 버튼 | 자세히 / 박스 스코어 / 지난 장면 |

### 무대에 나오는 상황 여섯 가지

| 상황 | 언제 | 무대 |
|---|---|---|
| 다음 공 | 추천이 준비됨 | 추천 구종, 위치(화살표 + "바깥쪽 낮게"), 꼬리표("평소에도 1순위 · 56%"), 존의 목표 칸 |
| 방금 던진 공 | 공 결과가 도착함. **6초** 보여 준 뒤 다음 공으로 | 실제 구종·구속·결과, "구종 ✓ / 위치 ✕", 존에 목표와 실제 |
| 결과 확인 중 | 삼진·볼넷·타구 직후 결과가 올라오기 전(약 10초) | "결과를 기다려요"와 방금 던진 공 |
| 타석 끝 | 타석 결과가 나옴. **10초** 보여 준 뒤 다음 공으로 | 결과, 수비 팀 승리확률 변화, "무엇 때문에" 막대 자리(미측정) |
| 공수 교대 | 이닝 교대, 준비 중 | "공수 교대"와 방금 던진 공 |
| 추천 없음 | 기록이 부족한 투수 | "추천 없음"과 이유. 실제 공은 계속 보여 줌 |

6초와 10초는 제안값이다. 실측(경기 849844)으로는 공과 공 사이가 중앙값 20.5초, 공을 놓은 뒤 기록이 뜨기까지가 중앙값 19.2초라서, 중계 지연을 짧게 맞춘 시청자에게는 결과를 보여 주는 동안 다음 공이 이미 던져졌을 수 있다. 실제 폰에서 보고 다시 정해야 한다.

### 눌렀을 때

| 누르는 곳 | 나오는 것 |
|---|---|
| 구종 이름 | 쉬운 풀이 한 줄("옆으로 휘면서 떨어지는 공"), 그 투수의 오늘 구수와 평균 구속 |
| 속도 숫자 | km/h ↔ mph 전환. 기본은 km/h, 선택을 기억한다 |
| 자세히 | 후보 세 개와 모델 선택 비율·평소 비율 / 투수 오늘 구종별 기록 / 안내 |
| 박스 스코어 | 지금은 현재 점수와 투수 구수만(3단계에서 채움) |
| 지난 장면 | 지난 공을 하나씩. "LIVE로 돌아가기"가 가장 큰 버튼 |
| LIVE | 내 중계 화면과 시간 맞추기(±1초, ±5초, 공이 미트에 들어올 때 누르기) |

### 표기 규칙

- **위치는 타자 기준 말**: 몸쪽·바깥쪽, 높게·낮게. 좌타자면 말과 타자 그림이 함께 뒤집힌다.
- **공 결과 색은 세 가지**: 스트라이크·파울·헛스윙 / 볼 / 타구. 색만으로 구분하지 않게 번호를 함께 쓴다.
- **승리확률은 수비 팀 기준**(D51). 예전 화면(`/live`)은 공격 팀 기준이라 서로 다르다.
- **"구종 ✓ / 위치 ✕"는 실제 공이 추천과 같았는지만** 뜻한다. 추천이 좋았다는 뜻이 아니다.
- **모든 화면에 "실험판" 표시**를 둔다. 추천 모델은 아직 성능 검증을 통과하지 않았다(D131).

## 7. 남은 일

사용자 답을 기다리는 것:

1. 실제 폰에서 본 의견(한 화면에 들어오는지, 전환이 너무 빠르거나 느린지).
2. 다음 단계 착수 여부. 마지막으로 승인된 범위는 경기 페이지 1·2단계까지다.
3. 색·글꼴 등 상세 디자인.

구현 순서 제안(승인 전):

| 단계 | 내용 | 새로 필요한 것 |
|---|---|---|
| 3 | 박스 스코어 판 | 이닝별 점수·안타·투수 기록을 주는 API(MLB 피드에 값은 있다) |
| 4 | 홈 | 지난 경기 점수와 날짜별 목록·검색 API |
| 5 | 지난 경기 분석(P3 → P1 → P2) | 경기 전체 승리확률을 한 번에 주는 API. 지금은 공마다 따로 불러야 한다 |
| 6 | 검사 확대 | 실기기, 사파리·삼성 인터넷 |

시안과 구현이 다른 곳(응답에 값이 없어서):

- 공수 교대 화면에 다음 투수·타자 이름과 지난 이닝 요약이 없다.
- 이닝을 끝낸 공은 "타석 끝" 화면으로 뜨지 않고 공수 교대 화면의 한 줄로만 나온다.
- "지난 장면"은 화면을 연 뒤에 본 공만 돌아볼 수 있다.
- 타자의 "오늘 몇 번째 타석"이 없다.

## 9. 같이 돌아가는 일과 지킬 것

- **실시간 서비스 세션**이 백엔드와 측정을 맡고 있다([LIVE-service-plan.md](LIVE-service-plan.md), 브랜치 `demo/live-sync`, 운영 서버 8766). 예전 화면 `/live`는 그쪽에서 더 손대지 않기로 했다. 서버 응답이 바뀌면 `/game`도 따라가야 한다(오늘 "결과 확인 중" 상태가 그렇게 추가됐다).
- **추천 모델은 검증 전**이다. 2026 평가에서 개선 근거가 없었고(D131) 서비스 정책으로 채택되지 않았다. 화면에서 "AI가 맞혔다" 같은 표현을 쓰지 않는다.
- **숫자를 지어내지 않는다.** 없는 값은 "미측정"으로 쓴다. 타석 끝 화면의 "무엇 때문에" 막대가 비어 있는 이유다(포수 목표 위치 자료가 아직 없다).
- **비공개 주소만** 쓴다(127.0.0.1 또는 Tailscale 100.x). 공개 배포는 MLB 피드 이용 조건을 확인한 뒤의 일이다.
- 이 레포는 여러 세션이 동시에 고친다. 커밋할 때 자기 파일만 골라 넣는다(`git add -A` 금지). 결정 번호는 쓰기 직전에 마지막 번호를 확인한다(오늘 D134가 두 번 쓰였다).
