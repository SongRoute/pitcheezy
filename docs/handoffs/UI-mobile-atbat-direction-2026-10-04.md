## 사용자가 정한 방향

- 실경기 중계를 보면서 옆에서 참고하는 모바일 웹이다.
- **현재 타석의 핵심 정보는 스크롤 없이 한 화면**에서 읽는다.
- 필수 텍스트는 유지하고 아이콘·그림·숫자로 우선 전달한다. 설명문·선수의 긴 기록은 한 번 선택한 뒤 제공한다.
- 실시간은 새 공·카운트·주자·투타자 정보를 자동 갱신한다. 과거 경기는 사용자가 눌러 다음 정보로 이동한다.
- 첨부 네이버 스포츠 문자중계 화면은 참고다. 넓은 경기장 배경·별도 선수 카드·타석 로그를 세로로 쌓는 구조를 그대로 복사하지 않는다.
- 연구는 병렬로 계속한다. 유의미한 결과는 개선 폭·여러 시드/범위에서의 일관성·학습 비용·검증 한계를 함께 보고한다. 단순 학습 종료를 성능 향상으로 알리지 않는다.

## PM 추천 기본 배치: 존 중심

| 영역 | 항상 보이는 것 | 한 번 선택하면 |
|---|---|---|
| 상단 | 팀·점수·회차·공수·B/S/O·주자 다이아몬드 | 이닝별 점수, 주자·수비, 경기 기록 |
| 대결 | 투수·타자 이름, 좌/우투·좌/우타 | 선수 시즌/당일 기록, 구종 흐름 |
| 중앙 | 큰 스트라이크존, 번호가 붙은 현재 타석 실제 투구, 다음 공 추천 구역 | 선택한 투구의 구종·구속·결과, 추천과 비교 |
| 중앙 하단 | 추천 구종 하나·짧은 위치 표현, `위치 근사` | 다른 후보·추천 근거·검증 상태 |
| 하단 | 이 타석의 투구 번호, 승리 가능성 추정, 연결/지연 상태 | 투구 상세·사건 변화·방송 지연 설정 |

대안 `추천 중심`은 같은 정보를 유지하되 추천 구종을 중앙 위에 크게 배치한다. 사용자가 아직 두 시안 중 하나를 최종 선택한 것은 아니다. 기본안은존중심이며 투구의 흐름과추천/실제비교를 같은 공간에서 보기 쉽다.

## 갱신·탐색 규칙

1. 실시간 기본 화면: 투구 전 추천 → 피드 수신 뒤 결과를 짧게 표시 → 다음 공 대기, 타석 종료 시 새 타자로 자동 전환. 실제 수신 전에는 결과·카운트를 추측하지 않는다. 중복·늦게 도착한 응답으로 과거 상태가 덮이지 않아야 한다.
2. 사용자가 상세를 읽거나 지난 공을 선택하면 해당 내용을 고정한다. 뒤에서 새 공이 와도 읽던 기록을 바꾸지 않고 `새 공 도착 · 최신 화면 보기`만 제공한다. 닫으면 현재 상태로 복귀한다.
3. 과거 경기 기본: `실제 투구 공개` → `다음 공`. 공개 전 결과·실제 구종·좌표·결과를 암시하는 상태/사유를 숨긴다. 자동으로 다음 공을 공개하지 않는다.
4. 상태와 시간을 숨기지 않는다. 정상/지연/연결 끊김/이닝 교대를 짧은 문구와 표식으로 구분한다. 방송보다 앞선 정보 노출을 줄이기 위한 지연 맞추기는 상태 영역을 한 번 눌러 조절한다. 타이머만으로 실제 중계 동기화가 됐다고 주장하지 않는다.
5. 추천 미지원이면 존과 실제 타석 정보는 유지하고 `추천 없음`과 이유를 제공한다. 오래된 다른 공의 추천을 현재 추천처럼 남기지 않는다.
6. 10구 이상 긴 타석에서도 본 화면 높이를 늘리지 않는다. 최근 투구와 `전체 n구` 진입을 유지하고 전체 목록은 상세에 둔다.
7. 아이콘만으로 뜻이 모호한 추천/실제/추정·지연은 짧은 글자를 함께 쓴다. 색만으로 구분하지 않고 점선·번호·기호도 사용한다. 승리 추정과 추천 성공확률을 혼동시키지 않는다.
8. CV는현재확보된과거경기자료의가로위치만 공개후 표시한다. 실시간CV동작이나 의도/높이/9구역검증을 시안으로 암시하지 않는다.
