# 병렬 업무 실행 계획

2026-09-23 갱신 (D49·D50). 목표와 완료 조건은 [로드맵](roadmap.md), 외부 CV 입력은 [의도 계약](intent-spec.md)을 따른다.
이 문서는 업무 범위·단계·완료 조건을 정의한다. 아래 계획 작성 당시의 미실행 설명과 실제 완료 기록을 구분한다.

실행 상태 갱신(2026-09-23): C0 `5289d90`, 병렬 기준 `16b30cf`, 첫 통합 실행 코드 `62b423f`. A C0/S0/S1 및 B 비교 검토·사건 입력 묶음, B 추천 경계·한 축 비교, C 사건 계약/계산 경계, D 대표 추천→실제 비교→사건 카드를 완료했다. 첫 통합 150개 검사 및 실제 K/HR PC·모바일 검증 통과. 이후 CV를 제외하고 공통 빈도/정책 내부 비교, B 실패 진단과 B002 설계 고정, 과거 등록 명단·휴식/타순 자료 및 반이닝 평가기를 진행했다. 최신 결과는 [A·B/A·C v2](handoffs/AB-AC-v2.md), 앞선 화면 통합은 [ABCD 통합 인수인계](handoffs/ABCD-integration.md)를 따른다. B 후보는 미채택이며 C 실제 의도 없는 비중은 null이다. S2/S3, 실제 CV, 교체/정책 효과 검증 완료를 뜻하지 않는다.

각 세션의 시작 순서·첫 완료 목표·복사할 지시문은 [A~D 인수인계](SESSION_HANDOFF.md)를 따른다. A가 공통 준비를 먼저 공유한 뒤 B·C·D를 병렬로 진행하고 D에서 첫 제품 통합을 맡는다.

## 제품 우선순위

| 시점 | 이번 필수 기능 | 후순위 |
|---|---|---|
| 투구 전 | 가장 유리한 구종·목표 위치 표시 | 후보별 비율/수치 비교, 다른 후보보다 유리한 이유 |
| 투구 후 | 저장된 사전 추천과 실제 구종·위치 비교 | 상세 후보 탐색 |
| 중요 사건 후 | 기여 비중·방향·근거와 미설명분 확인 | 더 넓은 사건 종류·설명 표현 고도화 |

투구 전 상세 설명을 미루는 것은 사건 후 기여 근거를 미루는 뜻이 아니다. 내부 후보 평가와 연구 검증은 계속한다.
기존 `ChoiceExplanation` 계산·코드를 급히 삭제할 필요는 없다. 첫 화면의 필수 조건에서 빼고 신규 개발 우선도를 낮춘다.
‘포심 50%’ 같은 값의 의미는 후속 설계에서 정한다. 임의 점수를 확률로 표시하지 않는다.

## 공통 준비 — C0

A~D가 서로 다른 입력·가치·모델을 쓰지 않도록 먼저 맞출 작은 작업이다. 실제 CV 알고리즘은 필요하지 않다.

| 작업 | 산출물 | 완료 기준 |
|---|---|---|
| C0-1. 기존 계약 재사용 | 투구 ID, `IntentEstimate`·검토 라벨·좌표 규약, 추천/분석 연결표 | `intent.py`의 검증과 `intent-spec.md`를 재사용; 별도 의도 규격을 만들지 않음 |
| C0-2. 공통 모형 경계 | 추천·실제 투구·대안의 결과/가치를 같은 버전으로 계산하는 인터페이스 사양 | 가치 단위·수비/공격 관점·평가 범위·버전이 명시됨 |
| C0-3. 개발용 사례 | 정상, 의도 없음, 잘못된 연결/좌표, 낮은 품질, 늦은 도착, 정정 사례 | 개발용 출처가 명확하며 실측 라벨·학습·성능 평가 자료와 분리 |
| C0-4. 공통 평가 사양 | 현재 서비스 모델 버전·자료 분할·선행연구 비교 범위·기준표 형식 | 후보 결과 열람 전에 지표·표본·판정 방법 고정 |

C0-2의 작업안은 **현재 서비스의 수비 팀 WE를 유지하고, 화면 변화량은 %p로 통일**하는 것이다. 기존 RE24 연구는 별도 표로 보존한다. 구현 착수 때 서비스 계약으로 기록하며 기존 실험의 보상·채택 기준 변경은 별도 결정으로 남긴다. 사건 확률 분해를 제공하면 WE와 별도 지표로 둔다. 교체의 장기 범위와 투구의 타석 범위가 다르면 같은 합계에 바로 더하지 않는다.

개발용 의도 샘플은 계약을 통과하는 가상의 사례다. 기존 실영상의 측정 결과나 사람이 검토한 라벨로 저장하지 않는다. 운영에서는 현재의 CV 미연결/실패 상태를 유지하며, 실제 출력 인수 검사를 통과한 뒤 운영 어댑터를 연결한다.

## 작은 데이터부터 단계적으로 학습 (D50)

학습 데이터셋의 규모를 단계적으로 늘린다. 학습 중 한 번에 처리하는 `batch_size` 조절과는 별개다. 기존 검증 결과가 있는 동일 경로는 재사용하고, 신규 모형·피처·데이터 경로를 작은 단계부터 확인한다.

| 단계 | 데이터 범위 | 성공·다음 단계 조건 |
|---|---|---|
| S0. 실행 검증 | 수백~수천 구 수준의 작은 실제 자료; 완전한 타석·경기 묶음으로 구성 | 전처리→학습→저장/복원→추천→평가가 연결되고 누수·잘못된 상태·NaN·재현 오류가 없음. 성능 우위는 요구하지 않음 |
| S1. 소규모 학습 | 충분한 기록이 있는 투수 2~3명과 여러 경기/타자; 앞 기간 학습·뒤 기간 개발 검증 | 같은 표본의 단순 기준선과 비교 가능, 예측·보정·정책·지원률·시간/메모리 기록. 명확한 오류/열화는 수정하고 표본 부족에 따른 미확정은 구분 |
| S2. 범위 확장 | 선수 구성·기간·좌우 타자·구종·경기 상황을 사전 순서대로 확대 | 규모별 학습 곡선과 하위집단/희귀 사건 성능, 지원률·비용 확인. 효과가 사라지면 원인 진단 후 다음 실험 결정 |
| S3. 전체 지원 범위 | 프로젝트가 지원하기로 한 코호트 전체; 모델/설정 고정 뒤 별도 최종 평가 | 선행연구 대비 공통 정책 평가, 추가 요소 제거 실험, 미열람 기간 재확인. 서비스 채택은 기존 성능 기준을 통과할 때만 |

S0·S1의 수치는 시작 규모의 예시이며 아직 선정·추출한 데이터셋이 아니다. 실제 규모는 가용 경기·결과 클래스 수와 실행 비용을 확인하고 config에 고정한다. ‘전체’는 모든 MLB 선수가 아니라 정의된 지원 범위다.

확장 규칙:

- **선정은 결과 열람 전에 고정한다.** 투수는 학습 기간 기록으로 고르고, 추천이 잘 맞은 경기·홈런/삼진 사례만 남기지 않는다. 작은 단계에서 유의한 우위가 나올 때까지 표본을 다시 뽑지 않는다.
- **경기 단위로 분할하고 타석·투구 이력을 보존한다.** 같은 경기/타석이 학습과 평가에 나뉘지 않게 하며 시간 순서를 지킨다. 과거 프로필과 구종 집계도 해당 예측 시점 이전 정보만 사용한다. 클래스가 없는 단계는 해당 지표를 미평가로 남긴다.
- **학습 집합은 가능한 한 작은 집합을 포함하며 확장한다.** 고정된 공통 개발 검증셋의 규모별 결과와, 새 선수/상황의 별도 결과를 함께 남겨 평가 표본 변화와 학습량 효과를 구별한다. 검증 자료를 다음 단계 학습에 편입하지 않는다.
- **최종 평가셋을 단계별 튜닝에 사용하지 않는다.** 반복 확인한 구간은 개발 평가다. 기존 2026 데이터 사용 제한과 노출 이력을 유지한다.
- **한 비교에서는 한 축을 바꾼다.** 데이터 규모 비교는 피처·학습 규칙·계산 예산 규칙을 고정하고, 피처/모형 비교는 동일 데이터에서 한다. 초기화/체크포인트 재사용·시드·학습 횟수도 기록한다.
- **작은 표본의 미유의가 자동 탈락은 아니다.** 계산/데이터 검증을 통과했고 불확실성의 원인이 표본 부족이라면, 사전 계획한 다음 규모에서 확인할 수 있다. 명확한 오류나 열화를 데이터 확대만으로 해결한다고 가정하지 않는다.
- **단계마다 산출물을 남긴다.** 데이터 목록/해시·기간·구성, config·코드 버전·시드, 기준선/후보 결과, 시간·메모리, 통과/수정/확장 이유를 기록한다. 개발용 CV 샘플은 학습·성능 평가에 사용하지 않는다.

병렬 업무 연결: A가 단계별 데이터 목록·평가셋과 기준선을 관리하고, B가 학습·추천 실험을 진행한다. C·D는 직전 검증된 모델 버전을 계속 사용한다. 큰 학습을 기다리며 사건 분석·화면 개발을 멈추지 않는다. 실제 CV 자료가 도착한 제구 모형도 같은 단계 원칙을 적용한다.

첫 실행은 **C0에 단계별 데이터 선정/분할 규칙을 포함 → 작은 실제 자료로 S0 → 같은 자료 범위에서 기준선과 후보의 S1 비교**다. 이번 문서 갱신에서 실제 추출·학습을 시작하지 않았다.

## 병렬 업무 A — 데이터·성능 평가

**담당: 우리.** 결과를 측정하는 기준과 데이터를 책임진다. B의 후보를 고른 뒤 유리한 기준을 새로 만들지 않는다.

| ID | 작업 | 선행조건 | 산출물·완료 기준 |
|---|---|---|---|
| A1 | 현재 서비스 모델·단순 기준선의 기준표 | C0-4; 기존 실제 자료 | 예측/보정/정책 지표, 지원률·불확실성·버전. 미측정은 미측정으로 표시 |
| A2 | 선행연구 비교 사양과 평가 실행 경로 | A1 | 같은 정보·데이터·행동·튜닝 예산; B2 2스트라이크 비교는 별도 범위로 재현 |
| A3 | 추가 요소 후보의 추가/제거 비교 | A2 + B2 후보 | 같은 표본의 정책 차이·신뢰구간·지원률; 예측 개선과 정책 개선을 구분 |
| A4 | 교체 대안·사건 분석 표본 준비 | C0-1; 확보 가능한 경기 기록 | 당시 명단·등판/휴식·타순·교체 시점, 자료 출처/결측, 고정한 사건 선정 규칙 |

영역: 연구 평가 스크립트·설정·보고서. 기존 `src/pitcheezy`의 RE24 결과는 서비스 WE 결과와 분리한다.
CV 없이 A1/A2/A4를 시작할 수 있다. 목표 위치 개입/제구 관련 평가에는 인수한 실제 목표 표본이 필요하다.

## 병렬 업무 B — 구종·목표 위치 추천

**담당: 우리.** 팬에게 보여줄 대표 추천과 모델 개선을 책임진다.

| ID | 작업 | 선행조건 | 산출물·완료 기준 |
|---|---|---|---|
| B1 | 기존 추천을 공통 모형 경계에 연결 | C0-2; 현재 모델 | 같은 입력·버전에서 기존 후보 가치/순위 재현, 지원 불가 처리, 대표 추천 1개 반환 |
| B2 | 비영상 추가 요소의 첫 개선 후보 | B1 + A1/A2 평가 사양 | 시점 이전 타자/투수/배합/당일 변화 중 근거 있는 한 축을 config로 비교; 바꾸지 않은 대조군 유지 |
| B3 | 목표→실행 모듈 인터페이스와 대체 구현 | C0-1/C0-2 | 현재 근사 분포를 교체 가능하게 분리, 가상 샘플로 입출력 검증 |
| B4 | 실제 의도 자료로 제구 분포 학습·검증 | B3 + CV 인수 + 실제 학습/검증 표본 | 좌표/라벨 오차·선택 편향을 반영한 검증; A3를 통과한 후보만 채택 |

영역: `recommender.py`와 연구 모델/설정. `runtime_src`·동결 번들·해시는 직접 덮어쓰지 않고 새 버전 후보를 만든다.
현재 공의 CV 의도는 다음 공 추천의 필수 입력으로 두지 않는다. 학습된 제구 모형과 그 시점까지 사용 가능한 과거 관측을 이용한다.

## 병렬 업무 C — 중요 사건 기여도

**담당: 우리.** CV 결과를 받아 작전·실행·타자·교체의 기여를 계산한다. 영상 추적을 다시 개발하지 않는다.

| ID | 작업 | 선행조건 | 산출물·완료 기준 |
|---|---|---|---|
| C1 | 분해 기준과 결과 형식 | C0-1/C0-2 | 기준 상황·단위·부호·분모·상호작용/잔여 처리, 근거 참조와 판단 불가 사유 |
| C2 | 홈런·삼진의 작전/실행/타자 분석 | C1 + 고정된 기존 모형 | 개발 샘플로 계산·합계·중복 귀속·누락 처리를 검증; 추천/의도/실제/결과 연결 |
| C3 | 유지 대 교체 대안 비교 | C1 + A4 | 실제 가능한 교체 후보와 평가 범위, 중복 없는 합산 규칙 또는 별도 카드; 정보 부족 시 판단 불가 |
| C4 | 실사건 검증·근거 추적 | C2/C3 + CV 인수 + 실제 사건 표본 | 모형/기준점/의도 오차에 대한 민감도, 기여 비중·근거·미설명분을 확인 |

영역: 신규 사건 분석 모듈과 분석 결과 저장. 기존 `explanations.py`는 투구 전 후보 차이 설명이므로 선수별 사건 기여도 모형으로 간주하지 않는다.
C2와 C3는 C1 뒤 병렬 개발 가능하다. 홈런·삼진부터 연결하지만 교체 기여를 최종 범위에서 빼지 않는다.
CV의 목표 **위치**만으로 목표 **구종**이나 사인 결정자를 알아냈다고 가정하지 않는다. 실제 구종을 선택 구종의 대리값으로 쓰면 그 가정을 명시하고 두 정보를 구분한다. ‘기여 비중’의 원시값은 부호 있는 가치 차이로 보존하고, 근거 없는 100% 배분을 하지 않는다.

## 병렬 업무 D — 웹·서비스 통합

**담당: 우리.** 현재 화면을 활용해 세 단계 흐름을 완성한다. 새 모델·CV 완료를 기다리지 않고 시작한다.

| ID | 작업 | 선행조건 | 산출물·완료 기준 |
|---|---|---|---|
| D1 | 투구 전 대표 추천·투구 후 실제 비교 | C0-1; 현재 API | 추천 구종·목표 위치 우선 화면; 실제 공은 그 공의 사전 추천과 비교 |
| D2 | 중요 사건 카드와 상태 처리 | C1 결과 형식 | 샘플 응답으로 기여 비중·근거·분석 중/일부만 가능/실패 표시 |
| D3 | CV/분석 어댑터·비동기 갱신 | 기존 의도 계약 + C1 | `pitch_id` 연결, 중복/지연/정정 처리, 사전 추천 불변, 분석만 새 버전 생성 |
| D4 | 전체 기록 재생·팬 평가 | B1 + C2/C3 + D1~D3; 실제 검증은 CV 인수 뒤 | 한 타석의 세 단계 완료, 재시작/누락 처리, 사실·추천·추정을 구분하는 팬 평가 |

영역: `web/src`, 서비스/API와 워커 통합. 투구 전 비율표·추천 이유 확장은 후순위다. 선택한 주요 공만 CV를 요청하는 기존 운영 범위를 유지한다.
화면 샘플 확인은 D2 개발 완료이며 실제 사건 분석 성공으로 집계하지 않는다.

## CV 담당 팀원과 합류

팀원에게 새 메시지를 보내거나 새 과제를 배정한 것은 아니다. 아래는 기존 담당 범위에 대한 우리가 사용할 인수 조건이다.

- 팀원 담당: 영상→투구 전 셋업 추정, 좌표 보정, 품질·기권 판정, 평가 근거와 산출물.
- 우리 담당: 기존 검증기로 수신·저장, 실제 투구 연결, 시점/품질별 사용 여부, 제구 모형·사건 분석·화면 연결.
- 필수 연결 정보: 투구 ID, 목표 좌표/도달한 좌표계, 변환 버전·오차 상태, 근거 프레임·시각, 추정 방법/버전, 불확실성, 추정/사용 불가 상태. 사람 검토 결과는 기존 별도 레코드를 사용한다.
- 픽셀 좌표만 들어오면 저장 가능한 추정이어도 실제 도달 위치와의 물리 비교에는 쓰지 않는다. 계약 통과와 분석 사용 가능 판정을 따로 한다.
- 근거 프레임은 릴리스 전이어야 한다. 처리 완료/수신 시각은 우리 저장 계층에 기록하고, 뒤늦게 도착한 분석이 과거 추천 입력에 들어가지 않게 한다.
- 인터페이스 개발은 성공·기권·부분 좌표·지연·정정 샘플로 완료 가능하다. B4·C4의 품질 통과는 실제 표본으로 확인한다.

## 실행 순서와 합류 지점

1. **공통 준비:** C0. 기존 계약을 다시 만들지 않고 서비스가 사용할 경계와 평가 사양만 고정한다.
2. **첫 병렬 묶음:** A1/A2/A4, B1/B3, C1, D1. C1이 나오면 C2/C3/D2/D3를 진행한다.
3. **첫 통합:** 고정 모델 + 개발용 의도 샘플로 대표 추천→실제 비교→사건 카드 연결. 제품 흐름/계산의 완료이며 실제 효과 증명은 아니다.
4. **실데이터 합류:** 팀원 CV 결과를 연결해 B4/C4/D4 수행. A의 공통 평가로 모델·분해 품질을 판정한다.
5. **모델 개선 반복:** B2/B4 후보를 A3로 비교하고 통과 모델만 서비스 버전 갱신. 실제 팬 평가 뒤 지연/라이브 운영으로 확장한다.

### 병렬 작업 충돌 방지

- A는 데이터·평가, B는 모형/추천, C는 사건 분석, D는 화면/API를 소유한다. 공통 타입·`domain.py`·스키마는 C0와 통합 작업에서 한 담당이 변경한다.
- 각 작업은 고정 모델/계약 버전을 소비한다. 새 버전이 나오면 합류 검사를 통과시켜 바꾸며 공유 파일을 동시에 수정하지 않는다.
- 맥미니의 대규모 학습은 동시에 여러 개 돌리지 않는다. 학습 한 건이 실행되는 동안 평가 코드·화면·분석 로직을 병행한다. 논리적 병렬성과 계산 자원 병렬성을 구분한다.
- 다음 한 가지는 ‘가장 많은 후속 작업을 열 수 있는 미완료 작업’으로 고른다. C0·첫 통합·작은 공통 비교 실행을 완료했다. 사용자 일정에 따라 CV 인수는 약 일주일 뒤까지 제외한다. B002는 TRAIN 선택/체크포인트 커밋 후 DEV 1회 평가까지 완료했고 NLL 악화로 미채택했다([실행 기록](handoffs/B002-execution.md)). 다음은 C의 조건부 이닝 평가 결과 형식을 고정해 D에 전달하는 것이다. 교체 자료/이닝 평가의 실제 가용성·지원 범위 검증과 기록 재생·팬 검증도 CV 없이 계속할 수 있다.

**다음 아침 확인:** 이번 계획에서 시작한 장기 실험 없음. 기존 RE24 예약은 별도 유지: 정규시즌 종료 후 freeze → 009 재확인, P1-009 vs 006 재측정(D28·D36·D39). 이 결과를 서비스 WE 모델의 검증 결과로 대신하지 않는다. 2026은 정책 학습·튜닝·모델 선택에 쓰지 않는다.
