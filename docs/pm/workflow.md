# 작업·검토·인계 절차

상위: [운영 진입점](overview.md) · 공통 지침: [AGENTS](../../AGENTS.md)

## 시작

사용자 요청과 해당 분야 계약을 확인한다. 작업 ID·담당·기준 커밋·dirty·정확한 수정 파일·완료 조건·출력·자원·중단 조건을 기록한다. [작업큐](work-queue.md)의 전체 댓글과 양쪽 상황판·열린 mail을 확인해 기존 점유를 보호한다. CLAIM/재조회는 발신 권한이 있을 때 수행한다. 이번처럼 발신이 금지된 작업은 읽기 조회와 로컬 작업 기록으로 제한하며 원격 선점으로 주장하지 않는다.

한 파일에는 한 작성자, 한 worktree에는 한 index 담당을 둔다. 관리자의 위임은 실자료·운영 권한을 넓히지 않는다. 다른 소유자의 무응답을 해제로 취급하지 않는다.

## 구현과 검사

1. [구현 원칙](../engineering/implementation.md)에 따라 기존 코드와 모든 관련 호출자를 확인한다.
2. 연구는 자료 역할·분할·seed·지표·예산·fresh output/lock, 서비스는 공 식별자·공개 시각·지원/오류 상태·복구 조건을 고정한다. 실자료 실행 전 등록과 작성자와 다른 에이전트의 검토를 수행한다.
3. 별도 worktree에서 작은 변경을 만들고 [관련 검사](../engineering/verification.md)를 실행한다. 코드·CSS에는 union merge를 사용하지 않는다.
4. 고정 커밋·diff·검사 로그로 검토한다. 작성자와 검토자를 구분하고, 같은 모델 검토를 독립 모델 검토라고 쓰지 않는다. source 변경 시 영향 범위의 검토를 갱신한다.
5. PR에는 문제·변경·실측 검사·미측정·남은 조건을 남긴다. 지정 통합 담당자가 검토한 커밋만 통합한다. 작업 완료와 merge·배포·과학 판정을 구분한다.

## 수용과 보존

착수는 단일 소유·기준 보존·계약·유한 완료 조건, 기능 수용은 실제 공 상태·시점·오류/지연·필요 기기 검증을 요구한다. 연구 실행은 고정 등록·소스·자료·장치 배타·감독을, 공개/운영은 복구·관측·관리 권한과 해당 release GO를 요구한다. 정확성·누수·권한·복구 조건은 기능 축소로 면제하지 않는다.

막히면 실행·변경 상태와 재개 조건을 남긴다. 완료 시 최종 커밋·검사·증거·잔여 작업·소유권 반환·보존 자원을 기록한다. worktree는 기본 보존이며 삭제 제안은 삭제 승인이 아니다. 다른 dirty·실패 시도·봉인 산출물을 포함하거나 덮지 않는다. 새 worktree는 자동 동기화되지 않으므로 고정 커밋으로 인계한다.

보고 형식은 **한 일 / 검사 결과 / 미측정·남은 조건 / 결정 필요**다. 현재 허가된 범위에서 진행 가능한 일은 계속하고, 새로운 과학 판정·정책 채택·운영 교체는 기존 게이트와 구분한다.

## 정본 우선순위

최신 사용자·상위 도구 지시 → AGENTS → 해당 공통 계약·승인 결정 → 분야 상태와 고정 source/config/manifest/receipt를 대조한다. 충돌하면 범위·근거를 명시한다. README는 안내, overview는 현재 방향, 이 문서는 절차, contracts는 분야 경계, resources는 자원, state는 날짜 있는 관측이다. [이전 절차 원문](../maintenance/instruction-history.md)은 당시 이력이다.
