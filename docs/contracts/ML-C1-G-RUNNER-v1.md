# C1 additive G extension: identity and resource contract

This runner extends a registered subset of the immutable G family from seeds 0–2 to 0–4. It does not change G selection or establish independent confirmation after DEV exposure. A baseline-only registration contains G0 and no superiority comparisons. At most two registered candidate/control pairs use the same Cpanel population and fixed four-slot C1 scoring family.

`parent_preparation_sha256` hashes the original G `preparation.json` file. **`parent_analysis_sha256` hashes G `analysis/panel/manifest.json`, not `results.json`.** The manifest transitively binds results, predictions and their input files. Preparation verifies all fifteen original G prediction members, their exact routed checkpoint unions, unit identities, fit reports, calibration counts, common keys/labels and archived probabilities before selecting references.

Seeds 3–4 fit exactly the union of required G units. TRAIN, early-stop, May temperature, June blend and DEV keys, normalizer, delivery sampler, continuous profiles, clusters and context remain the parent objects. Original G uses automatic device selection; this extension requires `device: auto` and the identical native/local environment. Fit settings remain MLP width 128, 30 epochs, patience 5, batch 1024 and learning rate 0.0005. Predictions use 400 delivery draws and the original calibration procedure. Each requested member resolver verifies the exact routed dependency set and returns `hashes` covering its preparation, prediction state/artifacts and every unit state/checkpoint/fit report for the scoring manifest. Checkpoint deserialization occurs only during authorized prediction; source-only tests use synthetic files.

Registration must set `single_member_wall_limit_seconds: 7200` and a positive integer `batch_wall_budget_seconds` no greater than 28800. The profile measures two-epoch representative fits by unit mode, new-seed G0 May calibration on 64 rows and 400-draw inference. The fit command rejects a projected per-seed union fit time over 7200 seconds. It also rejects inherited full-Cpanel prediction jobs over 7200 seconds or an aggregate projection over the registered batch cap. The aggregate is twice the per-seed fit projection plus twice the sum, across selected cells, of their largest original three-seed prediction runtimes. Those inherited prediction runtimes already include full May calibration and June/DEV integration.

These projections are necessary feasibility checks, not authorization or hard runtime enforcement. The sole execution owner must review and register the actual aggregate cost, include preparation/profile overhead in the execution ledger, and enforce per-command wall limits before the first new fit. There is no quality-based tuning in profiling. Frozen parent sources and artifacts remain unchanged.
