## 1차 묶음 — 병렬 진단과 제품 개선

### A·B: 추천 품질 진단

기존 승인된 개발 코호트에서 선수·기간·표본·지표·선정 규칙을 결과 열람 전에 고정/커밋한다. 현재 16구는 문제 발견 사례로만 둔다. 기존 노출 이력을 보존한다.

측정 항목은 선수/카운트별 실제 배합 대비 추천 집중도, 실제 선택 구종의 전체 지원 행동 내 순위와 최고 가치 차이, 구종×구역 지원률, 독립 seed별 순위 안정성이다. 상위 3개 구역 행동을 서로 다른 구종 세 개로 취급하지 않는다. 구종 일치율은 설명용 진단이며 채택 지표가 아니다. 지원 밖 실제 선택의 순위/가치는 만들지 않는다. 예측 지표·모형 내부 정책 가치·식별 가능한 정책 평가를 구분한다.

완료 산출물: 사전 고정 사양/config/커밋, 재현 가능한 집계, 불일치의 확인된 원인과 미확인 가설, 다음 실험 또는 보류 판정.

### D: UI/UX 정보 구조 개편

대표 흐름을 ‘다음 추천 → 같은 공의 실제 비교 → 사건 설명’으로 단순화한다. 첫 화면 정보량을 줄이고 수치·기술 상세는 필요할 때 펼치게 한다. 다음 공/선택한 과거 공의 시점을 명확히 하고, 작은 추정 차이를 확실한 우위로 보이게 하지 않는다. 사전 추천 불변과 실제 사실/추정/미측정 구분을 유지한다. 기능을 단순히 숨겨 최종 목표에서 빼지 않는다.

동결 모형을 쓰는 개편안을 별도 확인 경로에 구현하고 PC/모바일로 검증한다. 사용자에게 변경 전후와 접속 URL을 제공한다. 취향 질문 때문에 독립 구현 전체를 멈추지 말고 기존 피드백을 기준으로 첫안을 만든다. 모델 개선 완료를 기다리지 않는다.

### A·C: 교체 근거와 이닝 평가

기존 고정 경기·저장 자료를 먼저 재사용한다. 당시 등록 명단, 이전 등판/휴식/연투, 교체 직전 타순·시점을 확인한다. 등록 선수라는 이유만으로 실제 투입 가능하다고 단정하지 않는다. 데이터 부족/비공개 상태와 모델 미지원은 따로 기록한다.

완료 산출물: 근거가 있는 후보와 조건부 후보/판단 불가의 구분, 후보별 평가 가능 여부, 동일 초기 수비팀·이닝 범위의 비교 사양. C가 바꿀 결과 형식은 D 구현 전에 공유한다. 기존 PA 값과 이닝 값을 혼합하지 않는다.

## 3차 묶음 — 독립 검토와 통합

구현자와 분리된 핵심 검토, 동일 공/시점/좌표 연결, 저장 추천 불변, 사건 부호/단위/합계/누락, 실제 PC/모바일·새로고침·오류/지연 검사를 수행한다. 통과한 변경을 총괄이 순차 통합하고 커밋·재현·모델/자료 버전·접속 주소를 기록한다. 기존 검사 통과는 해당 범위의 증거로 재사용하고 이유 없는 반복을 하지 않는다.
