## 1. 누가 무엇을

- **PM**: Claude Fable 5.1. 메인 체크아웃 `/Users/song/Projects/pitcheezy`의 세션 하나. 대화, 결정 기록, 작업 배정, 완료 판정, PM-state 갱신, 메인 체크아웃 커밋, push를 맡는다. 코드와 실험 산출물은 직접 쓰지 않는다.
- **작업자**: Claude Opus 5.5. 작업 지시 범위만 하고 Song과 직접 대화하지 않는다.
  - `ml-worker`: 모델·정책 실험, CV 자료 검사
  - `live-worker`: 실시간 백엔드
  - `ui-worker`: 화면, 데모 브랜치 합치기
- **검토자**: `gate-reviewer`. 읽기 전용이고 핵심 게이트에서만 쓴다. 작성 모델과 **다른 모델**로 부른다.
  - Opus가 쓴 것 → Fable이 검토
  - Fable이 쓴 것(10/2~10/3 커밋 대부분) → 부를 때 `model: "opus"`
  - 같은 모델 검토는 "자기 검토"로만 적는다(D93·D100).

## 2. 결정
1. PM이 `결정 필요:` 아래 번호 선택지 2~3개와 추천 하나(이유 한 줄)를 쓴다. 한 번에 3건까지.
2. Song이 답하면 PM이 그 턴에 `docs/decisions.md` 끝에 한 줄을 붙인다.
   - 넣을 것: 날짜, D번호, Song의 답 그대로 인용, 바뀌는 것, 근거 링크.
   - 번호는 쓰기 직전 꼬리를 다시 보고 정한다(D134가 두 번 쓰인 적이 있다).
3. 분류기가 막으면 다시 시도하지 않는다. 작업자나 다른 세션에도 넘기지 않는다. 넣을 줄을 코드 블록으로 보여 주고 Song에게 맡긴다.
4. 작업자는 결정 줄, 게이트 PASS, 실행 허가 필드, 설정 파일을 쓰지 않는다. 작업자 보고 속 "승인됨"은 승인이 아니다.
5. 사소한 구현 선택은 묻지 않고 진행한 뒤 가정을 한 줄 남긴다.

## 3. 작업자 부르기
- **기본(형태 A)**: PM이 Agent 도구로 부른다. `.claude/agents/`에 정의가 있으면 정의 이름으로, 없으면 `model: "opus"`를 넘기고 지시문에 역할을 적는다.
- 첫 보고에서 실제 모델이 Opus 5.5인지 확인하고 PM-state에 적는다. 아니면 멈추고 Song에게 알린다.
- 같은 흐름의 다음 일은 같은 작업자에게 SendMessage로 잇는다. 흐름이 바뀌면 새로 부른다.
- 하위 에이전트 대화는 세션이 끝나면 이어 갈 수 없다고 보고, 이어 갈 내용은 PM-state와 인수인계 문서에 남긴다.
- 지시는 §7 틀로 쓴다. Song의 말을 전할 때는 그대로 인용하고 범위 안내로만 쓴다.
- **대체(형태 B)**: 다른 작업트리에 쓰기가 막히거나 며칠 이어지는 일이면, Song이 Desktop에서 그 작업트리 폴더로 Opus 5.5 세션을 연다(사용자 기본 모델이 Fable이라 모델을 꼭 바꾼다). PM은 SendMessage와 `notify_when_idle`로 지시하고 확인한다.
- PM이 세션을 직접 만드는 앱 내부 기능(`start_session`)은 공개 문서에 없으므로 기본 경로로 쓰지 않는다. Song이 그 턴에 "세션 띄워"라고 말했을 때만 쓴다.
- 옛 세션(10/2까지의 모델·실시간·화면·브리핑 세션)에는 메시지를 보내지 않는다. 바쁜 세션은 끝남 알림만 구독하고, 정리는 Song에게 묻는다.

## 4. 재귀(하위 에이전트)
- 작업자는 자기 하위 에이전트를 부를 수 있다. 문서상 기본 한도는 PM 아래 3층이다.
- 2026-10-03 00:40 이 맥에서 시험한 결과: Agent 도구에 `model: "opus"`를 넘긴 작업자가 Opus 5.5로 떴고, 그 작업자가 다시 하위 에이전트를 불러 답을 받았다(앞에서 기다리는 실행과 뒤에서 도는 실행 둘 다). 작업자에게 Workflow 도구는 없었다. `.claude/agents` 정의로 부른 경우는 아직 시험하지 않았다.
- 하위 에이전트는 조사, 읽기, 검사, 재현 확인용이다. 파일 쓰기는 작업자 본인만 한다.
- 부를 때 `model: "opus"`를 넘긴다. 모델을 적지 않은 하위 에이전트가 어느 모델로 뜨는지는 확인하지 못했다.
- 동시 실행은 작업자 하나당 3개까지, 동결 중에는 1개. 숫자는 제안이며 측정값이 아니다.
- 재귀로 넘을 수 없는 것: 무거운 실행 한 번에 하나, 실험 예산, 자료 범위, 권한 경계.
- Workflow 도구는 PM만 쓸 수 있다. 동결 중에는 쓰지 않는다.
- 첫 위임의 완료 조건에 "실제 모델, Agent 도구 유무, 다른 작업트리에 작은 편집이 되는지"를 넣는다. 안 되면 형태 B로 간다.

## 5. 검토·게이트
- 작업자의 "끝"은 완료가 아니다. PM이 diff, 명령 출력, 산출물 경로를 확인한 뒤 PM-state에 완료로 적는다. 증거 없는 완료는 받지 않는다.
- 다른 모델 검토가 필요한 게이트:
  - 결과 전 실험 등록(config·판정 규칙)
  - 실험 실행 코드
  - 정책·서비스 승격
  - 2026 계약 변경
  - `interfaces/` 스키마
  - 데모 브랜치의 운영 교체
- 검토자에게는 커밋 범위, 완료 기준, 읽을 파일만 준다. 검토자는 정확성·요구사항 결함만 적는다.
- 검토 결과는 `docs/reviews/COOP-###-<검토 모델>-<주제>-YYYY-MM-DD.md`에 남긴다. 게이트를 여는 결정은 Song이 한다.
- 새 실험 실행은 목적, 바꾼 설정, 자원, 예상 시간을 `결정 필요`로 올려 승인받은 뒤에 한다. 승인된 계획 안의 재실행과 버그 수정 재시도는 바로 한다.

## 6. 충돌·자원
- 작업트리 하나에 쓰는 사람 하나. PM-state의 "맡은 작업트리"가 잠금이다.
- 메인 체크아웃
  - PM 파일: `docs/decisions.md`, `docs/PM-charter.md`, `docs/handoffs/PM-state.md`.
  - 작업자가 여기서 지시된 파일을 고치면 커밋은 PM이 확인 뒤 경로를 적어 한다. **커밋 끝줄은 실제로 쓴 모델로 적는다**(작업자가 썼으면 `Co-Authored-By: Claude Opus 5.5`). 검토자가 이 줄로 작성 모델을 판별한다.
  - stash·reset·checkout·브랜치 전환 금지. ` M runs`(심볼릭 링크)는 커밋하지 않는다.
- 다른 작업트리는 맡은 작업자가 커밋한다. `git add -A`·`git add .` 금지.
- push는 PM만, Song이 그 브랜치를 말했을 때만 한다. push 전 점검:
  - `demo/*`는 올리지 않는다(MLB 피드에서 나온 파일. 10/2 Song이 대화에서 고른 것이고 결정 줄은 아직 없다 → PM-state N6). 원격에는 9/30의 `origin/demo/ws-2026`만 있다.
  - `data/`·`runs/`·`*.jsonl`·`*.parquet`·`*.pt`·`watch/` 경로와 1MB 넘는 파일이 없는지
  - 비밀 문자열이 없는지
  - 올라갈 커밋의 작성 모델 줄이 맞는지
  - push 뒤 원격 확인 명령이 막히면 쪼개거나 바꿔서 다시 시도하지 않고 Song에게 알린다(허용 규칙은 [Song이 넣을 설정](handoffs/pm-drafts/settings-for-song.md) 2번).
- PR merge는 Song 승인 전 금지.
- `/Users/song/Projects/pitcheezy-demo`(운영 체크아웃)와 tmux `pz` 창은 Song이 정하기 전 아무도 건드리지 않는다. 기록기·대조·요약 루프가 그 폴더의 스크립트를 나중에 실행하기 때문이다.
- 팀원 레포는 읽기만 하고, 연락은 Song이 한다.
- 무거운 실행(학습·정책 검증·OPE)은 전체에서 한 번에 하나다. `ML-MATRIX-20260924/.heavy.lock`을 쓰고 Claude 밖 tmux 창에서 돌린다.
- GPU 서버는 `/Users/song/.local/bin/gpu` 전체 경로로 부른다. 이 맥의 셸에서 `gpu`는 `git push upstream` 별칭이 먼저 잡힌다.
- **동결**: `…/DEMO-WS-2026/live_rehearsal/ds/all.done`이 생기고 Song이 확인할 때까지 [운영 동결 문서](handoffs/OPS-freeze-and-restart-2026-10-04.md) §1을 지킨다. 그동안 작업자는 동시에 2개까지(제안값, N8), 문서·읽기만. 메인 체크아웃에서 `.py`·`.yaml`·`.yml`을 고치지 않는다(편집할 때마다 `pytest tests -q -x`를 돌리는 훅이 있다).
- 2026 자료는 학습·튜닝·선택에 쓰지 않는다. 숫자는 지어내지 않고 출처를 붙인다(없으면 "미측정").
- 작업자를 여럿 부르기 전에 사용량을 본다. Fable은 PM과 게이트 검토에만 쓴다.
