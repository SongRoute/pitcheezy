# pitcheezy-handoff

Read the canonical repository's `docs/pm/workflow.md`, `docs/pm/contracts.md`, and `docs/pm/transfers/README.md`. Use the existing transfer schema instead of creating a parallel tracker.

Identify the sending and receiving PM and one active writer. Pin code, data, model and evidence paths; distinguish exploratory candidate, integration candidate, and approved production use. Include missing evidence and a concrete next action. The receiving PM must explicitly accept responsibility or return reasons before marking the transfer accepted.

Native agent messages are transient assistance, not guaranteed cross-chat delivery. Preserve the transfer in the shared canonical repository; do not claim that a new persistent app session or automatic monitor exists. For separate sessions use `docs/pm/kickoff.md` and transfer ownership without duplicate writers or runs.
