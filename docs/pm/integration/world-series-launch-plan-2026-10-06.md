# 월드시리즈 개발 방향과 점검 가설

소유: 통합 문서 담당 · 갱신: 사용자 방향/2~3일 진척 점검 · 마지막 확인: 2026-10-06 시연 종료 후 사용자 지시.

## 목표 시점과 유동적인 범위

월드시리즈에 맞춘 실서비스 개발을 목표로 한다. **최종 기능·공개 형태·출시일은 지금 고정하지 않고 실제 개발 속도로 정한다.** 빠르면 기능을 추가하고, 늦으면 기본 기능에 집중해 배포한다. 10/21 공개·초대 베타는 확정안이 아니다.

[MLB 공식 일정](https://www.mlb.com/news/2026-mlb-playoff-and-world-series-schedule)의 미국 1차전 날짜는 **10/23**, [시작 시각은 TBD](https://www.mlb.com/postseason)다. 정확한 한국 시간은 발표 후 정한다. 일정과 재배포 권한 근거는 [공식 조사](/Users/song/Projects/pitcheezy-pm-jobs/20261006-world-series-readiness/schedule-rights-001/REPORT.md)에 있다.

사용자 경험의 정본은 [함께 고민하는 투구 선택](../../product/experience.md)이다. 초보·중급 팬이 선택·수행·결과를 구분하며 즐기는 보조 시청 경험을 지향한다.

## 먼저 연결할 경로와 확장 후보

**실제 피드 → 중복·정정에 맞는 공 상태 → 투구 전 특성/추천 → 관람 화면 자동 갱신.** G0 artifact 로드와 실제 추론 지연·지원 범위도 준비됐다고 가정하지 않고 확인한다. 기능 UI의 로딩·미지원·지연·재접속 상태는 이 경로와 함께 검증한다.

핵심 경로가 예상보다 빠르게 검증되면 미트 CV, 유인구/존 밖 추천, 영상 동기화, 새 모델 등의 후보를 하나씩 추가 검토한다. 순서는 사용자 가치·필요 데이터·검증 비용·남은 시간으로 정하며, 자동 채택이나 영구 제외는 없다. 늦으면 지원 범위와 부가 기능을 줄여 기본 흐름을 완성한다. 연구 실행과 서비스 런타임은 격리한다.

## 2~3일마다 범위 재검토

기록할 것은 **실제 기기 E2E 검증 완료 기능 / 남은 일수 / 막힘 / 직전 기간 완료 속도 / 다음 작은 작업**이다. 코드 작성량과 합성 검사만으로 완료 속도를 세지 않는다. 공개 형태는 지금 답변을 요구하지 않고 이 증거가 쌓일 때 정한다.

기능 축소와 별개로 정확한 공 상태, 미래 정보 누수 방지, 오류·지연 표시, 권한, 복구는 지킨다. 단계별 필요조건과 공동 수용 기준은 [workflow](../workflow.md), 과학·데이터 경계는 [contracts](../contracts.md)가 정본이다. 지연/제공률 수용선도 대상 분모와 실제 측정을 보고 합의하며 임의의 숫자를 정책 채택으로 바꾸지 않는다.
