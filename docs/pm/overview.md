# Pitcheezy — 세 PM 운영 진입점

시행: 2026-10-06 Song 승인. 단기 10/6 16:00 시연, 최종 실서비스, 보조 논문화. 개발 우선순위는 성능 개선 → 실시간 처리 → UI/UX이며 시연 시간·기록기는 자원 계획에 반영한다.

## 역할과 모델

| 역할 | 책임 | 모델 정책 |
|---|---|---|
| 통합 PM(현재 Root 세션) | 전체 목표, 자원·계약 충돌, 인계 수용, Song 통합 보고 | Astra `gpt-6-astra` |
| 연구 PM | 실험 설계·실행 큐·평가·재현·논문화 | Astra `gpt-6-astra` |
| 서비스 PM | 백엔드·프런트·CV 연결·DB·수집·운영·시연 | Astra `gpt-6-astra` |
| 실행·검토 작업자 및 재귀 하위 작업자 | PM이 지정한 유한 범위 실행 | PM 판단으로 Sol `gpt-6-sol` 또는 Astra |

세 PM은 관리·위임·읽기 전용 증거 검토·수용만 한다. 실질 조사·구현·테스트·실험·기록·통합은 작업자가 한다. Sol은 명확한 범위의 구현·반복 검사·정리, Astra는 복합 설계·과학 검토·어려운 원인 분석을 우선 고려하되 고정 분업이 아니다. 실제 호출 모델과 선택 이유를 작업 기록에 남긴다. Opus 소진을 기다려 Sol을 쓰는 예전 제한은 폐기한다. 재귀 위임을 허용하되 권한·자료·자원 범위는 확대되지 않는다.

## 실행 현실

현재 협업 도구는 Root 포함 동시 4개 활성 슬롯이다. 3개 PM과 전환 작업자를 모두 활성 상태로 유지하면 구현 슬롯이 없다. PM은 인수·배정 후 반환하고 필요할 때 다시 호출하거나, PM별 작업을 순차 활성화한다. 재귀 깊이 자체를 임의로 2단계로 제한하지 않지만 슬롯·중복 실행·비용을 확인한다.

이 문서는 논리적 역할 분리다. 네이티브 하위 에이전트를 별도 영구 앱 채팅 세션이나 항상 실행 중인 감독기로 부르지 않는다. 별도 사용자 세션은 [kickoff](kickoff.md)로 시작하고 소유권을 명시적으로 넘긴다. 채팅 사이 자동 메시징·백그라운드 연속 실행·전용 MCP/설치된 스킬은 이번 문서 전환만으로 생기지 않는다.
