# 공동 작업큐

상위: [작업 절차](workflow.md) · 시작: [kickoff](kickoff.md)

[공동 작업큐 #37](https://github.com/SongRoute/pitcheezy/issues/37)의 추가 전용 댓글이 소유권·최신 작업 상태의 정본이다. [상황판 #35](https://github.com/SongRoute/pitcheezy/issues/35)는 목표·진행·막힘 요약이다. 본문·초기 계획은 스냅샷이며 고정 계약·실행 증거를 대체하지 않는다.

## 한곳에서 계획하고 선점하기

Song·Claude Code·Codex는 시작과 쓰기 직전 최신 댓글을 페이지 누락 없이 읽는다. 같은 계정이어도 actor/session을 구분하고 대리 기록은 reported_by를 적는다. 큐는 원자적 lock이 아니므로 파일과 운영 자원 점유를 별도로 확인한다. 보호하는 기존 소유자의 ACK·명시 인계 없이 범위를 가져오지 않는다. 무응답·시간 경과는 해제가 아니다.

최신 사용자 발신 권한이 있을 때만 PLAN/CLAIM·재조회·종료 댓글을 쓴다. 이번처럼 이슈 발신이 금지된 작업은 읽기 조회와 로컬 범위 기록만 남기며 원격 선점 완료라고 주장하지 않는다. 이미 유효하게 점유된 범위를 이 예외로 덮을 수 없다.

## 상태와 댓글 동작

| 상태 | 의미 |
|---|---|
| PLAN / READY | 완료 조건과 선행 입력을 준비한 제안. 추천 담당은 수락이 아님 |
| RESERVED | 기존 소유권 또는 당사자가 수락한 예약. 실행 중이라는 뜻이 아님 |
| CLAIM / ACTIVE | 선점 절차를 충족한 착수, 정확한 파일·자원 범위 |
| REVIEW | 고정 커밋·검토 증거 제출, 소유권 유지 |
| BLOCKED | 막힘·필요 입력·다음 확인 기록, 소유권 자동 반환 아님 |
| RELEASE | 편집·실행 중단과 변경/자원·인계 상태를 적고 명시 반환 |
| DONE | 완료 조건·필요 검토·수용 근거를 갖춘 종료와 범위 반환 |
| DEPENDENT | 선행 완료·사람 결정이 없어 착수할 수 없는 계획 |

소유권 변경은 당사자의 댓글 또는 지시를 인용한 대리 기록으로만 한다. 본문 지정 편집자는 최신 유효 이력으로 확인하며 다른 참여자는 허가된 댓글만 쓴다. 하위 에이전트는 대표 세션이 실제 작성·검토자를 구분해 기록한다. 준비할 다음 작업은 작은 하나를 권장하고 넓은 폴더를 장기 선점하지 않는다.
