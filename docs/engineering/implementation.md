# 구현 원칙

상위: [AGENTS](../../AGENTS.md) · 검사: [verification](verification.md)

문제를 끝까지 추적한 다음 아래에서 처음 충족하는 방법을 쓴다.

1. 실제 필요한 변경인지 확인한다.
2. 저장소의 기존 함수·패턴을 재사용한다.
3. 표준 라이브러리, 플랫폼 기능, 설치된 의존성 순서로 찾는다.
4. 그래도 필요할 때 가장 작은 올바른 구현을 만든다.

새 추상화·의존성·보일러플레이트를 필요 없이 추가하지 않는다. 버그는 모든 호출자를 확인하고 공통 원인을 고친다. 단순함은 입력 검증·오류 처리·보안·접근성·하드웨어 보정·사용자 요구를 생략하는 이유가 아니다. 알려진 한계가 있는 단순화는 `ponytail:` 주석에 한계와 확장 조건을 적는다.

의미 있는 변경은 실패를 잡는 기존 회귀 검사 또는 최소 실행 검사를 남긴다. 기존 테스트 프레임워크를 활용한다. 자명한 문구·한 줄 변경을 위해 구현을 그대로 복제하는 테스트를 만들지 않는다.

## 연구 예외

비교 모델·baseline·ablation은 중복 제거 대상이 아니다. 실험 config·seed·로그·평가·누수·identity/replay 게이트의 등록 의미를 합치거나 약화하지 않는다. 동결 소스는 보존한다. 과학적 동작이 같을 때만 공통 함수를 재사용하고, 프로토콜이 요구하면 별도 구현을 유지한다. Graphify 관계만으로 연구 변형의 불필요함을 판정하지 않는다.

이 원칙은 앞으로 수행할 변경에 적용한다. 기존 코드를 일괄 재작성하거나 전역 도구 설정을 바꾸는 권한이 아니다. 설계·스키마 변경은 [결정 원장](../decisions.md)과 [인터페이스 계약](../interface-spec.md)의 해당 변경 절차를 따른다.
