# Pitcheezy 목표 중심 로드맵

작성: 2026-09-22. 사용자가 제시한 최종 목표에서 역산한 제품·연구 통합 계획 (D43).
같은 날 병렬 세션이 각각 쓴 `GOAL_ROADMAP.md`(본문)와 `roadmap.md`(의존성 순서·위험)를 하나로 합쳤다 (D45).
이 문서가 **목표와 순서의 출처**다. 지금 하는 일은 `plan.md`, 결정 한 줄은 `decisions.md`, 설계 세부는 `design.md`.
기존 실험의 결과와 구현 기록은 보존한다. 이 문서의 완료 기준은 앞으로의 계획이며, 성능 달성이나 개발 완료를 뜻하지 않는다.

## 1. 최종 목표

**야구 팬이 실제 경기를 보면서 다음 공의 최선의 선택을 이해하고, 실제 투구와 비교하며, 중요한 결과에 영향을 준 요인의 비중을 근거와 함께 확인하는 웹페이지를 완성한다. 그 핵심 모델은 추가 정보를 활용해, 공정한 비교에서 기존 연구 기반 모델보다 좋은 추천 성능을 보여야 한다.**

팬이 한 화면에서 다음 세 질문에 답할 수 있어야 한다.

1. **다음 공:** 이 투수가 이 타자에게 지금 어떤 구종을 어느 목표 구역에 던지는 것이 가장 유리한가? 다른 후보보다 왜 유리한가?
2. **실제 공:** 실제 구종과 홈플레이트 통과 위치는 무엇이었나? 추천·추정 목표·실제 투구가 어떻게 달랐나?
3. **중요 사건:** 홈런·삼진·볼넷·병살·중요 교체에서 타자 수행, 투수 실행, 구종/배합 선택, 교체 판단이 결과에 얼마나 기여했다고 추정할 수 있나?

‘최적’은 **지원하는 선수·행동·데이터와 모델의 불확실성 안에서 수비 팀의 기대 승리 확률을 가장 높이는 선택**으로 정의한다. 비슷한 후보는 함께 제시하며, 근거가 부족하면 추천 범위를 줄이거나 판단을 보류한다. 매번 결과를 맞히는 것과 좋은 선택을 하는 것은 별도다. 좋은 추천 뒤 홈런이 나와도 그 한 번의 결과만으로 잘못된 추천이 되지는 않는다.

제품의 최종 완료에는 세 기능, 연구 성능 검증, 실제 팬 사용 검증, 경기 데이터 연동과 운영이 모두 필요하다. 기록 재생판은 첫 출시 단위이며 최종 경기 참고 서비스로 가는 중간 단계다. 중요 사건 분석을 ‘시간이 남으면 하는 기능’으로 두지 않는다.

### 이 목표가 바꾼 것

- **4자 분해는 후순위가 아니다.** `design.md` §0-f의 전략·투수·타자·벤치 분해가 곧 기능 3(G4)이다.
  D7("분해는 Phase 2 후순위")은 최종 목표의 3분의 1을 뒤로 미루는 셈이므로 D43으로 대체했다.
- **의도(목표 위치)가 필수 경로다.** 분해에는 기준점이 필요한데 Statcast 에 의도가 없다.
  기준점이 없으면 계획 오류와 실행 오류를 가를 수 없다. CV·사람 검토 목표 라벨은 "있으면 좋은 기능"이
  아니라 G4의 **선행조건**이다 (M1).
- **신뢰가 요구사항이 됐다.** 정확도만이 아니라 근거 제시·확률 보정·미지원 상황의 정직한 표시가
  같은 급의 목표다 (G6). `apps/observer`가 이미 지키는 원칙을 목표로 승격한다.
- **채택 판정은 그대로 e2e 정책 평가로만 한다.** 예측 지표(NLL·보정)는 스크리닝용이다.

### 결정이 필요한 것 — 가치 단위

M0 는 기본 문제를 **수비 팀 승리 확률(WE)** 로, RE24 를 보조 진단으로 두자고 제안한다.
그런데 `design.md` §0-c·§0-d B 는 학습 보상을 리그 공통 RE24 로 고정하고 WE 를 기각했다
(WE 상태 수천 개 → 투수별 모델에서 희소, OPE 분산 증가). 현재 동결 실험(P0·P1)은 RE24 위에 있고,
`apps/observer`는 WE 로 계산한다. **둘을 한 표에 섞기 전에 결정 한 줄이 필요하다.**
그때까지 두 트랙의 수치를 같은 근거로 인용하지 않는다.

## 2. 현재 출발점

2026-09-22 저장소의 결과 문서 기준이다. 이번 로드맵 작성 중 재학습·성능 실험은 수행하지 않았다.

| 영역 | 현재 확인된 자산 | 목표까지 남은 일 |
|---|---|---|
| 웹 관전 흐름 | 로컬에서 12경기·249타석·975구의 추천→실제 공개→비교, 선수 이름·탐색·기록 저장 | 실제 팬 평가, 지원 범위 확대, 외부 운영·경기 연동 |
| 구종·위치 추천 | 기존 모델과 관측 투구 분포를 이용한 구종×구역 추천 | 목표를 바꿀 때의 실행 분포와 추천 효과 검증 |
| 추가 요소 연구 | 타자 성향·과거 투구·경기 상황의 예측 실험, 기존 RE24 연구의 제한된 기준선 대비 우위 기록 | 현재 서비스 모델의 공통 정책 비교와 미열람 기간 재확인 |
| 위치 개선 | 예측이 좋아져도 정책 평가가 나빠진 후보를 기각하고 기존 모델 유지 | 예측 향상이 실제 추천 품질로 이어지는 개선 축 찾기 |
| 영상·목표 위치 | 실제 짧은 영상과 검토/추적 도구, AI 추정 라벨 | 사람이 검토한 셋업 라벨, 좌표 보정, 독립 검증 |
| 사건별 기여 | 추천 후보의 근거 설명 기반 | 타자·투수·작전·교체를 함께 다루는 검증된 기여도 모형 |

**기존 `src/pitcheezy`의 RE24/OPE 결과와 `pitchmdp`에서 이어진 웹페이지 모델의 승리 확률 결과는 별개다.** 전자의 B1 대비 개선을 후자의 성능 증명으로 쓰지 않는다. 현재 전체 서비스에 대해 ‘기존 연구를 능가했다’고 결론 낼 수 없다.

## 3. 최종 목표를 이루는 일곱 서브목표

| ID | 서브목표 | 필수 산출물 | 완료 판단 |
|---|---|---|---|
| G1 | 투구 시점의 상황과 실제 기록을 정확히 재현 | 경기/투구 ID, 입력 가능 시각, 선수 프로필, 실제 구종·위치, 데이터 품질 보고서 | 사전 정보 누수 없음, 잘못된 투구 연결 없음, 누락·정정 처리 검증 |
| G2 | 실행 가능한 구종·목표 위치 추천 | 선수별 구종 후보, 목표→실행 분포, 결과·가치 모형, 상위 후보와 차이 | 공통 평가에서 추천 가치 개선; 지원률·보정·불확실성 기준 통과 |
| G3 | 추천과 실제 투구를 정확하고 쉽게 비교 | 같은 존의 목표 구역·실제 좌표, 실제 결과와 추천 당시 기록 | 좌표·좌우·타자 존 대조, 사후 추천 변경 차단, 팬의 비교 과제 성공 |
| G4 | 중요 사건의 기여 비중 설명 | 작전·실행·타자·교체의 수치, 상호작용·잔여분, 근거와 범위 | 수치 정합성, 입력/기준 변경에 대한 안정성, 사람이 검토한 근거, 원인 표현의 적절성 |
| G5 | 기존 연구보다 좋은 성능과 개선 이유 입증 | 재구현 비교표, 요소별 추가/제거 실험, 재현 번들 | 사전 정의한 공통 정책 지표에서 가장 강한 해당 기준선 대비 개선, 미열람 기간 재확인 |
| G6 | 팬이 이해하고 적절히 신뢰하는 경험 | 한 화면의 관전 흐름, 쉬운 근거 설명, 성능 이력 | 추천·실제·추정을 구분하고 근거와 한계를 이해하는 팬 평가 통과 |
| G7 | 실제 경기에 사용할 수 있는 서비스 운영 | 웹 배포, 지연/라이브 이벤트, 중계 동기화, 운영 감시·복구 | 다음 공 전 추천 제공 여부와 데이터 지연 측정, 동시 사용자·장애 시나리오 통과 |

G1은 모든 목표의 공통 기반이다. G2와 G5는 함께 반복한다. G4의 데이터 확보는 초기에 시작하고 G2의 가치 모형을 공유한다. G3·G6은 기존 화면에서 계속 개선한다. G7의 기록 재생 배포는 먼저 가능하며 실시간 연결은 데이터 공급과 지연 검증 후 확장한다.

## 4. 단계별 실행과 통과 기준

### M0 — 범위·검증 기준 고정

목적: 무엇을 만들어야 완성이고 무엇을 측정해야 더 좋아졌다고 말할 수 있는지 고정한다.

- 첫 지원 범위는 기존 자료가 있는 MLB 선발투수로 시작한다. 지원 선수는 평가 결과가 아닌 학습 기간 정보로 선정한다.
- 구종+목표 위치, 다음 한 구 추천+타석 종료까지 계획, 수비 팀 승리 확률을 기본 문제로 정한다. RE24는 보조 진단으로 보존한다.
- 예측, 정책, 설명, 제품 지표를 분리한다. 현재 웹페이지의 모델·버전·결과를 기준점으로 고정한다.
- 선행연구 재현 사양, 비교 가능한 카운트·행동·정보, 개발/최종 평가 기간, 평가 지표와 최소 의미 있는 개선폭을 결과 열람 전에 문서화한다.
- 기존에 결과를 보고 판단한 2026 구간은 새로운 미열람 시험셋으로 취급하지 않는다. 아직 보지 않은 시점 이후 구간 또는 향후 기간을 확증용으로 잠근다. 2026은 기존 원칙대로 정책 학습·튜닝에 사용하지 않는다.

**산출물:** 제품 요구사항, 비교 사양, 데이터 노출 이력, 현재 성능표. 측정하지 않은 값은 ‘미측정’으로 둔다.

### M1 — 실제 기록·목표 위치·교체 정보 확보

목적: 추천과 사건 설명에 필요한 입력을 만든다. 새 모델 학습보다 먼저 시작한다.

- 기존 재생 데이터의 구종·실제 좌표·상태 연결을 유지하고 좌표 누락·기록 정정·투구 순서 오류를 검사한다.
- 투구 전 포수 셋업을 사람이 검토한다. 실제 도달 위치를 목표 정답으로 사용하지 않는다. 미트 셋업도 투수의 진짜 의도를 완전히 관측한 값은 아니므로 대리 라벨임을 보존한다.
- 학습용·검증용 영상을 경기/카메라/선수 단위로 나눈다. 삼진 모음만으로 학습·평가하지 않고 일반 투구와 실패 투구도 포함한다. 필요한 표본 규모는 첫 라벨의 일치도와 목표 오차 폭으로 정한다.
- 라벨링 시 미래 결과와 모델 추적 출력을 가리고, 복수 검토자의 일치도·기권률·좌표 변환 오차를 측정한다.
- 교체 분석용으로 당시 명단·가용 불펜·최근 등판/휴식·타순·교체 시점 정보를 준비한다. 비공개 준비 상태는 모르는 변수로 남긴다.
- 운영 CV는 기존 방침대로 타석 마지막/주요 투구 중심으로 실행한다. 학습 표본은 이 선택 규칙과 별도로 구성해 편향을 관리한다.

**통과 기준:** 추천→실제 연결이 정확하고, 목표/실행 구분과 교체 대안 비교에 사용할 독립 표본이 있다. 영상이 없는 공은 관측 비교를 제공하되 전략·실행의 분리 수치를 만들지 않는다.

### M2 — 더 많은 요소를 활용하는 추천 모델

목적: 타자·투수·배합·상황을 반영해 실제로 실행 가능한 선택의 가치를 계산한다.

모형의 흐름:

`투구 전 상태 → 가능한 구종×목표 구역 → 실행 위치·구위 분포 → 결과·진루 분포 → 타석 이후 승리 가치 → 추천`

| 우선 축 | 추가 정보/모형 | 검증할 질문 |
|---|---|---|
| 1. 제구 | 목표 셋업, 구종별 목표→도달 오차, 오차의 불확실성 | 이 투수가 실제로 던질 수 있는 위치를 추천하는가? |
| 2. 투수·타자 특성 | 투수별 구종/구위, 타자 연속 성향과 좌우·구역별 반응 | 전체 평균/단순 빈도보다 대결별 선택이 좋아지는가? |
| 3. 배합·당일 변화 | 직전 투구의 구종·위치·구속차, 스윙 반응, 투구 수·대결 회차·이전까지의 구위 변화 | 정적인 선수 성향에 없는 추가 이득이 있는가? |
| 4. 경기 가치 | 카운트·주자·아웃·점수·이닝·향후 타순 | 삼진·땅볼·볼넷·장타의 가치 차이를 추천에 반영하는가? |
| 5. 환경·운영 | 가용 불펜·휴식, 수비/포수, 구장·날씨 등 확보 가능한 정보 | 추가 비용과 결측을 감수할 만큼 정책을 개선하는가? |

현재 구속·회전·실제 위치처럼 투구 후에야 아는 정보는 다음 공 추천에 정답으로 넣지 않는다. 이전까지의 관측으로 분포를 예측하고 평균낸다. 피로·심리 상태는 투구 수나 결과만으로 사실처럼 라벨링하지 않는다.

기존 실험에서 이력·군집의 추가 효과가 미확인이었던 점을 반영한다. 같은 실험을 그대로 반복하지 않고 새 데이터·표현·평가 가설이 있을 때 다음 후보를 만든다. 모델 규모 자체를 성공 조건으로 삼지 않는다.

**통과 기준:** 지원 구역의 실행 분포와 주요 사건 확률이 검증되고, 후보가 M3의 공통 정책 평가를 통과한다. 예측 점수만 좋아진 후보는 서비스 교체 조건을 충족하지 않는다.

### M3 — 선행연구 대비 개선 검증

목적: ‘많은 요소를 쓴다’를 ‘추가 요소 때문에 더 좋은 선택을 한다’는 근거로 바꾼다.

- 주요 비교 대상은 SmartPitch, Takamido & Nakamoto, 목표/제구를 다루는 Douglas 등의 접근이다. Melville의 시퀀스·제구 접근도 문헌 비교에 포함하고, 재현 가능한 범위와 차이를 기록한다.
- 논문 충실 재현과 우리 과제에 맞춘 변형을 구분한다. 아직 충실도를 확인하지 않은 단순화 버전을 이겼다는 이유로 원 연구 전체를 이겼다고 쓰지 않는다.
- 같은 데이터·시간 분할·지원 선수·행동 공간·시점별 입력·튜닝 예산에서 비교한다. 모든 카운트의 과제와 2스트라이크 전용 과제는 별도 표를 만든다.
- 현재 서비스 모델, 강한 빈도/단순 기준선, 재구현 모델, 확장 모델을 함께 평가한다.
- 요소 하나씩 추가하는 비교와 전체 모델에서 요소 하나씩 제거하는 비교를 모두 한다. 모델 용량 증가·튜닝량·추가 데이터량 효과도 구별한다.
- 투구 결과 예측은 log loss/Brier/확률 보정, 추천은 공통 타석의 수비 측 기대 승리 확률 차이, 실점 변화는 보조 지표로 측정한다.
- 정책 평가에는 행동 겹침·유효 표본·지원률을 함께 보고한다. 경기 단위 짝지은 신뢰구간과 다중 비교 관리를 사용한다. 낮은 지원률의 일부 사례만 좋아진 것을 전체 개선으로 부르지 않는다.
- 한 구만 정책을 바꾼 평가, 타석 전체 정책 평가, 목표 위치를 바꾼 개입은 다른 주장이다. 1스텝 OPE를 전체 경기 효과로 확대하지 않는다.
- 목표 행동이 기록되지 않은 데이터에서 실제 도달 위치를 ‘선택한 목표’로 취급한 OPE는 목표 추천의 인과 효과를 식별하지 못한다. 분리된 평가 모델도 이 문제를 저절로 해결하지 않는다. 라벨이 있어도 숨은 교란과 의도 대리 측정의 한계는 남는다.

**통과 기준:** 사전에 지정한 지원 범위와 평가 방식에서 가장 강한 해당 기준선 대비 개선을 확인하고, 최소 한 개 추가 요소의 기여를 제거 실험으로 확인한다. 효과 크기·신뢰구간·지원률을 함께 통과해야 한다. 이후 새 기간의 사전 예측 기록으로 재확인한다. 개선이 없거나 평가가 불가능하면 미달로 남기고 데이터·지원 범위·모형을 수정한다.

실제 선수들이 추천대로 던졌을 때의 효과까지 입증하려면 별도 전향적 개입 연구가 필요하다. 팬의 웹 사용 실험이나 실제 투구와 추천의 일치율로 이를 대신하지 않는다.

### M4 — 중요 사건의 원인 기여 추정

목적: 홈런·삼진 등의 원인을 숫자로 이해하게 한다. M1부터 자료를 준비하고 M2·M3와 함께 발전시킨다.

먼저 두 질문을 분리한다. ‘왜 홈런 확률이 높았나’는 사건 확률을, ‘그 플레이가 경기 승패에 얼마나 중요했나’는 승리 확률 변화(%p)를 사용한다. 서로 다른 단위의 값을 같은 비율표에 합치지 않는다.

| 성분 | 비교 기준 | 필요한 근거 |
|---|---|---|
| 작전/배합 | 같은 투수·상황에서 선택한 구종/목표와 실행 가능한 대안 | 관측/추정한 선택, 구종·목표별 결과 모형 |
| 투수 실행 | 선택한 목표에 대한 통상 실행 분포와 실제 위치·구위 | 검토된 목표 대리 라벨, 제구 모형, 실제 측정 |
| 타자 수행 | 비슷한 실행 조건에서 기대하는 반응과 관측 스윙·타구 | 타자 성향, 스윙/컨택트·타구 정보; 없는 정보는 미식별 |
| 교체 판단 | 당시 계속 던지게 하는 선택과 실제 가능한 교체 후보 | 가용 선수·휴식·타순, 이후 타석/이닝까지의 공통 평가 범위 |
| 기타·잔여 | 수비·구장·판정·우연·모형 오차·미관측 정보 | 관측 가능한 부분만 별도 추정; 잔여 전체를 ‘운’이나 ‘타자 실력’으로 명명하지 않음 |

- 교체→작전→실행→타자 반응의 선후관계를 모델링하고 중복 귀속을 막는다. 교체 뒤 존재할 수 없는 선수/공 조합을 반사실 후보로 만들지 않는다.
- 기준 상황과 분해 순서를 사전에 정한다. 순서에 따른 차이 또는 상호작용을 공개한다. SHAP 같은 예측 설명값 자체를 선수의 인과적 책임이라고 부르지 않는다.
- 기본 출력은 부호가 있는 확률 차이 또는 승리 확률 %p다. 비중은 정해진 분모에 대한 설명 성분의 상대적 크기로 제시하고, 증가/감소 방향·상호작용·미설명분을 같이 보여준다. 부호가 상쇄되거나 총변화가 작은 경우 억지로 백분율을 만들지 않는다.
- 네 주체에 무조건 100%를 배분하지 않는다. 사람 검토 셋업이 있어도 실제 사인 결정자가 누구였는지는 별개의 미관측 정보다. 구종 선택의 평가를 자동으로 감독·포수 개인 책임으로 바꾸지 않는다.
- 합이 맞는 것은 계산 검증이다. 원인 분해의 타당성은 라벨 신뢰도, 반사실 지원, 기준점/모형 변경에 대한 민감도, 숨은 교란 검토로 따로 확인한다. 전문가 의견과 맞는 것만으로 인과적 정답을 입증하지 않는다.
- 홈런·삼진 등 사건군과 높은 레버리지 상황의 선택 규칙은 평가 전에 고정한다. 보기 좋은 사례만 뽑지 않는다.

**통과 기준:** 독립 사건 표본에서 근거를 추적할 수 있고, 수치 합·부호·단위·중복 귀속을 검증한다. 타자·투수·작전·교체 각각에 지원 사례와 판단 불가 사례가 있어야 한다. 사용자 화면은 ‘모델이 추정한 기여’로 표현하며 증거가 부족한 실제 인과 책임을 확정하지 않는다.

### M5 — 한 화면의 제품 완성·팬 검증

목적: 모델 결과를 경기에서 이해하고 참고할 수 있는 정보로 전달한다.

- 투구 전: 추천 구종·목표 구역, 대안, 차이가 나는 핵심 이유, 정보 부족 상태.
- 투구 후: 사전 저장한 추천 위에 실제 구종·좌표·결과 표시. 미래 결과를 본 뒤 추천을 다시 쓰지 않는다.
- 중요 사건: 기여도 막대, 증가/감소 방향, 미설명분, 펼쳐 보는 근거와 비교 기준.
- 초기 실제 팬 3~5명으로 사용 문제를 찾는다. 이후 별도 사용자로 한 타석 진행·비교·설명 이해를 검증한다. 작은 첫 표본의 만족도를 전체 팬의 신뢰로 일반화하지 않는다.
- ‘모델을 무조건 믿는다’보다 추천과 실제를 구분하고, 불확실한 상황을 알아보며, 근거를 보고 선택을 납득하는지 측정한다. 처음 제시하는 사용성 목표는 독립 진행/핵심 정보 이해 성공률 80% 이상으로 두되, 파일럿 후 본 평가 전에 표본수와 판정 기준을 고정한다.
- 정확한 추천도 결과가 나쁠 수 있는 사례, 후보 간 차이가 작은 사례, 모델이 기권해야 하는 사례를 평가에 포함한다.

**통과 기준:** 팬이 도움 없이 관전 흐름을 완료하고, 사실·추정·불확실성을 올바르게 이해한다. 기능 3의 수치가 없거나 연구 검증이 미달이면 최종 완성으로 선언하지 않는다.

### M6 — 실제 경기 연동·운영·지속 검증

목적: 제한된 기록 재생판에서 실제 경기 참고 서비스로 확장한다.

- 공급원의 구종·좌표 제공 시점, 이용 범위, 정정 방식과 지연을 확인한다. 원본 영상 서비스는 별도이며 필수 의존성으로 만들지 않는다.
- 과거 경기 공개 베타→지연 경기 연동→라이브 순으로 진행한다. 중계 지연을 맞추고 미래 결과가 먼저 노출되는 것을 막는다.
- 공급원 지연과 모델 응답 지연을 따로 측정한다. 초기 서버 목표는 명시한 동시 접속 부하에서 추천 API p95 1초 이내로 두고, 실제로 다음 공 전에 제공한 비율을 핵심 운영 지표로 기록한다. 현재 로컬 응답 속도를 운영 성능으로 환산하지 않는다.
- 누락·순서 역전·수정 이벤트, 모델 장애, 추적 실패에 대응하고 추천/설명/모델 버전을 보존한다.
- 확률 보정·지원률·하위집단 성능 변화를 감시한다. 재학습 후보는 고정된 기존 모델과 비교한 뒤 배포한다.

**통과 기준:** 실제 팬이 지원 경기를 보면서 세 기능을 이용하고, 해당 모델의 검증 근거가 연결되며, 지연·장애·미지원 상황을 처리한다.

## 5. 순서와 다음 한 가지

**날짜로 관리하지 않는다 (D44).** 발표·중간보고·자체 마감·주차표·신규 실험 컷라인은 계획의 기준이 아니다.
개발을 진행하고, 발표가 필요해지는 시점에 그때까지 된 만큼 발표한다. 순서는 날짜가 아니라 **의존성**이다.

```
M0 (범위·검증 기준)
  └→ M1 (기록·목표 라벨·교체 정보)  ──┬→ M2 (추천 모델) ──→ M3 (선행연구 대비 검증)
                                      └→ M4 (사건 기여 분해)
                                             M2·M4 ──→ M5 (제품·팬 검증) ──→ M6 (연동·운영)
```

- **M1 이 전부의 앞에 있다.** 특히 사람 검토 목표 라벨은 코드가 아니라 영상 확보에 걸려 있어
  착수와 완료의 간격이 가장 크다. 가장 먼저 열어야 나중에 병목이 되지 않는다
- **M4 는 M2 의 가치 모형을 공유한다.** 분해는 추천 위에 얹히는 구조라 순서를 바꿀 수 없다
- **M3 는 M1·M4 와 독립**이라 언제든 병행할 수 있다
- **M5·M6 은 M2·M4 의 통과 뒤**. 기능 3의 수치가 없거나 연구 검증이 미달이면 완성으로 선언하지 않는다

유일하게 지키는 날짜는 **2026-09-27 이후의 2026 freeze** 하나다. 이건 일정이 아니라 데이터 사건이다 —
정규시즌이 끝나야 검증셋을 고정할 수 있다 (D2·D28). 2026 은 기존 원칙대로 정책 학습·튜닝에 쓰지 않는다.

## 5-a. 큰 위험 셋

1. **정책 평가 저울의 해상도.** 기존 트랙에서 요소를 더 넣은 축 3개(투수 임베딩·시퀀스 맥락 v0·v1)가
   모두 "구분 안 됨"이었고, 원인은 아이디어가 아니라 저울이었다 — 짝지은 Δ 의 95% CI 반폭이 타석 68k 에서
   0.001~0.0025 였고 고감도 τ·DR 로도 좁혀지지 않았다 (D30·D31). **"더 많은 요소 → 더 좋다"를 보이려면
   이 벽을 먼저 다뤄야 한다**: 표본 확대, 슬라이스 판정(2스트라이크에서는 신호가 있었다), 다른 추정량 중 하나
2. **의도 라벨 확보.** G4 전체가 여기 매달려 있다. 영상 모듈이 담당자 작업으로 분리되면서(D46)
   위험은 "영상 확보"에서 **"담당자 산출물의 도착과 적합성"** 으로 옮겨갔다. 지금 기능 3 을 막는
   단 하나의 기술 항목은 `annotated_image_zone → plate_feet` 보정이다 (D47). 그 전까지 9구역
   의도는 나오지 않고, 계약이 그것을 만들어내지 못하게 막는다
3. **성분 간 단위 불일치.** 교체·작전은 승리 확률(%p) 층이고 투구 선택은 사건 확률 층이다.
   같은 비율표에 합치지 않는다 (§4 M4 규칙)

## 6. 연구 근거와 문서 사용법

- [SmartPitch — MIT 공식 서지](https://dspace.mit.edu/handle/1721.1/145144): MDP와 지도학습 기반 전이로 투수·타자 대결의 투구 전략을 다룬다.
- [Takamido & Nakamoto — 2026 공개본](https://arxiv.org/abs/2606.17345): 결정구/셋업을 바꾼 모델 예측과 시즌 지표 환산을 다룬다. 해당 모델 내부 변화와 실제 정책 효과를 구분해 비교한다.
- [Douglas 등 — 원문](https://arxiv.org/html/2110.04321v1): 목표에 따른 도달 분포, 타자 반응, 타석 전략을 다룬다. 목표/실행 구분 자체를 새로 발명했다고 주장하지 않는다.
- [Melville — 공식 발표 페이지](https://www.sloansportsconference.com/research-papers/a-game-theoretical-approach-to-optimal-pitch-sequencing), [기존 원문 검토 기록](../experiments/pitchmdp/docs/RESEARCH_GAP_REVIEW.md): 시퀀스·제구 관련 비교 사양을 구체화할 때 참조한다.
- [MLB Statcast 필드 문서](https://baseballsavant.mlb.com/csv-docs): 실제 구종·위치와 경기 상태 필드의 정의 확인에 사용한다.

‘입력이 더 많다’는 연구 성과가 아니다. **추가 정보가 어떤 상황에서 결과 예측과 추천 가치를 개선했는지, 그리고 팬에게 어떤 더 나은 판단을 제공했는지**를 연결하는 것이 이 로드맵의 연구·제품 공통 완료 조건이다.
