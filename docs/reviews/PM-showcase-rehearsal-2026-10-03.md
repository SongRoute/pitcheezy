## 바뀐 것

1. **버그 수정 — 장면 전환이 영상 오류로 보이던 문제** (`Showcase.tsx`)
   - 원인: "이 공 다시 보기"로 `play()`가 진행 중일 때 장면을 바꾸면 장면 효과가 `pause()`를 호출하고, `play()`가 `AbortError`로 거부된다. 기존 코드는 모든 거부를 영상 실패로 처리해 "영상 재생을 확인하지 못했어요" 경고를 띄우고 다시 보기 버튼을 계속 비활성화했다.
   - 수정: `AbortError`만 실패에서 제외한다. 다른 거부(`NotAllowedError` 등)는 계속 경고로 처리한다.
   - 재현: 수정 전 Chromium에서 같은 작업(task) 안에 다시 보기와 다음 장면을 누르면 경고가 떴다(테스트 실패 `aborted play() is not a video error`). 수정 뒤 통과.
2. **레이아웃 수정 — 공개 버튼이 화면 밖에 있던 문제** (`showcase.css`)
   - 원인: 추천 iframe 높이가 760px(폰 700px)로 고정돼 있었다. 임베드 화면의 "실제 투구 공개" 바는 iframe 아래쪽에 고정되므로, 1440×900 화면에서 iframe 아래 끝이 화면 밖으로 나가 버튼이 보이지 않았다. Playwright 실제 클릭이 `element is outside of the viewport`로 실패했다.
   - 수정: 데스크톱 `min(760px, max(480px, 100dvh − 280px))`, 폰 `min(700px, 100dvh − 64px)`. 데스크톱은 페이지 맨 위에서, 폰은 비교 영역까지 내린 뒤 영역 전체가 한 화면에 들어간다(테스트가 위치를 단언).
3. **테스트 강화** (`tests/showcase-smoke.mjs`, 1440·390 폭 각각)
   - 실제 공개: 합성 `/api/watch/849843/reveal/{i}` 응답을 주고 iframe 안 버튼을 실제 클릭 → 합성 실제 투구 표시 확인.
   - 장면 잠금: 공개 후 iframe 안 →·←·→ 키와 `#i=0` 해시 변경에도 3구째·같은 공개 내용 유지.
   - 다시 보기·재선택 재마운트: 다시 보기 시 공개 내용이 사라지고 ~4초 뒤 정지, 다른 장면 선택 후 돌아와도 이전 공개가 남지 않음, 영상은 장면 시작점에서 멈춤.
   - 링크 식별: 복사되는 URL이 장면 0→`/watch?game=849843#i=2`, 장면 1→`#i=3`, "관전 화면 열기" href 일치, 장면 바꾸면 복사 안내 사라짐, 페이지 URL `scene` 유지.
   - 영상 상태: 불러오기 전 요청 0건·버튼 비활성 → 메타데이터 후 장면 시작(release−3초) 탐색·정지 → 재생 → 정지 시점(release+4초) 자동 정지 → 장면 전환 AbortError 경고 없음 → 미디어 자연 종료(ended) 경고 없음·다시 보기 재생 → 미디어 요청 실패 시 경고·버튼 비활성.

## 합성 매체와 한계 (미검증)

- 영상 URL 요청은 테스트 라우트가 가로채 로컬에서 만든 무음 WAV(8 kHz, 약 61.7초)로 응답한다. MLB 영상은 내려받거나 열지 않았다. 따라서 `<video>` 요소의 상태 전환만 확인했고 실제 H.264 디코딩·화질·표식 시점 정확도는 **미검증**.
- 합성 응답이 HTTP Range(206)를 지원해야 탐색이 됐다. Range 없이 200만 주면 Chromium이 탐색하지 못해 `currentTime`이 0에 머물렀고 앱은 이를 오류로 알리지 않는다. 실제 MLB CDN의 Range 지원은 **미확인**(원격 영상 조사는 범위 밖).
- Safari·iPhone·실제 Tailscale 환경의 재생·클립보드는 **미검증**. 실제 `http://` 주소(보안 컨텍스트 아님)에서는 `navigator.clipboard`가 없어 "길게 눌러 복사" 안내로 빠지는 것이 예상 동작이며, 테스트는 클립보드를 대체해 복사 문자열만 확인했다.
- 자동 재생 정책: 같은 작업 안의 클릭 재현을 위해 테스트 브라우저를 `--autoplay-policy=no-user-gesture-required`로 띄웠다. 실제 사용자 클릭은 사용자 제스처라 해당 없음.
- 관찰(미수정): 다시 보기를 누른 직후 포커스는 바깥 버튼에 있어, 스페이스를 누르면 iframe 안 공개가 아니라 클립 재시작이 된다. iframe 안을 한 번 누른 뒤에는 스페이스가 공개로 동작한다(테스트 확인). 키보드 시연 시 주의.
- 폰 폭에서는 비교 영역이 영상 아래라 바깥 페이지를 내려야 공개 버튼이 보인다. 실제 기기 스크롤 체감은 **미검증**.
