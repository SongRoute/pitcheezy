# WatchSummaryPanel — 경기 흐름 요약 화면 부품 (2026-10-03)

작업자: Claude Opus 5.5 (worktree `codex-showcase-api-1006`). 대상 API: `GET /api/watch/{gamePk}/summary?through=<k>` (`pitcheezy-watch-summary-v1`, 커밋 `7ea9ef8`, 계약은 `apps/observer/CONTRACT.md`).

## 만든 것

- `apps/observer/web/src/WatchSummaryPanel.tsx`: 독립 React 부품. 외부 의존성 없음. `short`(팀 한글 약칭)만 `./WatchAlong`에서 가져온다(`Game.tsx`·`Live.tsx`와 같은 방식).
- `apps/observer/web/src/watch-summary.css`: `.ws-` 접두사. `.wa-page` 안에 넣으면 그 색 토큰을 쓰고 어두운 화면도 따라간다. 밖에서는 밝은 기본색을 쓴다.
- `apps/observer/web/tests/watch-summary-panel.mjs`: 브라우저 검사. 자체 Vite 서버와 가짜 `/api` 응답을 쓰며 백엔드·실제 자료는 쓰지 않는다.
- 백엔드·기존 화면·기존 테스트는 바꾸지 않았다. 백엔드 결함은 찾지 못했다.

## PM 연결 방법

```tsx
import WatchSummaryPanel from './WatchSummaryPanel';   // 또는 { WatchSummaryPanel }
// 공개된 마지막 공의 index. 아무 공도 공개 전이면 -1.
<WatchSummaryPanel gamePk={gamePk} through={revealedIndex} />
```

- `through`는 **지금 화면에 공개된 마지막 공**이다. 다음 공의 투구 전 화면에 있을 때는 `index - 1`을 넘기고, 그 공을 공개하면 `index`를 넘긴다. 경기 전체를 보여줄 때만 `decisions.length - 1`을 넘긴다. 부품에 경기 전체를 기본값으로 쓰는 경로는 없다.
- 부품은 자기 CSS를 직접 불러온다. 따로 import할 필요가 없다.
- `WatchAlong.tsx` 안에 넣으면 두 파일이 서로를 불러오는 순환 import가 생긴다. `short`는 화면을 그릴 때만 쓰므로 동작에는 문제없다. 피하고 싶으면 `Game.tsx`나 상위 화면에 넣으면 된다.
- 요청: `/api/watch/{gamePk}/summary?through={through}&top=5`. 요청마다 `cache: 'no-store'`를 쓰고 `AbortController`로 취소할 수 있다.

## 동작

- **줄 점수표**
  - 최소 9회까지 칸을 그리고, 연장전이면 늘린다. 합계 R은 서버의 `score`를 그대로 쓴다.
  - 칸 표시: 빈칸 = 아직 진행 전, `X` = 경기 끝으로 진행하지 않음, `?` = 기록 없음, 진하게 = 진행 중인 반 이닝.
  - 아래 설명줄: `N구 공개 후` / `최종 점수` / `경기 시작 전` / `점수 기록 없음`. `X`나 `?`가 있을 때만 범례를 덧붙인다.
  - 360px 화면에서도 페이지가 가로로 넘치지 않는다. 표만 안에서 가로로 밀리고, 팀 이름과 R 열은 고정돼 항상 보인다.
- **승리확률 흐름**
  - 홈팀 기준 작은 선 그래프다. 각 공의 투구 전 값을 잇고, 마지막에 마지막 공의 투구 후 값을 붙인다.
  - 값이 없는(null) 지점에서 선을 끊는다. 이어 그리거나 50%로 채우지 않는다. 혼자 남은 값은 점으로 찍는다.
  - 0과 1은 정상 값으로 그린다.
  - 50% 기준선(점선), 이닝 경계선과 이닝 번호, 현재 값(주황 점)을 표시한다.
  - 화면 읽기 프로그램용 `aria-label`에 처음·지금 값과 끊긴 지점 수를 넣었다.
- **크게 움직인 공**
  - 서버의 `largest_we_changes`를 받은 순서대로 보여준다. 변화가 큰 순이고, 같으면 앞선 공이 먼저다.
  - 각 항목: 반 이닝, 사건, 득점, `홈팀 ±x.x%p`, 타자 vs 투수, 공 전후 값(`a% → b%`), 중계 문장(두 줄까지).
- **문구**
  - "%p는 모델이 추정한 승리확률의 공 전후 차이(퍼센트포인트)"라는 설명과 서버 `notes.we`를 함께 보여준다. 서버 문구에는 "선수 책임이나 인과 기여도가 아닙니다"가 들어 있다.
  - "기여도"라는 말은 쓰지 않는다.
- **안전 장치**
  - 요청 결과에 `gamePk:through` 키를 붙이고, 지금 props와 키가 같은 결과만 그린다. 그래서 뒤로 가면 이전 요약이 같은 프레임에 바로 사라지고 "불러오는 중"이 뜬다.
  - props가 바뀌면 이전 요청을 취소한다. 늦게 도착한 응답은 버린다.
  - 응답의 `schema`·`game_pk`·`through`가 요청과 다르면 형식 오류로 처리한다.
  - 잘못된 props(`through < -1`, 정수가 아님)는 요청 없이 안내 문구만 보여준다.
  - 오류가 나면 `role=alert`로 알리고 "다시 시도" 버튼(44px 이상)을 보여준다.
  - 서버 `issues`가 있으면 "기록 불일치" 안내를 띄운다.
- **아직 하지 않은 것**
  - 그래프 점을 눌러 해당 공으로 이동하는 기능. 부품에 이동 콜백 prop이 없다. 필요하면 `onSelectIndex`를 추가한다.
  - 서버 `events`(타석이 끝난 모든 공) 목록. 응답에는 있지만 화면에는 쓰지 않았다.

## 검사

- `npx tsc -b`: 통과(오류 0).
- `npm run build`: 통과. 단, 이 부품은 아직 어느 화면에서도 import하지 않으므로 묶음 파일에 들어가지 않는다. 타입 검사는 `tsc`가 `src` 전체를 보며 수행했다.
- `node tests/watch-summary-panel.mjs [스크린샷폴더]`: `PASS watch-summary-panel (9 mocked requests)`. 화면 폭 360px, 로컬 Chromium. 확인한 항목:
  - `through=-1`: 요청 주소에 `through=-1`이 들어가고, 그래프 대신 "아직 공개된 공이 없어요"와 `경기 시작 전`이 뜬다.
  - null이 있는 곡선은 선 1개(3점)와 점 1개로 그린다. 0% 값도 표시한다(`0% → 45%`). `+45.0%p`·`−40.0%p`, 퍼센트포인트 설명, "인과 기여도가 아닙니다" 문구가 보인다.
  - 진행 중이고 득점을 모르는 칸은 `?`로 보인다.
  - 12회 경기: 페이지는 가로로 넘치지 않고, 표만 안에서 밀린다. R 열은 잘리지 않는다.
  - 7번 공 요약을 본 뒤 느린 응답으로 3번 공으로 돌아가면, 즉시 이전 내용이 사라지고 "불러오는 중"만 보인다.
  - 느린 7번 응답 직후 빠른 3번 요청을 보내도, 늦게 온 7번 결과가 화면을 덮어쓰지 않는다.
  - 503 오류 → "다시 시도" → 성공. 버튼은 44px 이상이다.
  - `through`가 다른 응답은 형식 오류로 처리한다. `through=-2`는 요청하지 않는다. 모든 요청에 `through`가 들어 있다.
- `npm ci --ignore-scripts`로 이 작업트리에 `node_modules`를 설치했다(gitignore 대상).

## 남은 불확실성

- 실제 저장 경기(예: 849843, 262구)로 화면에서 확인하지 않았다. 이번 지시 범위가 가짜 응답 검사였기 때문이다. 공이 많을 때 선 굵기와 이닝 번호 겹침은 14px 간격으로 거르는 처리만 했다.
- 이번에는 Song의 실제 기기(아이폰) 확인과 어두운 화면 스크린샷을 하지 않았다. 어두운 화면은 `.wa-page` 토큰만 따른다.
- 팀 약칭은 `WatchAlong.tsx`의 `short` 표에 의존한다. 그 표에 없는 팀은 영문 마지막 단어로 표시된다.
