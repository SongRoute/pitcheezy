# G0 연구 동결과 다음 보정·독립 평가 자료 감사

요청한 세 작업을 완료했다. 협업 체제는 **Astra → Opus5.5 → Sol**로 변경했고 Fable은 이번 작업에 참여하지 않았다. G0는 연구 기준선으로 동결했다. June 확대에는 충분한 요청 표본이 보이지만 적격 표본의 정확한 집계가 먼저 필요하며, 현재 감사한 증거에서는 미열람 비2026 확인 자료를 인증하지 못했다. 새 모델 학습·확률 보정·추론·성능 평가는 실행하지 않았다.

## 1. G0 연구 동결

[동결 번들](../../configs/G0-RESEARCH-FROZEN-v1.json)과 [검증 결과](../../results/G0-RESEARCH-FROZEN-v1.json)는 기존 G0 5개 모델과 관련 파일 **96개**를 연결한다. P4 seed0–2/P10 seed3–4 체크포인트, fit 상태, May 온도, C1 June 앙상블·시드별 혼합 가중치, 입력 처리·frequency·표본 키, 소스 및 P11 평가 증거를 SHA256과 의미 관계로 검증했다. I1 보정 악화와 I2 비활성도 채택 판단의 근거로 보존했다.

- 실제96파일 검증: **PASS**. 번들 SHA256 `c839dbf710c02ca5a1baafcc168e6ca3eaa6d80e269a99f71f08d7d537ec8062`.
- 실행 코드 C `5e82bebc239ced378911919de48c106034ee24b0`, 완료 결과 근거 HEAD `eef5417c0a035f11412fb7fe535bf32e57fe7f8e`를 분리했다.
- 검증기는 순서·부모·가중치·해시 불일치 및 연구/독립 확인 경계 변조를 거부한다. 작업 디렉터리에서 `.venv/bin/python scripts/freeze_g0_research.py verify`로 재확인할 수 있다.
- 이는 **외부 SSD와 기존 실행 소스에 의존하는 참조 묶음**이다. 모델·자료를 복제한 배포 패키지가 아니며 raw 자료 identity와 runtime 바이너리는 새로 바이트 검증하지 않았다. 검증 결과에 `archived_raw_identity_verified:false`, `runtime_binaries_verified:false`, `self_contained:false`를 명시했다. 서비스 채택·독립 확인은 없다.

## 2. June 보정 자료 지원·비용

[상세 감사](ML-June-support-cost-audit-2026-09-27.md), [설정](../../configs/ML-JUNE-SUPPORT-AUDIT-v1.json), [봉인 결과](../../results/ML-JUNE-SUPPORT-AUDIT-v1.json). 기존 승인 가공 파일의 provenance를 검증하고 날짜·키·선수·역할·좌우 등 허용된 메타데이터 열만 해석했다. 새 정답·현재 투구 좌표를 읽어 적격성을 계산하지 않았다.

| 모집단 | 구 수 | 해석 |
|---|---:|---|
| 2025년6월 정규시즌 전체 요청 | 115,816 | 397경기·552투수; 적격 투구 수와 다름 |
| 기존 Cpanel 투수 요청 | 5,212 | 115경기 |
| 기존 Cpanel 적격 키 | 4,821 | 110경기; 이미 보정에 사용 |
| 패널 밖 투수 요청 | 110,604 | 투수 명단 기준 차집합 |
| 적격 Cpanel 키의 정확한 차집합 | 110,995 | 알려진 부적격 패널391구 포함 |

원래 TRAIN에서 고정한 volume 문턱(q25=170, q75=1514)을 유지했다. 최소30경기 **및** 500구 기준에서 전체 June 적격 volume의 지원이 확정되는 그룹은 기존 적격 키만으로 통과하는 high 하나다. zero·low·middle은 정확한 적격 목록이 없어 **불확정**이다. starter×low는 요청 상한조차24경기라 이 분할에서는 지원 불가다. 확대로 모든 하위집단의 지원이 해결된다고 주장하지 않으며 기존 I2 비활성을 바꾸지 않는다.

기존 311,721행×5모델 공식 추론 wall 합계 **1,777.684초**를 근거로, 최대115,425행 규모에서는 약 **658초(11분)**의 full-worker 선형 proxy가 나온다. Profile의 추론 전용 외삽은 약640초다. 전자는 고정 적재 비용까지 행 수에 비례시키고 후자는 고정 비용을 제외하므로 둘 모두 실행 시간 상한 보장이 아니다. **June 적격 목록·특징 준비, 보정 fit, 채점 비용은 미측정**이다. 이번 수정 메타데이터 감사 자체의 외부 명령 wall은0.54초로 추론 외삽과 구분한다. 첫 감사의 외부 wall은 미측정이며 기존0.211초 부분 계측과 원본을 보존했다.

감사 중 정의와 비용의 오류를 바로잡았다. 처음110,604구를 적격 키 차집합과 혼동할 수 있게 썼던 점, 내부 ledger를 공식 비용처럼 사용했던 점, 누락된 출처 검증과 중단 검사를 수정했다. 첫 실행 파일과 수정 실행 파일을 모두 별도 SSD 경로와 Git 이력에 보존했다. 봉인 결과의 적격 목록 부재 표현은 **감사한 등록 입력의 범위**로 한정한다.

## 3. 미열람 자료 노출 이력

[노출 감사](ML-unopened-data-audit-2026-09-27.md)와 [기계 판독 원장](../../results/ML-unopened-data-audit-2026-09-27.json)은12개 모집단과12개 문서·설정·소스 증거를 기록한다. 인증된 미열람 비2026 모집단은 **0개**, 독립 확인 자료 가용성은 **unknown**이다. 전체 파일 저장소나 개별 투구 사용 이력을 전수 조사한 결론은 아니다.

2024 DEV는 이후2025 누적 TRAIN에 포함된다. 현재2025년7–9월 전체 MLB는 이미 평가했고, TRAIN0 투수나 Cpanel 밖 행도 새로운 미열람 자료가 아니다. June 비패널은 과거 리그 전체 CAL 표본 및 이력 사용과의 정확한 중복이 미확인이다. 파일이나 결과 로그가 없다는 이유만으로 미사용이라고 판정하지 않았다. 감사에서 새 원자료·후보 정답·2026 자료를 열지 않았다.

## 협업·검증

Sol이 동결 번들과 검증기를 구현했고 Astra가96개 실제 해시와 경계를 독립 검토했다. Opus가 June 감사를 구현·실행하고 Astra 지적을 수정했다. 별도 Opus 호출은 자신이 작성하지 않은 G0 동결과 Astra의 노출 감사를 교차 검토해 차단 사항 없음을 확인했다. 새 체제에서도 작성자와 검토자를 분리했다.

[Astra 최종 독립 검토](../reviews/G0-freeze-data-audits-Astra-2026-09-27.md)는 PASS, 차단 사항0건이다. [Opus 교차 검토 원문](../reviews/COOP-010-Opus-freeze-exposure-2026-09-27.md)과 [감사 JSON](../../results/G0-freeze-data-audits-review-2026-09-27.json)을 함께 보존한다.

통합 후 관련 검사 **32개(동결4+June28)**가 통과했고 G0 검증기를 실제 재실행해PASS를 확인했다. 기존 모델의 예측 품질 검증을 반복하거나 새 후보를 평가하지 않았다. 호출별 원본·수정·검토는 SSD `coordination/20260927-g0-freeze-audits/`에 보존한다.

## 다음 실행의 선행조건

다음 실험은 먼저 **전체 June의 적격 키와 역할·표본량 지원을 사전 등록한 절차로 확정**해야 한다. 그다음 실제 준비 비용과 지원을 확인하고, 동일 G0·동일 보정 알고리즘에서 기존Cpanel과 확대CAL의 효과를 분리 비교하는 설계를 등록한다. 부족 집단은 정한 fallback을 유지하고 문턱을 사후 완화하지 않는다. 이는 이후 작업의 제안이며 이번 감사에서 추가 학습·추론을 시작하지 않았다. 미열람 자료가 별도로 인증되기 전까지2025 DEV에서 얻는 후속 결과는 개발 결과로 남는다.
