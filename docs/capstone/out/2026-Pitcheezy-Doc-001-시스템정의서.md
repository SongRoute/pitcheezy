| 작품 설명 |  | 작품 Pitcheezy는 MLB 경기를 보는 야구팬이 중계 옆에 띄워 두는 웹 기반 보조 화면이다. 투구 전에는 2023~2025 Statcast 자료로 학습한 모델이 고른 구종·목표 구역 상위 3개를 선택 비중과 함께 보여 주고, 투구 후에는 실제 공(구종·구속·도착 위치·판정)과 추천을 비교해 준다. 사용자는 ‘다음 공은 무엇이 최선인가’를 생각하며 경기를 한 공 더 깊게 본다. |  |  |  |
| 사용자 유형 |  | 주요 사용자 : MLB 경기를 보는 초보·중급 야구팬(웹 브라우저, 모바일 우선)<br>보조 사용자 : 지도교수·전시 관람객(저장 경기 재생 화면으로 시연·전시)<br>운영자 : 발행기 운영(송동선), 공개 호스트·비상 안내 운영(조현준)<br>외부 시스템 : MLB Stats API 실시간 피드, Baseball Savant Statcast, 팀원 CV 의도 모듈 |  |  |  |
|   운영개념  |  | 1. 맥미니(상시 가동)의 발행기가 MLB 공식 경기 피드를 10초 주기로 읽고, 투구 전 상황마다 동결된 모델로 추천을 계산해 장부에 먼저 기록한 뒤 JSON 파일로 발행한다.<br>2. 공개 호스트는 발행 파일만 제공하고, 팬 화면(React 웹)은 파일을 읽기만 한다. 모든 시청자에게 같은 공통 지연(15초)을 적용해 중계보다 먼저 결과가 보이는 일을 막는다.<br>3. 모델은 2023~2025 Statcast 자료로 학습·동결하고 시드·데이터 버전·커밋을 기록한다. 2026 자료는 사전 등록한 정책 평가 1회에만 쓴다.<br>4. 지난 경기는 저장된 피드를 실제 속도로 재생해 시연·전시에 쓴다. |  |  |  |

| 작품의<br>주요 기능 | 투구 전 추천 상위 3개(구종·선택 비중·목표 구역)와 지원 여부·추천 출처 표시<br>실제 투구 공개 후 구종·구속·도착 위치·판정 비교와 포수 시점 존 그림<br>경기 상황 머리글, 선수 카드, 박스스코어, 타석 투구 띠, 다음 타자, 홈 승리확률 표시<br>실시간 경기 수신(10초 폴링)·공개 발행과 지난 경기 실제 속도 재생<br>주요 사건(홈런·삼진 등)의 승리확률 변화 분해(사건 기여도, 설계·뼈대 구현)<br>포수 미트 셋업(의도 대리값) 연결과 시연 운영자 화면 |  |
| 기타 개발시 <br>고려사항  | 1. 투구 전 추천 계산에 그 투구 이후의 정보를 쓰지 않는다(누수 방지, as-of 규칙).<br>2. 2026 시즌 자료는 학습·튜닝·모델 선택에 쓰지 않고 오프라인 정책 평가에만 쓴다.<br>3. 시드·데이터 버전·커밋이 없는 결과는 결과로 인정하지 않고, 측정하지 않은 값은 ‘미측정’으로 표시한다.<br>4. MLB 자료는 경기당 단일 수집기·10초 주기로 읽고, 팬에게는 발행 파일만 배포한다. 로고·선수 사진·중계 캡처는 쓰지 않는다.<br>5. 모바일 폭(390px)에서 가로 스크롤 없이 쓰이도록 하고, 기술 용어는 쉬운 말로 풀어 쓴다. |  |
| 선행기술 <br>조사<br>분석  | 논문 : SmartPitch(Otremba, MIT 2022)는 볼카운트 12상태 MDP로 투구 전략을 계산했고, Takamido & Nakamoto(2026)는 Transformer로 2스트라이크 결정구를 예측했다. 두 연구를 같은 자료·같은 저울(오프라인 정책 평가)에서 재구현해 비교 대상으로 삼았다. Douglas et al.(2021), Melville et al.(2023) 등 최적 투구 전략 연구도 검토했다.<br>상용 SW : ESPN ‘Pitch Predictor’, MLB Gameday, Baseball Savant Gamefeed, FanGraphs 승리확률 그래프를 화면 참고로 조사했다. 이들은 결과 예측이나 기록 제공에 머물고, 투구 전 추천과 실제 투구 비교를 팬 화면으로 제공하지 않는다.<br>오픈소스 : pybaseball(Statcast 수집), mlb-rs/mlbt 등 공개 MLB 클라이언트를 조사했다. 특허는 조사하지 않았다. |  |
