# 화면 담당용 작업 지시 — 포수 셋업 위치 표시 (2026-10-02, D151)

서버 쪽 연결은 끝났다. 화면 표시만 남았고, 화면 파일은 건드리지 않았다.
화면의 현재 상태와 원칙은 [UI-frame-PM-handoff.md](UI-frame-PM-handoff.md)를 따른다.

## 무엇을 보여 주나

공이 들어온 뒤 "방금 던진 공" 화면의 존 그림에, **포수가 미트를 대고 있던 가로 위치**를 하나 더 표시한다.
지금 존에는 추천 목표와 실제 공이 있다. 여기에 포수 셋업이 더해져 "추천 / 포수 셋업 / 실제 공" 세 가지를 비교할 수 있다.

## 받아 오는 방법

- 브랜치 `demo/intent-setup`(`5a102ea`, `demo/live-sync` `221436a` 기준)을 화면 브랜치에 합친다. 바뀐 파일은 서버 쪽 4개뿐이라 화면 파일과 충돌하지 않는다.
- `GET /api/watch/{game_pk}/setup` — 경기당 한 번만 부르면 된다. 자료가 없는 경기는 404다.
- 응답의 `pitches` 각 항목: `at_bat_number`, `pitch_number`(경기 자료의 타석·투구 번호와 같다), `status`, `plate_x_feet`, `x_band`, `unavailable_reason`.
- `plate_x_feet`는 포수 시점 가로 위치(피트, 음수 = 포수의 왼쪽)로 실제 공의 `x`와 같은 좌표다. `x_band`는 `left`/`middle`/`right`/`off_left`/`off_right`다.
- 자세한 형식: `apps/observer/CONTRACT.md`의 "Catcher setup estimates" 절.

## 지금 있는 자료

- 경기 **849843** 하나. 262구 가운데 **39구**에만 줄이 있고, 가로 위치가 있는 것은 **27구**다(그중 추천이 함께 있는 공은 25구).
- 39구는 MLB 공식 압축 경기에 나온 공이라 대부분 타석의 마지막 공이다.
- 좌우 분포: 왼쪽 8, 가운데 8, 오른쪽 8, 존 왼쪽 바깥 3.

## 지켜야 할 것

1. **가로 위치만 그린다.** 높이는 서버가 주지 않는다. 이 경기 포수들은 릴리스 직전까지 글러브를 낮게 두어서 셋업 높이가 실제 공보다 중앙값 1.35 ft 낮다(팀원 보고). 존 그림에서는 세로선이나 존 위·아래의 눈금처럼 높이를 주장하지 않는 표시를 쓴다.
2. **줄이 없는 공에는 아무것도 그리지 않는다.** "자료 없음" 글자도 넣지 않는다(대부분의 공이 해당하므로 화면이 시끄러워진다). `status`가 `unavailable`이거나 `plate_x_feet`가 없을 때도 같다.
3. **공이 들어온 뒤에만 보여 준다.** 다음 공 화면(추천)에는 넣지 않는다. 실제 중계에서는 공을 던지기 전에 알 수 없는 정보다.
4. **말은 "포수 미트 위치"로 쓴다.** "투수가 노린 곳", "의도", "제구 오차" 같은 말은 쓰지 않는다. 포수 셋업은 의도의 대리값이고 검토 전 추정이다.
5. 눌러서 보는 자세히 화면에 한 줄을 둔다: "포수 미트 위치는 영상에서 읽은 추정이며 검토 전입니다."(응답의 `badge`를 써도 된다.) 첫 화면에는 글자를 늘리지 않는다(D136).
6. 표시 방식(모양·색)은 화면 담당이 정한다. 색만으로 구분하지 않는다.

## 확인 방법

- 849843의 1번 타석 3구째(`849843:1:3`)는 `plate_x_feet` −0.05(가운데)다. 화면에서 존 가운데 세로 위치에 표시가 나오면 맞다.
- 줄이 없는 공(예: 1번 타석 1구째)에서는 표시가 없어야 한다.
- 서버 테스트: `cd apps/observer/backend && python -m pytest tests/test_setup_estimates.py -q`

## 하지 않는 것

- 실시간 경기에는 붙이지 않는다. 영상에서 읽는 일은 경기 뒤에 사람이 돌리는 작업이라 실시간으로 오지 않는다.
- 다른 경기 자료는 아직 없다. 팀원이 다른 경기 정확도(M3)를 재는 중이다.
