# Pitcheezy UI용 백엔드 데이터 목록 (초안)

기준: v3 시안 + 라이트 시안 (2026-10-16), 인터페이스 스펙 v1. 필드 이름은 제안이며 확정 아님.

- **라이트** = 라이트 화면에도 필요한 필드 / **v3** = 상세·PC에서만 필요 / **협의** = 항목 미확정
- 출처 칸의 "라이브 피드"는 실시간 경기 데이터 원천(후보: MLB Stats API 라이브 피드 — 제공 필드·지연 시간은 확인 필요)

## 0. 공통 규칙

| 항목 | 내용 |
|---|---|
| 값 상태 | 모든 값은 `value` + `status` 쌍. status = `ok` / `missing`(미제공) / `computing`(계산 중) / `under_review`(기록 확인 중). 미제공을 0이나 빈 문자열로 보내지 않음 → 화면에서 `—` |
| 시각 | 모든 레코드에 `received_at`(우리 서버 수신), `source_ts`(원천 시각) |
| 수정 이력 | 판정 정정 시 덮어쓰지 않고 `revision` 증가 + 이전 값 보존 |
| id 체계 | 스펙 v1 그대로: `base_out_id`(0..23), `count_id`(0..11), `pitch_id`(0..8), `loc_id`(0..24, 포수 시점), `action_id` = pitch_id × 25 + loc_id, `outcome_id`(0..10) |
| 단위 | 구속은 km/h 표시. 원천이 mph면 변환 위치(서버/클라이언트) 결정 필요 |
| 버전 라벨 | 화면 하단 "모델 [EXP-ID] · 데이터 [버전]"용: 실험 ID, 시드, spec_version, data_version, RE24 버전 |

## 4. 추천 (모델 산출, 트랙 B)

투구 **전에** 기록하고 이후 바꾸지 않음. "당시 기록된 추천"을 보여주려면 필수.

| 필드 | 라이트 | 출처 | 비고 |
|---|---|---|---|
| 대상 투구 번호, `state_id` (count·base_out·cluster) | ✓ | 서버 | |
| 타자 군집 `cluster_id` | ✓ | `batter_clusters_{버전}` | 군집 파일에 없는 타자 처리 방식 결정 필요 |
| 상위 3개 행동: `action_id` → pitch_id, loc_id, 순위 | ✓ | `policy` / `Q` | |
| 행동별 Q (RE24 단위) | v3 | `Q.npy` | 순위 근거. 화면에는 "예상 실점 낮은 순" |
| 모델 선택 비중 (완화 후 분포) | v3 | `policy.npy` | 성공 확률 아님 — 이름 그대로 전달 |
| 구종별 25칸 위치 가치 (상위 구종) | v3 | `Q.npy` | 추천 상세의 위치 가치 지도 |
| `valid` 마스크 | v3 | `valid.npy` | 레퍼토리 밖 구종 제외 |
| 기록 시각, 계산 상태 | ✓ | 서버 | computing / ok / missing |
| 추천 이유 (문장) | v3 | 없음 | 현재 모델 산출물에 없음 → missing 고정. 근거를 지어내지 않음 |
| 모델 버전 메타 | v3 | `meta.json` | 실험 ID, 시드, spec_version, lookup_mode |

추천이 미제공(missing)인 경우:
- 투수가 `pitchers.parquet`에 없을 때
- 수신이 끊긴 사이에 지나간 투구
- 첫 투구 전 연결이 안 됐을 때

## 5. 타석 분석 (책임 분해, 트랙 C) — 협의

| 필드 | 출처 | 비고 |
|---|---|---|
| V(추천), V(의도), V(실제) | `lookup` (같은 mode) | |
| 의도 위치 (기준점) | 트랙 C | ⓑ / ⓒ / CV 프록시 중 실험 결과로 결정 |
| 실제 결과 ΔRE24 | RE24·dRE24 테이블 | 같은 RE24 버전 |
| 성분 4개: 전략, 투수 실책, 타자, 운 | 트랙 C | 합 = V(추천) − 실제 결과 |
| 정합성 검증 통과 여부 | 서버 | 실패 시 화면에서 숨김 |

화면 문구 규칙: 의도와 실제가 같은 칸이라는 이유만으로 "투수 실책 0"이라고 쓰지 않음. 값만 전달하고 해석 문구는 붙이지 않음.

## 10. 결정 필요

1. 실시간 원천과 지연 시간 — 지연·끊김 판정 기준(몇 초부터 "지연"인지)
2. 추천 기록 시점 — 직전 투구 판정 확정 후 즉시? 정정되면 재계산하고 이전 추천도 보존?
3. 군집 파일에 없는 타자의 `cluster_id` 처리
4. wRC+·FIP 출처
5. 승리확률 출처
6. 구속 단위 변환 위치
7. 분해 성분을 화면에 노출할지 (현재 "항목 협의 중")
