# EVAL-PREPITCH-001 — 평가를 먼저 만드는 준비 실험

상태: **SYNTHETIC_ONLY / 실자료 게이트 CLOSED**. Song의 2026-10-29 새 요청으로 시작한 별도 작업이다. 기존 완성본·연구 판정·봉인 OPE/RS·운영 모델은 변경하지 않는다. 산출물은 평가 계약, 합성 실행기와 검사이며 모델 성능 실험 결과가 아니다.

## 질문과 목표

“같은 투구 전 정보로 다음 공의 **결과 확률**을 예측할 때, 단순 모델과 현재 모델 구조의 차이는 어디서 생기는가?”를 향후 질문으로 둔다. 구종 예측·가정한 구종/위치의 조건부 반응·추천 정책 효과는 다른 문제다. 본 v1은 실제 모델 비교를 등록하지 않으며, 그 전에 평가 흐름을 검증한다.

## 이번에 고정한 계약

- 스키마 `pitchmdp-ten-v1`: `ball, strike, foul, out, single, double, triple, home_run, hbp, double_play` 순서. 기준 ca55f47c의 `pitchmdp/model.py:OUTCOMES`와 동일하다. 무거운 모델 의존성 없이 상수만 명시했다. 7-leaf·서비스 11분류는 순서 변경과 함께 거절하며 자동 변환하지 않는다. 실제 원천 사건→라벨 매핑과 미지원 사건 처리는 아직 미등록이다.
- 한 번의 주 비교는 `synthetic_candidate − synthetic_control`. 합성 확률을 직접 지정하며 모델 fit이나 어댑터 호출은 없다. 설정은 `configs/EVAL-PREPITCH-001.json`에 있고, 시드 20261029·경기 부트스트랩 1000회다. 합성 기준시각은 2000년으로 실제 평가 기간을 뜻하지 않는다.
- 분모는 예측과 독립인 전체 적격 투구 명부다. 물리 키 `(game_id, at_bat_number, pitch_number)`는 양의 정수이며 선수 교체와 무관하다. 명부/모델별 중복은 동일 내용이어도 거절한다. 명부 밖 예측·등록 밖 모델·필드·라벨·층도 거절한다. 실제 공급자 키 재발급·중단/재개·정정 매핑은 후속 어댑터 계약이다.
- `ok`, `error`, `abstain`을 입력하고 미제출은 `missing`, 마감 이상에 생성된 정상 예측은 `late`로 계산한다. 모두 원래 분모에 남는다. 오류/기권은 확률 없이 상태만 기록한다. 잘못된 정상 예측은 조용히 제외하지 않고 전체 실행을 거절한다.
- 비교 점수와 불확실성은 **양쪽 모두 제시간에 성공한 공의 교집합**에서 계산한다. 각 모델의 자체 성공 표본 점수는 별도 이름으로 표시하며 서로 직접 비교하지 않는다. 전체 분모·상태별 수·coverage·공통 키를 함께 출력한다. coverage가 다르거나 불완전한 경우의 승자 규칙은 미등록이고, 이번 실행에서는 coverage와 무관하게 과학적 승자를 내지 않는다.
- 확률은 정확한 10차원 유한 숫자, 각 값 `[0,1]`, 합 1(절대 허용오차 `1e-6`)을 검사하며 재정규화하지 않는다. 주지표 NLL은 기존 `matrix_metrics.pitch_losses`의 `−log(max(p_true, 1e−12))`이므로 **바닥값으로 제한된 NLL**이다. 진짜 정답 확률 0인 건수를 별도 출력한다. 보조지표 Brier는 클래스별 제곱오차의 합(클래스 수로 나누지 않음), 정답률의 동률은 고정 순서의 첫 라벨이다.
- `paired_game_comparison`을 재사용한다. 물리 키를 정렬한 뒤 게임 전체를 재표집하고 표집된 총 투구 수로 나눈다. 따라서 투구 가중 평균 차이이며 행 순서에 불변이다. 95% 구간은 고정 예측에 조건부인 percentile 구간이고 학습·모델 선택 불확실성을 포함하지 않는다. 두 경기 미만은 구간 미측정, 교집합 없음은 점수 미측정이다. 합성 준비 검사에서 가설검정 p값/기존 승격 함수는 사용하지 않는다.
- 사전 기술층: 합성 count `0-0/1-0`, handed matchup `R-R/R-L`, prior history `none/available`, 공통 누락은 `unavailable`. 층마다 적격 수·공통 성공 수·점수만 내고 추가 승자/검정은 없다. 실제 카운트 범위·이력량 구간·선수별 분석·최소 표본수는 후속 등록사항이다. 결과 후 추가한 분석은 탐색으로 표시한다.

## 투구 전 정보와 시각의 의미

정상 행은 `input_available_at ≤ generated_at < deadline`을 만족해야 한다. 입력 시각이 마감과 같거나 이후면 거절하고, 생성만 늦으면 `late`로 남긴다. 시각은 시간대가 포함된 ISO 문자열이며 모델 학습 cutoff는 합성 holdout 시작보다 엄격히 앞서야 한다. 양쪽 정상 예측의 입력 fingerprint는 같은 명부 행의 SHA256 선언과 일치해야 한다.

이 검사는 **선언의 일관성만 검사한다**. fingerprint 문자열과 시각을 제출했다고 동일한 정보·실제 당시 가용성·실제 학습 cutoff가 증명되는 것은 아니다. 실자료에서는 입력 내용/피처 허용목록, 불변 최초 수신 기록, 파생 이력의 as-of, 모델 provenance를 감사해야 한다. 사후 공식 정정자료로 만든 retrospective replay와 실제 마감 전에 저장한 prospective 예측도 별도로 표기해야 한다. 현재 합성 결과는 둘 중 어느 실측도 아니다.

순수 투구 전 예측에는 **현재 공의 실제 구종·도착 위치·구속·투구 결과**를 입력하지 않는다. 과거 공의 정보도 당시 수신을 증명해야 한다. 기존 `model.py`의 조건부 입력에는 현재 `pitch_type`, `plate_x`, `plate_z`가 있으므로 기존 가중치를 그대로 붙여 같은 예측 문제라고 주장할 수 없다. 투구 전 입력으로 재학습하거나 과거로만 추정한 행동 분포로 주변화하는 설계 등은 후속 검토 대상으로 남긴다. 라벨 호환은 입력 호환을 뜻하지 않는다.

## 실자료로 넘어가기 전 미완 조건

1. 자료 manifest·버전·완전한 후보 명부, 적격/제외 규칙과 이유별 분모, 원천 사건 라벨 매핑을 고정한다. 기존 `model.eligible()`는 현재 구종·좌표 유무를 요구하므로 그대로 가져오지 않는다.
2. 노출 장부를 확인하고 FIT → SELECT → CAL → TEST의 경기/날짜 구간을 정한다. 동일 경기가 역할 사이에 걸치지 않게 하며 이미 본 자료는 새 독립 TEST로 이름만 바꾸지 않는다. 미노출 자료가 없다면 미래 수집 평가를 설계한다.
3. 공통 투구 전 피처 계약·수신/파생 시각 증거·결측 처리와 모델 source/config/artifact pin을 고정한다. 연구 모델마다 입력 분포가 달라지는지 확인한다.
4. 하나의 실제 주 비교, 실용 개선 문턱·Brier 안전 기준·coverage 실패 규칙·학습 시드/예산·검정과 최소 경기 수를 결과 열람 전에 정한다. 합성 두 경기는 통계적 충분성 근거가 아니다. 기존 실험의 .003/.001 문턱을 자동 상속하지 않는다.
5. 작성자와 다른 검토자가 구체 등록을 검토한 뒤 해당 실행만 연다. 이 v1 설정은 미완 값을 채우거나 gate를 OPEN으로 바꾸어도 거절한다. 실자료 실행 지원 자체가 별도 변경·검토 대상이다.

## 실행과 증거

프로젝트 기존 numpy/pytest 환경에서, 저장소 루트 기준:

```sh
PYTHONPATH=experiments/pitchmdp python -m pytest experiments/pitchmdp/tests/test_prepitch_evaluation.py experiments/pitchmdp/tests/test_matrix_metrics.py -q
python experiments/pitchmdp/scripts/evaluate_prepitch.py --config configs/EVAL-PREPITCH-001.json --output /tmp/eval-prepitch-synthetic.json
```

CLI는 내장 합성 4구만 만들고 외부 투구 입력 옵션이 없다. 같은 출력 경로가 있으면 거절한다. 결과는 설정 hash·스키마·시드·합성 모드·coverage·점수·구간을 담으며 실제 성능 개선 증거가 아니다. 실행 소스는 검토 커밋과 함께 보존한다. Python 함수는 검사 용도로 선언된 행을 받으므로 데이터 진위를 판별하는 보안 장치가 아니다.

검사는 손계산 점수, 0확률, 부동소수 확률 오류, NaN/Inf, 시각/중복/스키마/등록 오류, 분모와 공통키 정렬, 부족 경기, 행 순서 불변성, 실제 모드 거절, CLI 결정적 직렬화·덮어쓰기 거절을 다룬다. 검토 기록은 `REVIEW-EVAL-PREPITCH-001.md`에 별도 작성자가 남긴다.
