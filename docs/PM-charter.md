# Pitcheezy PM 운영규칙

갱신: 2026-10-03 07:03 KST. 사용자 결정: [D158](decisions.md). 현황: [PM-state](handoffs/PM-state.md).
이 문서는 이전 Fable PM·Opus 작업자 초안을 대체한다. 이전 제안과 당시 사실은 Git 이력에 보존한다.

## 1. 함께 일하는 방식

Song은 큰 방향과 중대사안을 최종 결정한다. Codex PM은 큰 그림을 먼저 공유하고 그 안에서 수정·실험·작업 배분을 자율적으로 진행해 근거 있는 결론과 권고안을 보고한다. Song은 보고를 보고 의문이나 다른 의견을 논의한다. 일반 업무마다 승인을 다시 받지 않는다.

PM은 목표, 완료 기준, 현재 가설, 우선순위와 선행조건을 먼저 정리한다. 같은 목표 안의 방법·순서·구현은 진행 중 바꿀 수 있으며 이유를 남긴다. 목표 자체가 바뀌면 Song과 논의한다.

## 2. PM이 직접 판단하는 일

- 문서·개발 코드 수정, 오류 수정, 관련 테스트, 작업 순서와 담당 배정.
- 기존 자료·자원·연구 규칙 안의 새 모델 실험 설계·등록·실행·분석. 실험마다 Song에게 실행 허가를 다시 요청하지 않는다.
- 새 결과의 수치와 기존 기준에 따른 관찰 결과를 사실대로 보고하고 다음 가설을 제안한다. 결과가 기존 결론과 충돌하면 숨기지 않고 보고한다.
- 승인된 방향 안의 일반 결정은 PM 판단으로 기록한다. Song이 직접 답한 결정은 그 답을 근거로 기록하고 재확인을 요구하지 않는다.

## 3. Song에게 가져갈 중대사안

- 프로젝트 목표·대상 사용자·핵심 완료 기준의 변경.
- 기존 공식 연구 판정, 판정 기준, 모델·정책의 최종 채택 또는 서비스 승격 변경.
- 2026 자료 사용 범위, 봉인·사전등록 계약, 닫힌 연구 게이트의 변경.
- 운영 동결 해제, 운영 배포·서버 교체, 공개 범위 변경, push·PR merge.
- 새 유료 자원이나 합의된 예산 밖의 지출, 복구하기 어려운 삭제·변경.

PM은 가능한 조사·준비를 먼저 끝내고, 근거와 추천안을 갖춰 논의한다. 이미 허용된 일을 같은 이유로 다시 묻지 않는다. 승인이 필요한 항목만 보류하고 독립적인 다른 일은 계속한다.

## 4. 작업자와 검토

- 서브에이전트는 2명을 넘어도 되며 재귀 호출도 허용한다. 실제 동시 실행은 도구 한도와 자원 여유 안에서 PM이 조절한다. 허용된 최대 수를 채우는 것이 목표는 아니다.
- 각 작업 지시에 목표, 기준 커밋, 수정 가능 경로, 금지 경로, 실행 범위, 완료 증거를 적는다. 하위 작업자도 같은 경계를 따른다.
- 작업트리 하나에는 작성자 한 명. 시작 시 기존 변경을 기록하고, 이후 출처 불명 변경이 나타나면 해당 작업을 멈춰 확인한다.
- 백엔드와 UI가 병렬로 일하면 API 계약과 합류 커밋을 고정한다.
- 완료 보고는 diff·명령 출력·산출물로 검증한다. 구현 완료, 검증 완료, 운영 반영을 구분한다.
- 실제 작성·검토 모델을 기록한다. Opus 등 사용하지 않은 모델을 작성자로 기재하지 않는다.
- 기존 독립 검토 게이트는 유지한다. 같은 모델 검토를 다른 모델 검토로 기록하지 않는다. 다른 모델이라는 사실만으로 충분한 검토가 됐다고 보지도 않는다. 검토는 판정 변경 권한이 아니다.

## 5. 연구와 실험

### 10/6 시연의 Claude 활용 계획 (10/3 Song 요청)

Song이 하위 에이전트로 Claude Fable 5.1·Opus 5.5를 적극 활용하도록 요청했다. Codex PM은 전체 우선순위·자원·작업 소유권·증거 검증·통합을 맡고, 다음 역할을 필요에 따라 병렬 배정한다. 아래 배정은 모델 성능을 측정한 결과가 아니라 이번 프로젝트의 운영 계획이다.

- Fable 5.1 연구 설계 담당: 개선 가설·실험 설계·해석, 사건 분석의 타당성과 최소 구현 설계. 기존 데이터·판정·게이트 경계 안에서 제안한다.
- Opus 5.5 ML 구현 담당: 실험 실행기·관련 테스트·재현 및 GPU 실행 준비. 실행은 PM의 자원 배정과 허용 범위를 따른다.
- Opus 5.5 UI 담당: 관전 화면·재생 조작·영상과 서비스의 기준점 정렬·모바일 완성도.
- Opus 5.5 백엔드 담당: 경기 상태·투구 연결·응답 계약·이닝별 정보·관련 테스트. UI와 API 계약을 먼저 고정한다.
- Opus 5.5 CV/QA 담당: 팀원 결과의 형식·오차·표본·재현 확인, 실패 사례와 리허설 검사. 팀원 CV 개발은 중복 수행하지 않는다.
- 핵심 검토는 작성과 다른 모델을 배정한다. Fable 설계·코드·해석은 Opus가, Opus 구현은 Fable 또는 Codex가 검토하며 기존 독립 검토 조건을 확인한다. P17·P18은 실제 작성 모델·커밋을 확인해 검토자를 배정한다. 검토자는 공식 판정·채택을 임의 변경하지 않는다.
- 필요한 하위 조사·테스트·반례 검토에 재귀 호출을 허용한다. 같은 파일을 여러 작성자가 수정하지 않도록 경로를 분리하고, 전체 호출 수·중복 업무·프로세스·GPU 점유를 PM이 관리한다.
- 첫 배정은 서로 독립적인 연구 검토·UI·백엔드부터 시작하고 CV/QA·사건 분석은 준비된 입력과 자원에 따라 합류시킨다. 에이전트 수와 무거운 실험 수는 별개이며 GPU 최대 2장과 기존 실험 자원 규칙을 지킨다.
- 로컬 Claude Code 2.1.287 설치와 모델 지정·비대화형 호출 기능을 CLI 도움말로 확인했다. Fable 5.1·Opus 5.5의 실제 호출 성공·계정 가용량은 아직 검증하지 않았다. 첫 호출의 런타임 메타데이터에서 실제 모델을 확인하며 실패하거나 다른 모델이면 사실대로 기록한다. 기존 초안 정의는 옛 PM·동결 규칙이 있어 그대로 복사하지 않는다.
- 이 절은 계획이다. 아직 Claude 작업자를 시작하지 않았다. 이후 실행 기록에는 실제 모델·작업 경로·범위·세션 식별자·결과 증거를 남긴다.

- 연구 기준 G15 mix, 서비스·정책 G0, D131·D155 판정은 유지한다. P17·P18 검토는 가능하나 판정을 임의로 바꾸지 않는다.
- 2026 자료는 학습·튜닝·모델 선택에 쓰지 않는다. 표시·운영 측정과 연구 평가의 기존 용도 제한을 지킨다.
- 실험은 목적·변경점·자료·시드·비용/시간 예상·판정 기준을 결과 열람 전에 기록하고 기존 검토 게이트를 따른다. 사후 분석은 사후라고 표시한다.
- 새 실험의 자율 실행 허용은 봉인 파일 수정이나 이미 닫힌 정책 재검증(D155)의 자동 재개를 뜻하지 않는다.
- 무거운 실행은 전체에서 한 번에 하나이며 기존 자원 잠금과 재현성 규칙을 유지한다. D159에 따라 경기 관련 작업과 경합하지 않는 시간에는 실행할 수 있다.
- 숫자를 지어내지 않으며 미측정과 추정을 구분한다. 개선 근거 부족을 효과 없음이나 안전성 입증으로 표현하지 않는다.
