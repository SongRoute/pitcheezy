# 맥북 단독 예비 시연 (맥미니·Tailscale이 안 될 때)

맥미니 8771이 열리지 않을 때, 맥북 안에서 같은 시연 화면을 띄우는 예비 경로입니다.

## 쓰는 법 (맥북 터미널)

1. 묶음 파일을 맥북으로 옮겨 풀기: `tar xzf pitcheezy-offline-demo.tar.gz`
2. `cd pitcheezy-offline-demo/offline && python3 serve_offline.py`
3. Safari에서 `http://127.0.0.1:8790/showcase` 열기. 끝낼 때는 터미널에서 Ctrl+C.
   - "포트를 열지 못했어요"가 뜨면 안내된 번호로 다시: `python3 serve_offline.py --port 8791` (주소의 8790도 같이 바꾸기)

## 무엇이 같고 무엇이 다른가

- 화면 코드: 묶음 안 `dist/`. v4 묶음의 `dist/`는 8771 빌드(e9e9d4d)에 영상 사본 선택(`?media=local`)과 그 안내 문구만 더한 빌드(5b181d1). 8771에 같은 변경이 배포되기 전까지는 8771과 바이트가 다름. `?media=local` 없이 열면 화면 동작은 8771과 같음.
- 경기 자료: 8771의 응답을 저장 시각(화면 맨 위 노란 줄)에 그대로 저장한 사본. 시작할 때 sha256을 확인하고, 하나라도 빠지거나 바뀌면 서버가 뜨지 않음. 예외 하나: 경기 목록(`/api/watch/games`)은 8771 목록에서 849843만 남긴 것(manifest에 표시).
- v3 묶음(`--all-decisions`로 만든 것)은 경기 849843의 공 262개 전부의 공개 결과·경기 흐름을 저장함. 화면 맨 위 노란 줄에 "공 262개 전체"가 보이면 v3. 관전 화면에서 → / ←로 어느 공으로 넘겨도 저장된 응답이 나옴. 아래 줄은 v1·v2("시연 장면만") 설명.
- v1·v2: 저장된 것은 경기 849843의 시연 장면 39개(장면별 같은 타석 앞 공 + 공개 결과 + 요약)뿐. "이 공 관전 화면 열기" 새 탭에서 → / ←로 다른 공으로 넘기면 공개 결과나 "경기 흐름" 칸에 "오프라인 예비 묶음에는 이 자료가 없어요"가 뜸(같은 타석 앞 공은 공개 결과만 보이고 경기 흐름은 안내 문구). 지어낸 자료는 없음. 시연은 영상 옆 장면 선택으로.
- 포수 미트(공을 공개한 뒤 존 그림의 세로선 "미트"): `--with-setup`으로 만든 묶음에만 들어 있음. manifest.json의 `setup_rows`가 숫자면 들어 있고 `null`이면 없음. 없으면 미트 표시만 조용히 빠지고 나머지 화면은 같음. 들어 있어도 저장 시각의 영상 추정치 사본이라, 그 뒤 맥미니 쪽 추정치가 바뀌면 8771과 다를 수 있음.
- 실시간 경기는 볼 수 없음(목록에 "실시간 경기 정보는 볼 수 없어요"로 표시).
- MLB 영상은 인터넷에서 받음. 인터넷이 없으면 영상 없이 화면만으로 설명(묶음에 영상·영상 캡처는 들어 있지 않음). 예외: 아래 "맥북에 저장한 같은 공식 영상 사본"을 따로 받아 `--media-dir`로 켠 경우.
- 아이폰은 이 맥북 서버에 붙지 않음(127.0.0.1 전용). 아이폰 쪽은 맥북 화면으로 대신. "아이폰용 관전 링크 복사" 버튼이 주는 `127.0.0.1` 링크는 아이폰에서 열리지 않으니 쓰지 않기.

## 인터넷이 없을 때 영상: 맥북에 저장한 같은 공식 영상 사본 (선택)

기본 화면은 그대로 MLB 주소에서 영상을 받습니다. 아래는 따로 켤 때만 쓰는 예비 경로입니다.

1. 영상 받기(한 번, 약 436 MB): 총괄이 맥이 녹화·보호 시간대가 아닐 때 실행. `python3 fetch_media.py --dry-run`으로 주소·저장 위치만 먼저 확인한 뒤 `python3 fetch_media.py`. `showcase-scenes.json`의 `mediaUrl`과 같은 파일을 `offline/media/`에 받고 `MEDIA-SHA256SUMS`(파일 이름과 sha256)를 씀. 이미 있는 파일은 덮어쓰지 않음. 받는 중 실패하면 그 실행의 `.part`는 지우고 멈춤. 강제 종료 등으로 이전 `.part`가 남아 있으면 건드리지 않고 멈추니, 확인한 뒤 손으로 지우고 다시 실행. 맥미니에서 받았다면 `media/` 폴더째 맥북의 `offline/` 아래로 복사.
2. 서버 켜기: `python3 serve_offline.py --media-dir media`. 시작할 때 `MEDIA-SHA256SUMS`에 적힌 파일의 sha256을 모두 확인하고, 파일이 없거나 바뀌었거나 목록에 없는 `.mp4`가 폴더에 있으면 서버가 뜨지 않음. 첫 줄 아래에 사본 주소·크기·sha256이 한 줄 더 나옴.
3. Safari에서 `http://127.0.0.1:8790/showcase?media=local` 열기(장면 지정은 `?media=local&scene=3`처럼 같이 씀). 영상 아래에 "맥북에 저장한 같은 공식 영상 사본을 씁니다"가 보이면 사본 모드, 안 보이면 인터넷 영상. 같은 탭에서 한 번 켜면 주소에 `?media=local`이 없어도 사본 모드일 수 있으니(아래) 주소가 아니라 이 문구로 확인.

- 같은 파일이라 장면 시점(투구 전 3초~후 4초)은 그대로. 추천·공개·경기 자료 요청도 그대로.
- 영상 오류 안내의 "공식 영상 따로 열기"는 사본 모드에서도 MLB 공식 주소(인터넷 필요).
- 서버는 목록에 적힌 파일만 `/offline-media/<파일 이름>`으로 내줌. 구간 요청은 한 구간만 206으로 답하고(범위 밖이면 416), 여러 구간을 한 번에 요청하면 파일 전체(200)로 답함.
- 확인한 것: 합성 H.264/AAC 짧은 영상으로 headless Chromium에서 재생·장면 이동·206 응답. 실제 MLB 파일(436,737,676 bytes, sha256 c32208e8…d06f, 2026-10-04 맥미니에서 받음)로 맥미니 headless Google Chrome 1440·390 너비, 장면 1·2·25에서 재생·멈춤 시점·외부 요청 0건(2026-10-04 18:29). 확인 못 한 것: Safari·아이폰, 맥북에서의 재생.
- 시연 전에 받은 실제 파일로 Safari에서 한 번 재생·장면 이동해 볼 것(위 확인 못 한 것).
- `?media=local`로 한 번 열면 같은 탭 안에서는 기억함(T66): "← 경기 목록"에 갔다가 "영상과 나란히 비교 ▸"로 돌아와도 사본 영상. 새 탭은 다시 인터넷 영상에서 시작하므로 새 탭에서는 주소 끝에 `?media=local`을 다시 붙이기(탭 복제는 기억을 그대로 가져갈 수 있음, 확인 안 함). 끄려면 `?media=online`. 이 기억 기능이 들어간 빌드(묶음 v5 이후)가 아니면 예전처럼 브라우저 뒤로 가기를 쓰거나 주소에 다시 붙이기.
- 영상 파일은 시연용으로 따로 보관하는 MLB 공식 영상 사본이라 저장소에 올리지 않음(`.gitignore`에 `offline/media/`, `*.mp4`). 배포·공유하지 않기.

## 다시 만들기 (맥미니)

`python3 capture_snapshot.py --base http://100.108.252.111:8771 --scenes ../src/showcase-scenes.json --out <빈 폴더>/offline/snapshot` 후 서빙 중인 빌드를 `<빈 폴더>/dist`로 복사. GET만 약 180번. 경기 전체(v3)는 끝에 `--all-decisions`를 붙임: GET 526번(공 262개 × 공개·흐름 + 시간표 + 경기 목록), 시작할 때 262개 공의 공개·흐름이 하나라도 빠지거나 manifest의 공 수가 저장된 시간표와 다르면 서버가 뜨지 않음. 포수 미트까지 담으려면 `--with-setup`도 붙임: GET 1번 추가(v3면 527번), 셋업 자료가 HTTP 200이 아니거나 다른 경기 것이면 저장을 멈춤.
