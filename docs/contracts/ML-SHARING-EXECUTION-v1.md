# 선수 정보 공유·강건성 비교 사전 사양

2026-09-24. G 후보 DEV 결과를 열기 전에 고정한 실행 사양이다. 부모 ML2 preparation 파일 해시가 확정되면 `EXP-P4-001` config에 그대로 등록한다. 아직 G 자료 준비·학습·평가는 실행하지 않았다. [전체 매트릭스](../ML_EXPERIMENT_MATRIX.md)의 G1~G4, I2, T1을 구현하며 T4의 전체 MLB 추론 경로를 준비한다.

## 모집단과 입력

- 동일 D100 TRAIN와 ML2의 ordered early-stop 표본, physical normalizer·연속 타자/경기 context·400-draw joint delivery pool을 사용한다. TRAIN은 2023-05-15~2025-04-30이고 각 후속 기간은 기존과 동일하다.
- Cpanel은 TRAIN 투수의 역할(선발 투구 비중 ≥50%), 일관된 좌우, 전체 투수별 TRAIN 수의 25/75% 분위 세 층을 교차한 12개 층에서 최대 4명씩 고른다. 분위수는 linear 방식, 경계 동률은 low≤q25/middle≤q75/high>q75다. 순위는 `SHA256('20260924|pitcher_id')`이며 DEV 유무·점수로 교체하지 않는다. 최대 48명이고 빈 층/부족 층을 기록한다.
- 선발 신원은 필터 전 TRAIN의 경기/수비 half 첫 공(1회·0아웃)과 원래 starter_pitcher 열을 대조한다. 평가 때는 해당 경기의 실제 선발/불펜 역할도 따로 기록한다.
- 모든 G 모형에 동일한 연속 투수 표현을 추가한다. TRAIN 투수별 effective_speed·release_spin_rate·pfx_x·pfx_z 평균, 좌완 비중, 구종 비중을 TRAIN 투수 사이에서 표준화하고 `log1p(TRAIN 수)/10`을 추가한다. 이는 마감 시점에 적합한 정적 선수 표현이며 각 TRAIN 투구 시점의 누적 통계라고 부르지 않는다. DEV 결과나 미래 DEV 물리를 적합에 사용하지 않는다. 새 선수는 표준화 0 벡터/표본 수 0 및 league fallback이다.
- 이 입력 추가 때문에 G0는 새로 3회 학습한다. ML2 A0의 체크포인트를 그대로 G0라고 부르지 않는다. A0→G0는 입력 변경 bridge로만 해석한다. 내부 시계열 HPO나 선수 제외 fold에서는 해당 내부 TRAIN만으로 표현·군집·모든 auxiliary를 다시 적합해야 한다.
- 구종/과거 결과를 포함하는 동일 enriched H5를 사용한다. 현재 결과 채널은 0, 현재 물리는 결과 학습에서만 실제 값을 쓰고 CAL/DEV에서는 고정 TRAIN draw로 적분한다. 결과는 기존 공통 10-class다.

## 비교 family

| 셀 | 적합·추론 | 주 대조군 |
|---|---|---|
| G0-global | 전체 D100 공유 MLP, 연속 투수 표현 포함 | 공통 기준선 |
| G1-personal | 패널 선수별 MLP, 부적격 선수는 G0 | G0 |
| G2-feature | G0 정보 + TRAIN 군집 one-hot 5채널(4군집+unknown) | G0 |
| G3-cluster | 군집별 MLP, G2와 동일 입력, 부족 군집/새 선수는 G0 | G2 |
| G4-partial | G0→군집→개인 조건부 확률 수축 | G2 |

군집은 결과 라벨을 쓰지 않는 위 연속 투수 유형 표현에서 투수 동일 가중 k-means++ K=4, seed=20260924, 최대 100회로 고정한다. 군집 의미를 보이기 위한 평균/구종 비중은 보고하되 최적 야구 유형이라고 주장하지 않는다. G3 대 G2를 주 비교로 삼아 입력 추가 효과와 공유 범위 효과를 분리한다. G3/G4 대 G0는 보조 진단이다.

개인 적격성은 TRAIN≥500구 및 공통 early-stop≥20구다. 기준에 못 미치면 선수/평가 행을 제거하지 않고 league로 돌아간다. 군집 전문가도 같은 최소 수를 적용한다. 전 모델 MLP width128, 최대30epoch, patience5, batch1024, AdamW 학습률.0005, seeds0/1/2로 고정한다. 개인 fit 수는 준비 단계의 적격 선수 수×3이며 사전에 고정한 규칙으로만 결정된다.

G4는 파라미터를 베이지안 추론하는 모형이 아닌 **고정 확률 수축 적응**이다. 군집 조건부 확률을 `N_cluster/(N_cluster+10000)`으로 league에 섞고, 개인 조건부 확률을 `N_person/(N_person+1000)`으로 그 결과에 섞는다. N은 TRAIN 적격 구 수다. 개인/군집 체크포인트는 G1/G3에서 재사용하되 의존 해시와 비용을 기록한다. 혼합 후 log 확률을 공통 delivery-temperature 절차에 넣고 400회 적분한다.

모든 셀의 temperature는 **동일 Cpanel 5월 후반**, 앙상블/빈도 혼합은 **동일 Cpanel 6월**에서 적합한다. 혼합 전 조건부 계산은 float64이고 최종 적분도 float64다. D1/ML2의 C6 보정 점수를 같은 대조군으로 재사용하지 않는다. 빈도 기준선도 Cpanel temperature에 재보정한다. MLB 전체 확장에서는 이 계수들을 그대로 고정한다.

## 판정과 비용

- 네 주 비교마다 전체 N과 저표본 G 가설을 하나씩 두어 총 **8개 가설에 Holm α=.05**를 적용한다. 미측정 저표본 가설도 family 자리에서 제거하지 않는다.
- N은 ΔNLL≤−.003, 경기 paired bootstrap 95% 상한<0, 보정 p≤.05, ΔBrier 95% 상한≤+.001, 3 seed 중2개 이상 개선 방향이다.
- G는 low 그룹의 위 N 조건과 전체 ΔNLL 95% 상한≤+.001 및 전체 Brier 기준을 모두 요구한다. 저표본은 전체 TRAIN 양의 투수 수 분포 하위25%이며 TRAIN0 선수는 별도다.
- R 그룹은 실제 경기 선발/불펜, 좌우, TRAIN low/middle/high/zero, 2스트라이크 유무, 주자 유무의 **12개**다. 네 비교×12그룹×NLL/Brier=**96개 상한**에 Bonferroni α=.05를 사용한다. 상한 문턱 NLL+.010/Brier+.002, 최소30경기·500구다. 부족 집단은 미확인으로 남기며 전체 R 통과로 처리하지 않는다. TRAIN 선정 패널의 TRAIN0 그룹은 구조상 비어 있어 R 전체 확인에는 별도 확장 검증이 필요하다.
- N/G 및 I2/T1 bootstrap은 10,000회, R의 96개 보정 상한은 극단 분위의 Monte Carlo 오차를 줄이기 위해 **100,000회**로 G 준비 전에 고정한다. 모두 seed20260924, 경기 전체 재표집 후 투구 가중 평균이다. 고정 예측에 조건부라는 한계를 명시한다. N/G의 Holm 보장은 8개 NLL 가설이며 추가 Brier/전체 비열등 gate까지 통합한 공동 95% 보장이라고 부르지 않는다. 희귀 결과 보고 적격성은 사건30건이고 0건을 점수0으로 채우지 않는다.
- I2는 low와 high의 후보−대조 차이의 차이를 같은 경기 resample로 계산하는 보조 분석이다. 집단 차이를 자료량의 무작위 개입 효과로 해석하지 않는다. T1은 같은 모델의 7/8/9월 구간 지표이며 rolling refit과 구분한다.
- 공통 지원/제외 분모와 겹칠 수 있는 제외 사유를 보존한다. 선수 macro, 역할별, 클래스별 결과·fallback 빈도·온도·혼합 계수를 함께 남긴다. 새로운 선수의 관측 이력 갱신은 엄격한 zero-shot T2를 대신하지 않는다.
- 실제 신규 fit 비용과 각 배포 셀이 필요로 하는 전체 구성원 학습 비용을 구분한다. G4의 추가 fit이 0회라는 이유로 무료 모형이라고 기록하지 않는다. formal C 판정은 별도 비열등·비용 사전 등록 없이 주장하지 않는다.
- G 결과를 열기 전 선택 규칙 확인: N 또는 G 통과 후보를 주 NLL, 동률이면 전체 의존 fit 비용 순서로 최대2개 고른다. 매트릭스 공통 규칙대로 **측정된 R 실패 후보는 승격하지 않는다**. 단순한 미관측 R 그룹은 unconfirmed로 유지하고 T4에서 따로 평가한다.

무거운 실행 1개, 단일 명령 7200초 상한. 자료 준비 뒤 적격 fit 수와 작은 profile을 기록하고 실제 전체 예산을 고정한다. 자동으로 자료량·seed·draw를 줄이지 않는다. 정책 효과·목표 위치 인과 효과·미개봉 최종 확인은 이 비교의 결과가 아니다.
